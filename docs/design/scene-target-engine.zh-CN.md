## 目标与现状

用户在现有“识别物”入口选择资产、数量和行为模式。引擎先判断世界能支持什么活动，再生成固定身份、外观、活动和连续位姿。
引擎可选启用；保留旧目标和事件接口，逐步用适配器接入，不让父项目依赖 ALE。

代码核查发现：

- M22 PRD 定义了 `nav.person`、`nav.vehicle`、`nav.graph` 和设施锚点，但当前 GLB pipeline 尚未产出完整导航层。
- `MeshWorldQuery` 明确尚未实现 `walkable_height` 和 `nav_path`。
- `events.compile` 实际调用 `build_nav`：向下射线的最高表面、台阶过滤、连通岛筛选。平屋顶可能在几何上满足条件；没有道路语义、单行、转向和路权。
- `awr.anchors.v1` 已能表达带来源与确认状态的区域、入口、路缘和设施类别，应复用它，而非另起一套坐标与 POI 格式。
- 旧 `targets` 和 D3 `events` 是两个接入面；细化资产与姿态必须同时服务 Web 和相机，不能再维护两套外观替身。

因此不能根据“磁带编译通过”或“有 nav 文件”就宣称场景可以承载真实生活。

## 第一批行为定义

`python -m awr.sim.events scene-audit --world WORLD` 只读检查：世界/坐标文件、锚点现有 schema 与绑定、导航层声明和文件、每类已确认活动区域。
输出分开记录数据缺失、数据待验证、当前消费后端不足。退出码 2 表示阻塞，3 表示仍需验证，0 保留给完成能力验证；当前实现不会为真实活动给出 0。
报告是诊断输出，不替代 `worldpkg validate`，不把文件存在当作拓扑、支撑面或交通真实性证明。

`build_nav(..., allowed_mask=mask)` 是可选的底层许可约束：布尔栅格必须与高度场严格同形、同格网；调用者负责从确认过的区域、对应地面层和实体尺寸生成它。
先与几何可走格求交，再做车辆腐蚀与连通岛筛选。约束只能删格，不能把无支撑格变成道路。空掩码产生空导航，不退回无约束结果。
默认不传时保留既有行为。此批不自动把任意 `zone` 解释成活动区，也不让现有编译器悄悄启用约束。

`audit_nav` 报告现有格网各连通分量面积，并对调用方明确选择的点报告所在分量及点对可达性；不自动吸附、不将两个隔离岛视为可互通。
这些都是二维诊断；桥面/地面分层、车身扫掠、转弯半径、道路方向及多主体路权留待场景适配器实现。

仓库根目录的开发者调用示例（使用已有开发环境）：

```sh
PYTHONPATH=python python -m awr.sim.events scene-audit --world worlds/example
PYTHONPATH=python AWR_KERNEL=numpy pytest tests/d3/events/test_scene.py -q
```

导航适配器的调用形状如下；`permission` 是与 `height` 同形且配准的布尔栅格，不是从图像颜色自动推断的道路：

```python
from awr.sim.events.nav import build_nav
from awr.sim.events.scene import audit_nav

nav = build_nav(query, bbox, "person", seeds, z=height, allowed_mask=permission)
report = audit_nav(nav, {"entrance": entrance_xy, "destination": destination_xy})
```

种子岛选择仍沿用原逻辑：有种子时保留附近的岛，无命中时保留最大岛；本批诊断只统计筛选后格网。
后续适配器必须对实际起终点调用可达性检查，不能把被筛掉的区域作为可用容量，更不能将区域计数当作可达证明。

## 两种生成模式共用的架构

世界包与人工补充标注 → 场景能力图 → 资产/角色选择 → 配方 → 验证 → 活动规划/运动 → 磁带与验收。

随机模式：用户选择目标和 seed；模板按可达设施、角色和容量采样活动，而不是在几十米范围内往返。休息、等待、在室内均可发生，但必须有原因及状态；25 分钟不要求每个人永远运动。

定制模式：设计 agent 读取世界能力与资产能力，生成同一份结构化配方。LLM 不逐帧控制位姿，不允许编造缺失道路或设施；配方仍经确定性编译与验收。
保存用户意图、模型/提示版本、工具结果和批准的配方；重放使用保存的配方，不重新调用模型。“同 seed”只保证锁定输入和实现的生成过程，不能保证远端 LLM 重答相同。

复现摘要需要覆盖世界几何、坐标、导航/语义、资产目录、模板/编译器版本、配方、seed 和随机流分配。一个实体同一时刻只有一个运动状态写入者。
Web、相机和评分消费同一身份、时间轴与实际状态。模型推理期间世界继续推进；离线编译磁带与在线暂停世界是两回事。

## 后续不能遗漏的条件

- 设施名称不等于可用入口；停车点不等于可驶入停靠位；OSM 线不等于真实路面宽度。
- 几何许可、语义许可、资产运动能力和行为前置条件分别验收；未知保持未知。
- 资产复用先逐项审查来源与许可；本批不复制 ALE 代码或二进制，不新增依赖。
- 有目的的通勤/购物/休闲与交通持续性独立验收，不按单个 benchmark query 手写轨迹。
- 真实场景生成验收与 query 可解性/评分验收分开；不得随着被测 agent 的寻找动作偷偷搬动目标。

## 完整生活活动目标（2026-10-22 开始）

用户要求持续实施至完整可验收版本，不在中间切片结束。仍不推送或提 PR。工作顺序：

1. 全部原生类别（person / vehicle / dog / uav / machine / object）的可选资产与身份元数据；车辆类型、车牌可编辑并在三维中显示。元数据不生成新身份。
2. 场景能力图：可行走/行驶/飞行连接、支撑高度、设施入口、室内状态、停车/服务位、冲突区。合成城市提供明确作者定义；真实地形只接受经过准入验证的适配数据，不凭名称虚构入口。
3. 生活活动调度：角色日程、通勤、购物、服务、休息、进出设施；车辆按有向车道、速度/加速度/转弯约束行驶，行人过街和路口使用路权，主体动态避让。有限等待必须有原因，拥堵/不可达明确报告。
4. 可选生成器：固定世界与版本、目标集合、seed 的确定性生成；用户自然语言经 DeepSeek 生成受限结构配方，经同一规则校验再编译/运行。模型不直接输出未经验证的逐帧坐标。
5. 原生 UI 配置、预览、部署；完整长时验收、重置/恢复复现和 2–3 个低成本 DeepSeek 定制案例。测试报告分别说明已证实条件和限制。

API 密钥只放部署外的私有配置，绝不进入代码、场景、提示记录或浏览器包。付费生成严格限制请求次数与输出长度，不自动循环重试；记录 usage 和计费信息（供应商没有价格信息时不伪造美元数值）。

### 全体持续推进（用户追加验收要求）

每个活动目标在每个固定仿真步均参与调度，不允许按预算只轮流激活小子集。静止状态必须带业务原因、进入时刻和恢复条件：室内工作、购物、服务、排队、交通等待或休息。无人机观察/模型推理/渲染可见性不得成为活动目标推进条件。
验收输出每目标移动距离、角色活动分布、最长无进展时间及原因，以及每个时间窗移动/室内/服务/排队人数；增加人口密度时仍须全体推进。不能以人为强制全员不停走动掩盖缺少生活逻辑，也不能以有原因标签掩盖死锁。
