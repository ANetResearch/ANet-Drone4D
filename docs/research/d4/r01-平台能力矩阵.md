## 1. 结论摘要

1. 现有生态在四个方向上各有成熟方案：MARL 环境接口与训练基线（PettingZoo、VMAS、BenchMARL、JaxMARL）、带留出集的泛化评测（Melting Pot）、经典路径规划与调度实例与竞赛（MovingAI、League of Robot Runners、Flatland、POGEMA）、高保真机器人与无人机仿真（Isaac Lab、Gazebo、Webots、AirSim 后继）。
2. 尚无平台同时提供"可替换的实验内通信模型 + 标准化协同问题库 + 带置信区间与留出集的评测治理"。MARL 平台的通信为无或理想；网络–机器人联合仿真有网络模型，但均为研究原型，无统一发行版、无基准任务集、无榜单。
3. 评测治理普遍薄弱：带留出集的持续榜单只见于 Melting Pot；竞赛型榜单（League of Robot Runners、Flatland、RoboCup Rescue、CARIC）以赛事为周期；MARL 基线库只提供训练与多种子报告，没有提交机制、配对比较与支配分层。
4. 无人机方向的高保真多机平台出现供给缺口：微软 AirSim 已归档，官方后继为 Project AirSim（其当前维护状态待核实）；社区分叉 Colosseum（CodexLabsLLC 维护，并非微软项目）于 2026-07-11 由其所有者归档；Flightmare 实质停更，gym-pybullet-drones 规模较小。
5. D4 可主张的增量应限定为"在声明的确定性等级下，新增可控的协作干预实验能力"，不应主张物理保真度优于 Isaac/AirSim、吞吐优于 VMAS/JaxMARL，也不使用"首个""首创"等措辞。
6. 最需正面对比的五个平台为：VMAS + BenchMARL（含 PettingZoo/MPE2）、Melting Pot、REMROC、CARIC（及 MultiUAV-Plat）、ROS-NetSim/ns-3–Gazebo 联合仿真族（含 ns3-gym）。

## 4. 主要差异分析

### 4.1 通信建模

- MARL 平台（PettingZoo、MPE2、VMAS、JaxMARL、BenchMARL）的通信为"无"或"理想离散消息"，没有带宽、时延、丢包与队列状态。
- 协同感知数据集（Griffin、U2UData）在离线数据上注入时延与丢包，用于评估感知融合的鲁棒性，不形成闭环决策。
- 网络仿真联合方案（ROS-NetSim、ns3_gazebo、ns3-gym）具备分组级网络模型，但需要双时钟同步、规模受限、难以逐位确定，且没有基准任务集与评测协议。
- 结论：中间层空缺——"参数化的有状态网络服务"（路损与遮挡、容量、令牌桶、有界队列、Gilbert–Elliott 突发丢包、分区）可以在保持确定性的前提下提供可控的通信变量，并以 ns-3 受控场景校准。

### 4.2 物理与感知保真度

- 高吞吐平台（VMAS、JaxMARL）为抽象物理，适合大规模训练；高保真平台（Isaac、Gazebo、AirSim 后继）非确定且部署成本高。
- 现有平台的保真度通常是固定点，同一算法无法在"同一任务、同一接口"下逐档升降保真度评估，也没有跨保真度的排名一致性度量。
- 结论：保真度应作为可切换的配置轴，并以排名一致性（Spearman ρ、显著差值方向一致率）衡量低保真结论能否外推。

### 4.3 问题族覆盖

- 经典协同算法族分散在不同生态：MAPF（MovingAI、League of Robot Runners、POGEMA）、DCOP（FRODO、pyDCOP）、任务分配与协同搜索（多为论文自带代码）、MARL（PettingZoo 生态）、LLM 多智能体（MultiUAV-Plat、EmCoop、MASBench）。
- 各生态的实例格式、指标与资源约定互不相同，同一算法无法在同一世界、同一通信条件、同一资源预算下横向比较。

### 4.4 评测治理

| 平台 | 留出集 | 持续榜单 | 置信区间与配对比较 | 提交机制 |
|---|---|---|---|---|
| Melting Pot | 有（原版 85+ 场景；第二版 256+，待核实） | 有 | 论文报告，未见配对检验协议 | 库内评测 |
| League of Robot Runners、Flatland、RoboCup Rescue、CARIC | 竞赛隐藏实例 | 赛事周期 | 未见 | 竞赛提交 |
| BenchMARL、MARLlib、JaxMARL | 无 | 无 | 多种子报告 | 无 |
| MultiUAV-Plat | 隐藏校验 | 无 | 未见 | 无 |

结论：把"提交状态机 + 留出集 + 层次自助法 + 配对比较 + 多重比较校正 + 支配分层"组织为按问题族划分的持续榜单，在现有生态中没有直接对应物。

### 4.5 无人机方向的供给状态

微软 AirSim 已归档（后继 Project AirSim 的维护状态待核实），社区分叉 Colosseum 于 2026-07-11 由其所有者归档，Flightmare 实质停更，gym-pybullet-drones 规模较小；CARIC 与 MultiUAV-Plat 分别代表竞赛型与 LLM 任务型路线。无人机多机协同的"可复现、可扩展、带评测治理"平台存在空缺。

## 5. 生态空白

| 编号 | 空白 | 依据 |
|---|---|---|
| 1 | 通信模型与物理、感知栈割裂：没有同时提供"可配置通信层（理想 / 参数化 / ns-3 后端）+ 标准化任务套件 + 评测协议"的平台 | §4.1 |
| 2 | 异构实体的跨域覆盖不足：机器人基准多限于单域；空地协同数据集为离线数据，不能闭环评估协同决策 | §3.3、§3.4 |
| 3 | 世界真值与各体 Belief 未分离、未度量：普遍只评最终任务成功率；认知分歧、信息年龄、信息充分性缺少通用度量 | §3 全表 |
| 4 | 评测治理薄弱：带留出集的榜单少；MARL 库无提交、置信区间与支配分层 | §4.4 |
| 5 | 可复现性与保真度无人兼顾：高保真非确定且笨重，高吞吐为抽象物理 | §4.2 |
| 6 | 经典协同算法族分散在不同生态，无法横向比较 | §4.3 |
| 7 | LLM 多智能体基准偏文本或偏静态，缺少 LLM 与经典、学习型算法同榜对比的闭环平台 | §3.4 |

## 6. D4 可主张的差异与验证方式

每项差异对应一个空白与一个可执行的验证实验；措辞采用"在声明的确定性等级下""与 X 相比新增 Y 实验能力"的句式。

| 编号 | 差异主张 | 对应空白 | 验证方式 |
|---|---|---|---|
| DF-1 | 同一 Suite 在 `none` / `ideal` / `abstract-*`（后续 `ns3`）网络档下对照运行，网络为有状态队列服务，网络档进入赛道定义 | 1 | 同一基线集在各网络档下的效用差、排名变化与显著反转对；`abstract-radio` 对 ns-3 受控场景的拟合误差可报告 |
| DF-2 | 世界真值与 Belief 分离，提供信息年龄、认知分歧与按信息类别计量的通信成本三类标准度量，以及观测泄露审计 | 3 | 标准接口与公开指标实现；泄露审计在全部官方基线运行上通过 |
| DF-3 | 固定外生事件（Canonical Event Tape）加 `exogenous` / `interactive` 两种模式，外生随机量跨策略配对 | 3、6 | 跨策略重跑时外生轨迹与扰动序列哈希一致 |
| DF-4 | 观测、物理、网络三轴正交保真度，并给出跨保真度排名一致性 | 5 | `L1` 与 `L2`、快速与标准时钟档的 Spearman ρ 与显著差值方向一致率 |
| DF-5 | 异构实体在同一世界与同一评测协议下统一调度 | 2 | 地面、水面与固定传感器实体交付后，在任务分配 Suite 中运行异构编队 |
| DF-6 | 评测治理：提交状态机、留出集、加盐种子承诺、层次自助法、真正配对的比较、Holm 校正与支配分层 | 4 | 公开统计协议与复算脚本；榜单由原始行数据逐字节重算 |
| DF-7 | 经典求解器、MARL、LLM 多智能体在同一实例、同一资源包下同赛道比较，赛道按资源预算而非方法族划分 | 6、7 | 同一 Suite 中三类方法同赛道提交 |
| DF-8 | 协作贡献以干预对照度量（零通信参考、阻断投递、载荷置换） | 3 | 构造的对照策略上"阻断投递"与"载荷置换"两种干预显著分离 |

**不应主张的内容**：物理保真度优于 Isaac 或 AirSim 后继；规模或吞吐优于 VMAS、JaxMARL 的 GPU 并行级别；"首个多机协同仿真平台"或"首创"类表述。

## 7. 最需正面对比的五个平台

| 序 | 平台 | 对比理由 | 建议对比维度 |
|---|---|---|---|
| 1 | VMAS + BenchMARL（含 PettingZoo/MPE2 作为接口基线） | 连续多智能体物理加基线库的事实标准组合，是 MARL 研究者的缺省入口；D4 须说明迁移成本与增量 | 吞吐、基线覆盖、接口兼容、通信层、许可证（VMAS 为 GPL-3.0，只做对照与适配，不内嵌代码） |
| 2 | Melting Pot | 唯一成熟的带留出场景与泛化榜的多智能体基准，与协作智能排行榜目标最接近 | 留出集协议、排名统计、"未见伙伴泛化"与"未见事件和世界泛化"的差异 |
| 3 | REMROC | 同样基于真实传感器栈做协调算法评测，并开放协调器模板 | 扩展点、通信模型（ROS 2 话题理想通信）、可复现性、实体异构 |
| 4 | CARIC（及 MultiUAV-Plat 作为 LLM 路线） | 多无人机协同的竞赛型基准，Gazebo 真实传感器加任务分配与规划 | 任务套件、异构设计、评分协议、ROS 1/2 迁移成本；MultiUAV-Plat 的 REST 接口与隐藏校验 |
| 5 | ROS-NetSim / ns-3–Gazebo 联合仿真族（含 ns3-gym） | 与"网络仿真器类比"及通信层设计直接对照 | 时钟同步方式、规模上限、确定性、集成工作量 |

次级对照：JaxMARL（吞吐上限）；POGEMA、League of Robot Runners、MovingAI（MAPF 的指标与实例兼容）；Isaac Lab 与 AirSim 后继（作为物理后端选项而非竞争者）。

## 8. 对 D4 设计的启示

| 启示 | 设计落点 |
|---|---|
| 接口须与 PettingZoo Parallel 兼容，降低 MARL 研究者迁移成本；但不让 Gym 风格的 `step()` 成为内核调度器 | 原生 `Policy.step(obs, inbox)`，PettingZoo 为同步适配器（一个 `step` 对应一个密封决策周期） |
| 通信层是最主要的可主张增量 | `abstract-radio@1` 主档、`abstract-disk@1` 快速档、ns-3 研究档；网络档进入赛道定义 |
| 吞吐不与 GPU 向量化平台竞争 | 以"10 分钟内完成 20 个 Agent × 100 个外生种子 × 4 个算法的对比实验"为门禁，而非步每秒指标 |
| 评测治理是第二个主要增量 | 协作智能排行榜：留出集、加盐种子承诺、层次自助法、配对比较、Holm 校正、支配分层 |
| 许可证约束 | GPL-3.0（VMAS、MultiUAV-Plat）、AGPL-3.0+（FRODO）项目只做对照与适配；MovingAI 等实例导入前核实许可 |
| 高保真后端选择 | 既有 Gazebo 链路作为审计档；不依赖已归档的 AirSim/Colosseum |
