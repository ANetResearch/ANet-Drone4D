# D4 外部模型两轮讨论：共识、分歧与定案（u-debate）

范围：仅平台与协作智能排行榜，不含 ALE/EIoT。
材料来源：
- 第一轮：Gemini（gemini-4-argon）`r1-gemini.md`（输出被截断，缺路线图、风险与对设计稿的批评）；ChatGPT（gpt-6.1-sol）`d4/r1-gpt.md`。
- 第二轮：`d4/r2-gpt.md`、`d4/r2-gemini.md`。
- 文献核查：WebSearch，结果见第 6 节。

核查说明：凡文中给出的数值（路径损耗参数、预算、基线得分预期）均为设计默认值或待校准目标，不是对现有代码性能的断言。

## 1. 共识（两模型一致，可直接作为设计前提）

1. **时间与调度**
   - 整数虚拟时钟，禁止浮点时间累加。
   - 同刻事件使用稳定排序键 `(time, phase, producer_id, producer_seq)`。
   - 零延迟消息必须被强制至少延迟 1 个最小时间单位，避免同刻无限递归。
   - 外生事件（Canonical Event Tape）只记录与 Agent 行为无关的内容；Interactive 模式下目标反应由固定规则加独立随机流生成，不再声称"同一完整世界轨迹"。
2. **随机流**：按身份派生随机流（`HMAC/BLAKE2b(seed‖domain‖object_id)` 加计数器 RNG），不使用单一全局流。理由是共同随机数（CRN）：某策略多发一条消息，不应改变天气、目标和传感器噪声。
3. **Agent–Entity–Assignment 三元模型**
   - Assignment 是带 `epoch` 的控制权租约，用来防止旧指令覆盖新指令。
   - Agent 不一定对应一个 Entity：可以一对多（集中式）、无实体（地面站），Entity 也可以无 Agent。
   - Belief 不强制统一表示，只收集 Agent 自愿提交的 `BeliefSnapshot`。
4. **Interaction 不止网络**：机巢充电争用、跟踪交接、控制权移交、任务承诺与撤销都属于 Interaction。
5. **保真度命名**：弃用 C0–C3 这一"协作保真度"单轴。改用独立的观测（O）、物理（P）、网络（N）三轴，并另设与保真度无关的标签（执行拓扑、目标模式、计时模式）。
6. **D3 衔接**
   - `obs.v1` 向后兼容扩展，旧 Agent 通过投影器原样运行。
   - 保留集中式模式，新增分布式模式。
   - EC/EU/AO/CE 作为 D3 任务指标保留，`board.v1` 原样保留，新榜用 `board.v2`。
7. **Abstract 网络**是首发主力，NS-3 是可选扩展，不能成为运行 Drone4D 的前置门槛。Abstract 网络的组成：
   - LoS/NLoS 路径损耗与建筑遮挡；
   - 令牌桶限速和有界队列（drop-tail）；
   - Gilbert-Elliott 突发丢包；
   - 外生分区掩码；
   - 带 TTL 的消息。
8. **排行榜**
   - 不设万能总榜，按"执行拓扑 × 观测档 × 预算"划赛道。
   - 主榜用绝对任务效用排名，协作增益作为诊断量。
   - 必须资源对齐：团队规模、传感器、算力、通信字节、LLM token。
   - 采用配对种子加分层 bootstrap，多重比较用 Holm 校正，提交限额并只返回聚合结果，留出集在地理上隔离。
   - 单机或集中式参考不得称为"oracle 最优"，只能称"合法信息的集中式参考"。
9. **统计功效公式**：`n = ((z_{1-α/2} + z_{1-β}) σ_D / δ)²`。两模型各自代入的数值都核算无误（GPT：σ=0.10、δ=0.05 得 31.4；Gemini：σ=0.08、δ=0.035 得 40.96）。
10. **吞吐与成本**
    - L2 渲染不适合大规模跑，主榜在 O1 上跑，O2 只做抽样或审计。
    - 路线图要做 O1 到 O2 排名一致性检验（跨保真度迁移）。
    - 最大风险包括区分度坍塌、权限旁路、L2 成本。
11. **兼容层**
    - PettingZoo `ParallelEnv` 只是同步适配器，不是内核调度器。
    - BenchMARL 通过 TorchRL 适配。
    - 训练期使用无容器的进程内模式，评测期使用容器。

## 2. 分歧与我的判断

### 2.1 确定性承诺的强度

| 议题 | Gemini | GPT | 判断 |
|---|---|---|---|
| 复现等级 | 声称 1000 步单步与批量运行的 Trace "逐字节一致"；"任何人在任何机器上跑出完全一致 Trace" | 整数时钟不能消除浮点、GPU 渲染、物理引擎、线程、模型推理的差异；提出 D-A/D-B/D-C 三级 | **GPT 正确**。Gemini 的表述会在论文评审中被直接质疑。采用分级声明。 |

最终声明：
- **D-A**：固定制品和声明硬件下，规范化事件与动作哈希一致。目标是 O1 + P1/P2（纯 Python/numpy 路径）。
- **D-B**：动作重放后，轨迹和指标在数值容差内一致。目标是 O2（Gazebo）。
- **D-C**：多次运行的分布与 CI 可复现。适用于在线 LLM API 和测量时延模式。
- 不做跨机器位级承诺。

### 2.2 Agent 推理时延与超时

| 议题 | Gemini | GPT | 判断 |
|---|---|---|---|
| 虚拟延迟 | `FIXED_VIRTUAL_DELAY`，默认 20 ms | `modeled_latency` 默认 100 ms | 机制相同，默认值取 **100 ms 与决策周期对齐**。扫描档 50/100/250/500 ms 作为固定延迟消融。 |
| 墙钟超时 | 丢弃迟到响应，强制 `FAILSAFE_HOVER` | 超 CPU/内存/调用预算按违规处理，不转为随机动作延迟；墙钟 watchdog 只防挂起（5 s） | **GPT 的处理更好**。Gemini 的悬停回退会让结果随宿主机负载变化（超时是否发生取决于墙钟），破坏确定性。 |

定案：
- 超时只判违规或基础设施故障，不进入正式分数的随机路径。
- 计算耗时单独计入资源账本。
- 若要评估部署时延，使用 `timing_profile = measured` 的独立赛道（标签 D-C），把墙钟量化到 5–10 ms 后映射为虚拟时延。

### 2.3 Gemini 对 GPT 同步 `step()` 的批评

Gemini 提出两点：
- 同步 `step()` 与容器异步 IO 脱节；
- 零延迟网络下一次一跳往返要两个决策周期（200 ms），这会扼杀同周期多轮拍卖。

我的判断：**第一点不成立，第二点成立且值得吸收**。
- 第一点：屏障式同步加固定虚拟延迟，正是确定性的前提。容器内部是否异步无关紧要，宿主等待所有 Agent 返回后按稳定 ID 提交即可。
- 第二点：这是真实的表达力缺口。定案如下：
  - v1 的 Agent 只在决策 tick 被唤醒，一跳往返下限是 `2 × decision_period + 网络延迟`，并写进文档。
  - 增加可选特性 `wake_on_rx`。消息到达后，在下一个最小唤醒粒度（默认 20 ms 物理步）触发一次"轻量决策"，该次调用只允许发消息和改写已有承诺，不允许推翻运动指令。
  - 默认关闭，由 Suite 配置显式声明。

### 2.4 通信模型细节

| 议题 | Gemini | GPT | 判断 |
|---|---|---|---|
| 丢包 | 每链路两状态马尔可夫链（每 10 ms 步进）加 SNR sigmoid | 连续时间生成矩阵 `P(Δ)=e^{QΔ}`；GE 状态按固定网络时间演化，不随包数演化 | 数学上等价。采用 **GPT 的连续时间写法**（对任意步长一致，不依赖包频率），并取 Gemini 的 SNR 到误包率映射作为基础误包率。 |
| 拥塞 | 令牌桶加优先级队列 | 令牌桶加队列加共享信道 DRR 服务 | 首发**取 GPT 的共享信道 DRR**（拥塞随节点数变化才有意义），保留 Gemini 的 `priority` 字段并进入 DRR 的类别。 |
| 重传 | 网络层提供 `RELIABLE_ORDERED`（指数退避，计费重传字节） | 首发无自动重传，可靠性由应用承担 | **取 GPT**。网络内置重传会掩盖协议设计，而协议设计正是被测对象。可靠性由 Agent 自己实现 ACK，平台只提供接收确认事件并计费。 |
| 抖动 | Gamma | Uniform[0, 10 ms] | 采用 GPT 的 Uniform（有界、不产生负时延）。Gamma 留作扩展。 |
| 阴影衰落 | 一阶自回归相关阴影 | 首发 X=0，避免未校准的包级阴影 | 默认 **X=0**。AR(1) 相关阴影作为 `network_profile` 扩展（需给出相关长度与校准数据）。 |
| 多播 | 广播按一次信道占用计发射字节，接收字节另计 | 首发实现为计费单播复制 | 取 **GPT（单播复制计费）**，实现更简单且不可被广播绕过。广播语义作为扩展，同时报告 `B_tx` 与 `B_rx`。 |
| 参数 | EIRP 20 dBm，γ_NLoS 3.6，穿墙 12 dB，噪声 -92 dBm | γ_NLoS 3.2，NLoS 附加 15 dB，S_min/S_good = -90/-65 dBm | **Gemini 的 γ_NLoS 与 L_wall 叠加双重计价**（NLoS 已经提高指数，再加穿墙损耗），数值偏悲观。采用 GPT 参数（见 3.3 节）。 |

两方都缺少一个关键的验证步骤。Gemini 用 NS-3 的 3GPP UMa 模型加 802.11s 做校准基准，这有价值，但 3GPP UMa 是蜂窝宏站模型，用来标定低空无人机自组网并不匹配。建议：
- 校准基准选用 ns-3 的 `LogDistancePropagationLossModel`、`WifiPhy` 与 `Buildings` 模块；
- 或使用公开的低空无人机空对地链路测量数据；
- 没有实测数据的 profile 一律标注 `synthetic-stress`，不得宣称"真实城市无线"。

### 2.5 赛道

| Gemini | GPT | 判断 |
|---|---|---|
| 三个赛道：Decentralized-O1、Embodied-O2、Agentic-Budgeted（含 LLM） | 按执行信息与资源权限分：D-Coord、D-End2End、C-Reference；算法类型只是标签 | **GPT 的原则正确**：GNN+MPC、LLM+拍卖、学习估计器+CBBA 无法按"经典/MARL/LLM"归类，同样的 50 ms 限制在 CPU 与 GPU 下不等价。 |

定案：赛道由三个正交字段决定 `(execution_topology, observation_profile, budget_profile)`。
- `execution_topology` 取 `decentralized` 或 `centralized`。
- `observation_profile` 取 O1（模型化）、O2-共享检测器（`ref_det_v1`）、O2-自带感知。
- `budget_profile` 取 B1（CPU，无 GPU，token = 0）、B2（含固定 GPU 配额）、B-LLM（固定模型制品，输入加输出 token 总额，例如 5 万/团队/episode，慢决策周期 1–5 s）。

LLM 不单设赛道，只是预算档。集中式只作为 C-Reference 单列展示，不参与分布式排名。

### 2.6 协作增益 Δ_coop

两模型在第二轮已基本收敛，且都批评了第一轮 Gemini 的公式。我的整合：

**不使用"一个 Δ_coop 公式"，而是一套带明确因果解释范围的对照。**

| 量 | 构造 | 能回答什么 | 因果性 |
|---|---|---|---|
| `Δ_ind = E[U(π) − U(π_ind)]` | π_ind 是公开版本的"静态分区 + 单机最强策略"，零通信，同资源 R | 比一个合理的独立团队多赚多少 | **系统级净收益，不是机制因果**（算法架构不同） |
| `Δ_cut = E[U(π) − U(π｜drop)]` | 同一镜像，评测器在运行时阻断送达，发送仍计费 | 该策略对显式通信的依赖度（Channel Reliance） | 弱。对"脆弱策略"会虚高，不得称为协作增益 |
| `Δ_perm = E[U(π) − U(π｜perm)]` | 同一镜像，保持消息频率、长度与格式不变，将内容替换为同类型的历史或其他 episode 消息，或加固定时间戳延迟 | 消息中的**实时世界信息**对任务的贡献 | **最强**：干预对象是"消息与世界状态的互信息"，不是"有没有消息"。这是 Gemini 的原创贡献，GPT 未涉及，**采纳** |
| `R_central = U(π_central^legal) − U(π)` | N 个实体、一个决策主体，共享合法私有观测，团队总算力/token 对齐 | 去中心化折损（参考差距） | 非因果；central-reference 不是上界 |
| `U(π_single)` | 单实体上场 | 扩容收益 | **资源不对齐，不得称协作增益** |

关键防护：
- **主榜按绝对任务效用 U 排名**，Δ 只是诊断。否则策略可以故意压低干预组得分来抬高增益（sandbagging）。
- 干预组由评测器施加，且对策略尽量不可检测：
  - `Δ_perm` 优于 `Δ_cut`，因为消息仍然"到达"，策略难以检测被干预。
  - 但策略仍可能通过内容一致性检测置换，所以对 `Δ_perm` 异常大的提交要审计。
- 通信干预的因果解释仅限于 exogenous 模式。Interactive 模式下两组目标反应轨迹不同，只能报总效应并固定初态、外生驱动和反应机制。
- 若需要 headroom 归一化，只作辅助分析：`G = (U − U_ind) / (U_central − U_ind)`，仅在分母 ≥ 0.05 时报告，允许大于 1，称"参考差距闭合率"。

我不采纳 Gemini 的分段 `G_sym`。它在 `U = U_ind` 处斜率不连续，且在高 U_ind 场景下仍然不可比；原始差值加置信区间更可靠。

**通信效率**：`U/B` 和乘指数惩罚都有漏洞（GPT 的 `η_B` 在 `B→0` 时奖励"躺平"，乘小于 1 的惩罚因子会让负增益变好；Gemini 指出了前者）。

- 主榜**不**合成通信效率。展示 `(U, B/B_allowed, CPU/CPU_allowed, tokens/tokens_allowed)` 的帕累托前沿。预算内不再惩罚，超额按违规处理。
- 若必须给标量，采用 Gemini 修正式的思路，仅对超出独立基线的正增益计价，并取对数边际：
  `η_comm = max(0, U − U_ind) / ln(1 + max(B, B_floor)/B_floor)`，其中 `B_floor = 0.05 B_cap`。该式在 `B=0` 时得 0，不可被躺平刷分；但它仍是诊断量，不进入主分。

**AoI**：定义为二元矩阵 `AoI_{u←v}(t) = t − τ_{u←v}(t)`（Gemini 的修正正确，GPT 原式下标不明）。消息必须携带 `source_sample_time_ns`，由内核而非 Agent 填写其来源采样时间的可信部分（见 3.1 的接口）。

### 2.7 安全性、防作弊措施的取舍

| 措施 | 来源 | 判断 |
|---|---|---|
| 容器内禁止直连（`--network none`）与独立进程/网络命名空间 | 两方 | **采纳**。GPT 补充：`--network none` 不能阻止共享文件、共享内存、公共 GPU 上下文与挂载目录，必须同时做只读根文件系统、禁用 Docker socket、IPC 限流，并对 GPU 共享模式明确限制。 |
| 同容器内多 `agent_id` 上下文 | 第一轮 Gemini 提出 | **否决**：不提供内存隔离，不得用于官方分布式赛道。 |
| 坐标盲化（全局平移加 90° 旋转） | Gemini | **部分采纳**：只在 O1 + P1/P2 中，对所有坐标、GNSS、风向、地图一致施加刚体变换；O2（Gazebo 渲染）不用（光照方位和阴影会变）；不采用镜像（改变手性）。这只能阻止硬编码绝对坐标，**不是防作弊核心**。核心是地理区块隔离的留出集。 |
| 金丝雀伪目标（第一轮 Gemini） | Gemini r1 | **否决**。往正式传感器里注入虚构目标会污染 benchmark，也检测不到内存扫描。真值泄露探针应放在 Agent 不可观察的一侧。 |
| 观测噪声抑制隐写（飞控微动作编码比特） | Gemini | **有价值的威胁模型，但不能写成"信道容量趋近于零"**。该防护未经证明。采用：对队友位姿观测加标准化噪声并低通，同时统计 Agent 动作的高频成分，对异常的高频偏航/横滚振荡做审计；论文中声明为"风险控制"，不承诺根除。 |
| 数据划分 | Gemini 按 40/30/30 随机划 tile | **GPT 正确**：相邻建筑、纹理资产和事件模板会跨 split 泄露。按地理区块、事件生成族和时间段隔离。 |
| 提交频率 | Gemini 每周 2 次；GPT 每周 3 次完整验证加每月 1 次冻结 holdout | 取 GPT 的"完整验证 3 次/周 + holdout 1 次/月"，且只返回聚合统计。 |

### 2.8 统计协议与样本规模

- 功效计算两方无误，但**场景聚类是真正的瓶颈**。GPT 提醒"同地图不同种子不是完全独立样本"，这一点正确，Gemini 的 `16 场景 × 3 种子 = 48` 把种子当独立样本使用过度。
- 采用：每 Suite **12–16 个场景配置 × 5 个外生种子**（场景为主要统计单位），先用 pilot 估计组内相关 ICC，按设计效应 `deff = 1 + (m−1)·ICC` 修正有效样本量。
- 估计量：场景等权均值及 95% CI，辅助 IQM、失败率、10% 分位数。Gemini 把 IQM 当"消除异常种子"是错的，IQM 可能掩盖尾部风险，必须并报均值与失败率。
- 层次 bootstrap：先抽场景，再抽场景内种子，1 万次。
- 多重比较：Holm。实际意义阈值 `ε = 0.02`（GPT）；Gemini 用 0.03。取 0.02，由 pilot 的 σ_D 复核。
- 支配分层：两模型都保留 D3 的 dominance tier，但 GPT 指出了实质问题：
  - 成对 CI 支配关系可能**不传递、有环**。
  - 定案：计算有向图后合并强连通分量，标注"不确定组"；组内不暗示统计等价。
  - Gemini 的"安全准入"（碰撞率 > 0 即淘汰）过严，一次随机碰撞就淘汰是不合理的，改为碰撞率与违规时间比超阈值才降级，阈值在 pilot 后固定。
- 学习算法至少 3 个训练种子，正式 5 个（两方一致）。

### 2.9 Suite 选择与 Suite 内容

两方均选 4 个，名称与范围不同。

| 来源 | Suite |
|---|---|
| 设计稿 P0 | TaskAlloc、CoopSearch、InfoShare、DynamicCoalition |
| GPT | 同设计稿 P0；强调"算法隔离模式 + 闭环模式"双模式；RobustCoord 作为协议而非 Suite |
| Gemini | CoopSearch-Handoff、TaskAlloc-WindNest（含联盟任务）、InfoShare-AsyncTrack、RobustCoord-FaultPartition |

**我的定案**：首发 **3 个完整 Suite + 1 个横切协议**。
1. **TaskAlloc**（含联盟任务子集 TA-C，吸收 DynamicCoalition 的核心）。
2. **CoopSearch-Handoff**（D3 `crop-handoff` 的直接升级，保持连续性）。
3. **InfoShare**（算法隔离优先）。
4. **RobustCoord 协议**：对前三个 Suite 注入故障与分区，输出退化曲线，不再是独立的第四套任务语义。
DynamicCoalition 作为 TaskAlloc 的高级 tier（v1.1 单列榜）。理由：设计稿 P0 的四个任务族各自可以成为一个课题，同时上线会使"成功"的定义不一致；GPT 的 6.3 节批评成立。

**所有 Suite 提供两种运行模式**（GPT 的建议，我认为是最有价值的设计之一）：
- **算法隔离模式**：固定感知、运动和控制，只评协调或融合组件，成本低，适合 Track D-Coord 与 MARL 训练。
- **闭环模式**：Agent 同时决定行动与消息，对应 D3 的现状。

两方 Suite 实例中的问题：
- Gemini 的 `U_search` 公式含 `− min(0.3, 0.05·N_FA)`，会出现**负值**，需截断到 [0,1]；交接因子 `η_ho ∈ {0.6, 1.0}` 是任意设定，应由 pilot 校准。
- Gemini 的"预期得分"（0.22/0.48/0.70–0.85 等）**没有任何实测依据**，只能作为 pilot 的区分度目标，不能写进文档当结论。GPT 的做法（pilot 差异小于 0.05 则调整任务，不在隐藏集调参）更稳妥。
- Gemini 的 InfoShare 使用逐样本 NEES 的 `|ln(NEES/3)|`：单样本卡方量方差很大，不稳定。应改为时间窗平均 NEES（ANEES）与一致性区间（χ² 界）。
- GPT 的 InfoShare 误差截断在 20 m，指标本身简洁，可作为 Suite 主分；NEES/ANEES 作为校准性辅助指标。

### 2.10 与 PettingZoo/BenchMARL 的兼容

两方一致：`ParallelEnv.step()` 对应一个决策周期，不对应一个网络事件。差异：
- Gemini 的 Python 层使用固定 K 槽位邻居观测、收件箱按队友索引排列，吞吐声称单核 ~800 steps/s，64 核 4–5 万 steps/s。**这些数字没有实测依据**；GPT 的验收标准更合理（8 实体、L1、10 Hz、32 环境，≥ 200 team-steps/s/服务器，未测前不承诺 1000 FPS）。采用 GPT 的做法：先测，再承诺。
- Gemini 的 `comm_payload` 用连续向量加 int8 量化，是可学习通信的合理映射；采用，并保留任意 bytes 协议走原生 SDK（不强行压入固定张量）。
- 训练用集中 critic 的全局 state 通过独立训练接口返回，不进入官方评测观测（GPT）。

### 2.11 路线图

两方时间表接近。差异：
- Gemini 在 W13–W16 安排顶会论文定稿并提交，**与实际进度不匹配**（Hidden-Test 在 W13–16 才冻结，却要同时写论文）。GPT 的 M5/M6 才冻结 holdout 并做外部复现，更现实。
- 两方都不要把 NS-3 联仿放进关键路径。

## 3. 可直接采纳的具体设计

### 3.1 核心接口（合并版，Python 3.11）

约定：
- 时间用 `int64` 纳秒（与 NS-3 一致，292 年范围足够）。
- 内核生成消息身份和时间戳，Agent 不得伪造。
- 外部报文由 schema 编解码器验证，`bytes` 载荷必须附 `schema` 名，且有大小上限（应用消息 16 KiB）。

```python
from __future__ import annotations
from dataclasses import dataclass, field
from enum import IntEnum
from typing import Mapping, NewType, Optional, Protocol, Sequence

TimeNs  = NewType("TimeNs", int)
AgentId = NewType("AgentId", str)
EntityId = NewType("EntityId", str)
MessageId = NewType("MessageId", str)

# ---------- 调度 ----------
class Phase(IntEnum):
    PHYSICS_CLOSE   = 10  # 用上一周期已生效控制积分至 t
    WORLD_UPDATE    = 20  # 外生事件带、故障、出生、租约变更
    RESOURCE_ARBIT  = 25  # 机巢停靠/交接/移交仲裁 (依赖已更新的几何)
    SENSOR_CAPTURE  = 30  # 采样, 记录 capture_time_ns
    NET_ADVANCE     = 40  # 网络服务队列、投递
    OBS_SEAL        = 50  # 密封本轮私有观测
    AGENT_DISPATCH  = 60  # 并行发起推理; 本阶段不得修改世界
    COMMAND_COMMIT  = 70  # 提交到达执行时刻的动作
    TRACE_FLUSH     = 90

@dataclass(frozen=True, order=True)
class EventKey:
    time_ns: TimeNs
    phase: Phase
    producer_id: str     # 稳定规范 ID, 不得用哈希值或线程完成顺序
    producer_seq: int    # 生产者内部确定性序号

# ---------- Agent / Entity / Assignment ----------
class ControlScope(IntEnum):
    NONE = 0; SENSOR_GIMBAL = 1; NAVIGATION = 2; FULL = 3

@dataclass(frozen=True)
class Assignment:               # 控制权租约, 与 MRTA 的"任务分配"概念不同
    agent_id: AgentId
    entity_id: EntityId
    scope: ControlScope
    valid_from_ns: TimeNs
    valid_until_ns: TimeNs      # -1 表示直到被显式移交/抢占
    epoch: int                  # 单调递增, 旧 epoch 的命令被拒绝

@dataclass(frozen=True)
class FrameRef:
    frame_id: str; sensor_id: str
    captured_at_ns: TimeNs; content_sha256: str

# ---------- 消息 ----------
@dataclass(frozen=True)
class SendRequest:              # Agent 提交
    destinations: tuple[AgentId, ...]   # 空 = 广播 (内核展开为计费单播)
    channel: str
    schema: str
    payload: bytes              # <= 16 KiB, 更大的证据须分片
    max_age_ns: int             # TTL
    priority: int = 4           # 0 最高 .. 7 最低, 进入 DRR 类别
    source_sample_time_ns: Optional[TimeNs] = None  # 声明值; 内核核对其不晚于 Agent 已收到样本的采集时刻

@dataclass(frozen=True)
class DeliveredMessage:         # 内核生成
    message_id: MessageId
    sender_id: AgentId
    submitted_at_ns: TimeNs
    delivered_at_ns: TimeNs
    wire_bytes: int
    rssi_dbm: Optional[float]   # 仅本消息的接收测量; 不提供全体邻居表 (防真值侧信道)
    channel: str; schema: str; payload: bytes
    source_sample_time_ns: Optional[TimeNs]

# ---------- 非网络交互 (Request/Grant/Release/Preempt) ----------
@dataclass(frozen=True)
class InteractionOp:
    op_type: str                # "nest.dock.req" | "nest.undock.rel" | "handoff.offer"
                                # | "handoff.accept" | "lease.transfer" | "commit.revoke"
    actor: AgentId; target_id: str
    params: Mapping[str, object] = field(default_factory=dict)

@dataclass(frozen=True)
class InteractionEvent:
    op_id: str; op_type: str
    status: str                 # GRANTED | DENIED_BUSY | DENIED_DISTANCE | PREEMPTED | EXPIRED
    effective_at_ns: TimeNs
    updated_assignment: Optional[Assignment] = None

# ---------- 决策 ----------
@dataclass(frozen=True)
class EntityCommand:
    entity_id: EntityId
    assignment_epoch: int
    command_schema: str         # "vel_body" | "waypoint_w" | "hover_hold" ...
    command: bytes
    valid_for_ns: int

@dataclass(frozen=True)
class Observation:              # 对应扩展后的 obs
    agent_id: AgentId
    tick_id: int
    sampled_at_ns: TimeNs
    sealed_at_ns: TimeNs
    assignments: tuple[Assignment, ...]
    body_schema: str            # "obs.v1" (legacy 投影) 或 "coord.v1"
    body: bytes                 # 原 obs.v1 msgpack
    inbox: tuple[DeliveredMessage, ...]
    interaction_events: tuple[InteractionEvent, ...]
    visible_frames: tuple[FrameRef, ...]
    ledger: Mapping[str, float] # 自己的剩余预算: bytes, cpu_ms, tokens, energy_wh[entity]

@dataclass(frozen=True)
class ReportRequest:
    report_schema: str; report: bytes
    evidence_frame_ids: tuple[str, ...]   # 必须是该 Agent 在报告时刻前确实收到的帧

@dataclass(frozen=True)
class BeliefSnapshot:           # 自愿提交, 仅供诊断与事后归因
    schema: str; valid_at_ns: TimeNs; payload: bytes

@dataclass(frozen=True)
class Decision:
    tick_id: int                # 必须回显
    commands: tuple[EntityCommand, ...] = ()
    messages: tuple[SendRequest, ...] = ()
    interactions: tuple[InteractionOp, ...] = ()
    reports: tuple[ReportRequest, ...] = ()
    beliefs: tuple[BeliefSnapshot, ...] = ()

class AgentPolicy(Protocol):    # 本地进程内 (研发/训练) 与容器 RPC (正式评测) 共用语义
    def initialize(self, ctx: "InitContext") -> None: ...
    def decide(self, obs: Observation) -> Decision: ...
    def close(self) -> None: ...

# ---------- 网络 (有状态队列服务, 不是 "一次函数返回随机送达时间") ----------
@dataclass(frozen=True)
class TxReceipt:
    message_id: MessageId; accepted: bool; charged_bytes: int; reason: str

@dataclass(frozen=True)
class LinkGeometry:             # 由内核提供, 记录几何年龄
    sender: AgentId; receiver: AgentId
    distance_m: float; n_wall: int; snapshot_at_ns: TimeNs

class InteractionNetwork(Protocol):
    def submit(self, sender: AgentId, req: SendRequest, now: TimeNs) -> TxReceipt: ...
    def advance(self, now: TimeNs, elapsed_ns: int,
                geometry: Sequence[LinkGeometry]) -> "NetworkAdvance": ...
    def save_checkpoint(self) -> bytes: ...
    def restore_checkpoint(self, blob: bytes) -> None: ...

# ---------- 随机与 Trace ----------
class RandomOracle(Protocol):
    def uniform(self, domain: str, object_key: str,
                time_index: int, draw_index: int) -> float: ...
# 派生: key_d = BLAKE2b-128(master_seed ‖ suite_version ‖ domain ‖ object_id)
# 域: world / target / weather / sensor / channel / failure / policy

@dataclass(frozen=True)
class TraceRecord:
    key: EventKey
    visibility: str             # evaluator_private | participant | public
    schema: str
    payload: bytes              # 大数组/图像存内容寻址对象, trace 存引用

class TraceSink(Protocol):
    def append(self, rec: TraceRecord) -> None: ...
    def finish(self, manifest: Mapping[str, str]) -> None: ...
```

约束：
- 插件不得持有 `WorldKernel`、调度器或网络对象；所有输出经 `DecisionValidator` 校验身份、epoch、能力范围和大小。
- 首发不允许同一 Entity 同时被多个 Agent 写入；共享控制需另设仲裁模块。
- 评测器 `TaskEvaluator` 读取权威（evaluator_private）Trace，Agent 不可见。可见性标签**不是安全机制**，必须物理分文件存储。
- Trace 格式：事件流用定长二进制或 Arrow IPC（避免 JSON 序列化拖慢 FleetSim，这是 Gemini 对 GPT JSON 事件的正确批评），分析导出为 Parquet。至少记录：配置与制品哈希、Assignment 变化、帧时间位姿与标定、报告接收时刻与证据关联、排队与资源计量、超时与违规及终止原因、指标版本与有效样本掩码。

**与 `obs.v1` 的映射**
- `legacy-v1`：投影为原 `obs.v1`，不发送扩展字段，原 action/report 解码器保持。若 Agent 仅持有一个有效 Assignment，其观测映射回顶层旧键。
- `coord.v1`：外层增加 `agent_id/tick_id/assignments/inbox/interaction_events/ledger`，`body` 保存原私有 `obs.v1`。
- 握手声明所支持的 observation/action/report schema。严格 schema 校验的旧 Agent 通过旧版投影器隔离，不假设"旧 Agent 会忽略新增字段"。
- 旧 Agent 没有消息输出能力，不得据此宣称其参加了完整通信协作赛道。

### 3.2 调度语义

默认配置：

| 项目 | 默认值 |
|---|---|
| 时间表示 | int64 纳秒 |
| 物理步长 | 20 ms（50 Hz） |
| 网络服务粒度 | 1 ms |
| 决策周期 | 100 ms（10 Hz） |
| 建模决策时延 | 100 ms（扫描档 50/100/250/500 ms） |
| 理想网络最小送达 | 1 ms |
| 外生事件量化 | 20 ms（原始时刻和量化误差入 Trace） |
| 墙钟 watchdog | 5 s / 决策 RPC（只防挂起） |

每个物理边界 `t` 的处理顺序（对应上面的 `Phase`）：
1. 用上一周期已提交动作和环境积分 `[t − Δp, t)`。
2. 在 `t` 应用外生事件、故障和租约变更。
3. 仲裁机巢与交接等资源交互。
4. 采样传感器，记录 `capture_time_ns`。
5. 处理网络，投递已到达消息。
6. 密封观测，并行发起 Agent 推理。
7. 提交此前观测产生且到达执行时刻的动作（`t_apply = t_sealed + ℓ_model`）。
8. 刷新轨迹。

规则：
- 网络在物理边界之间运行，默认几何使用最近已完成物理帧的位置保持值，几何年龄 ≤ 20 ms，并记录在 Trace。
- 禁止调度到已完成阶段；当前阶段新事件只能进入更后阶段，否则推进到下一网络 tick。
- 排序号不得按 RPC 完成顺序分配。
- 暂停只停止宿主执行，不推进虚拟时间；批量环境互不共享 RNG、队列或缓存可变状态。
- 检查点只在无未完成 RPC 的屏障处保存，包含物理状态、任务状态、事件堆、生产者序号、队列、令牌、GE 状态，以及 Agent 状态或输入输出重放位置。Gazebo 或外部 API 不支持完整状态恢复时，降级为从初始状态重放。

**随机流细则**
- 外生世界随机量（天气、目标、故障）必须保持配对。
- 传感器噪声按 `sensor_id + capture_tick` 派生。
- GE 链路状态按 `link_id + 固定网络时间` 演化，不随包数演化。
- 包级随机数按内核分配的消息 ID 派生。不同消息序列之间不能声称完美 CRN（改变了策略就改变了内生量），论文中如实说明。
- 代价：ID 稳定性成为契约；新实体需规范出生 ID。

### 3.3 通信网络三档

**命名**：`network_profile ∈ {ideal, abstract, ns3}`（别名 N0/N1/N2）。`observation_profile` 沿用 D3 的 L0/L1/L2 名称（可有别名 O0–O2），`physics_profile ∈ {kinematic, fleetsim, external}`。

**Ideal**：无随机丢包，固定延迟 1 ms，保留认证、TTL、最大尺寸和字节预算。`ideal-unlimited` 只能用于参考实验，不与受限通信主榜混排。

**Abstract**（有状态服务）：

1. 路损（2.4 GHz）
   `PL(d) = 40.05 + 10·n·log10(max(d, 1 m)/1 m) + A_NLoS·I_NLoS (+ X)`，`P_r = P_t + G_t + G_r − PL`。
   `I_NLoS` 由 BVH 线段求交给出；默认 `X = 0`。
2. 有效容量（应用有效容量抽象，不宣称符合某个 MCS）
   `C = 0`（`P_r < S_min`）；否则 `C_min + (C_max − C_min)·clip((P_r − S_min)/(S_good − S_min), 0, 1)`。
3. 节点上行令牌桶 `b(t+Δ) = min(b_max, b(t) + R·Δ)`。令牌不足则排队，队列有界，满则 drop-tail，超 TTL 则过期丢弃。应用消息确定性分片，每片负载 1200 B，头部 64 B；每次发送和转发计费，首发不模拟 MAC 重传。
4. 共享信道每 1 ms 按稳定 ID 轮转 DRR 服务。服务时片消耗 `τ = 8·L_wire / C`。默认所有节点属同一干扰组。
5. 时延 `t_rx = t_service_done + ⌈d0 + d/c + J⌉_Δn`，`J ~ U(0, J_max)`。队列延迟已在 service completion 中体现，禁止重复计入。
6. 突发丢包：两状态连续时间马尔可夫链，生成元 `Q = [[−a, a],[b, −b]]`，`P(Δ) = exp(QΔ)`。包完成发送时按状态用 `p_G / p_B` 抽样。初态取稳态分布或显式固定。若叠加 SNR 误包率，则 `p_drop = 1 − (1−p_phy(SNR))(1−p_state)`（不使用 Gemini 的相加形式，避免超过 1 需截断）。
7. 分区：外生有向掩码 `M_ij(t) ∈ {0,1}`，有效容量 `M·C`。分区期间队列保留到 TTL，已完成发送的包不撤回（规则写入配置，避免实现分歧）。

默认参数（首发；`synthetic-stress` 标签，未校准前不得称真实）：

| 参数 | 默认 | 严苛档 |
|---|---|---|
| 频率 / 发射功率 | 2.4 GHz / 20 dBm | 2.4 GHz / 14 dBm |
| n_LoS / n_NLoS | 2.2 / 3.2 | 2.4 / 3.6 |
| NLoS 附加损耗 A_NLoS | 15 dB | 20 dB |
| S_min / S_good | −90 / −65 dBm | −88 / −65 dBm |
| C_min / C_max | 16 / 512 kbit/s | 8 / 256 kbit/s |
| 节点令牌速率 / burst / 队列上限 | 8192 B/s / 16 KiB / 64 KiB | 4096 B/s / 8 KiB / 32 KiB |
| 固定附加时延 d0 / 抖动上界 | 15 ms / 10 ms | 30 ms / 40 ms |
| GE a / b | 0.1 / 1.0 s⁻¹ | 0.4 / 0.8 s⁻¹ |
| GE p_G / p_B | 0.005 / 0.5 | 0.01 / 0.7 |
| 默认 TTL | 2 s | 2 s |
| 重传 | 无 | 无 |

默认参数的量级自检（本次计算，P_t=20 dBm，G=0）：
- 在 LoS 下，`S_min = −90 dBm` 对应 `PL = 110 dB`，范围约 1.5 km（`(110−40.05)/22 ≈ 3.18`）；`S_good = −65 dBm` 对应约 110 m。因此 110 m 以内为满容量，之上线性衰减到 1.5 km。
- 在 NLoS 下（n=3.2，附加 15 dB），`S_min` 对应约 52 m，`S_good` 对应约 8.6 m。即穿建筑几乎断链，必须依赖中继或绕行，这与"城市峡谷需要移动中继"的实验意图一致。需在 pilot 中确认这一苛刻度是否使通信无意义；若是，降低 A_NLoS 或 n_NLoS。

**预算口径**
- 硬额度以团队总发射字节计。例如 180 s、8 节点：`8 × 180 × 8192 B`。
- 明确区分：应用提交一次、无线发送一次、接收端累计字节是三个量。首发把广播展开为计费单播，同时记录 `B_tx` 与 `B_rx`。
- 内部 LLM 对话不得绕过团队通信预算；多 `Assignment` 单容器内部 Entity 之间的数据交换同样必须经网络服务计费（Gemini 的"关键封堵"，正确）。分布式赛道要求每个 Agent 独立进程或沙箱。

**校准与验证**
- 实现验证：
  - 1/4/8 节点恒定和突发流量下，发送字节守恒误差为 0；
  - 长时平均服务率与目标值误差 < 1%；
  - FIFO 场景排队时延误差 ≤ 1 网络 tick；
  - GE 坏状态占比与稳态理论值落入模拟 CI；
  - 饱和对称链路 DRR 公平性偏差 < 2%；
  - 固定输入和种子，网络事件哈希一致。
- 模型校准：用 ns-3 受控场景（`LogDistance` + `Buildings` + Wi-Fi）和真实链路测量分别校验。至少含 30 个距离点、LoS/NLoS、1/4/8 发送节点，拟合路损、goodput、RTT 与突发丢包长度。拟合目标用 Gemini 的做法：PDR-距离曲线与 P95 时延的 Wasserstein-1 距离 < 5%（作为目标，不是已达成）。无实测数据的配置标 `synthetic-stress`。

**NS-3 档同步协议**（保守锁步，唯一时间权威；GPT 的版本更严谨，采用）
1. Drone4D 在 `t` 发布位置快照、接口状态和待发送包。
2. NS-3 适配器注入事件，运行严格区间 `[t, t+h)`。
3. 边界前收集包事件，按 NS-3 时间戳返回。
4. 双方交换 `ADVANCE_DONE(t+h, state_digest)`，ACK 后 Drone4D 才推进。
5. 恰在边界的事件归入下一窗口，避免重复消费。
6. 默认 `h = 1 ms`（Gemini 的 20 ms 窗口使无线 MAC 退避与 ACK 的时序粒度偏粗）。窗口内位置按声明规则保持（或用 `ConstantVelocityMobilityModel` 线性外推，须在配置中声明）。
- 多跳与路由由明确一侧拥有，不双重计算；watchdog 触发则整次实验标为 infrastructure failure；联合检查点覆盖两侧，NS-3 模型无法序列化时采用输入重放。
- 首发只验收桥接协议、一个固定无线 profile 和对照测试。

### 3.4 首发 Suite 标准实例（pilot 前的初始值，pilot 后冻结）

通用：效用 `U ∈ [0,1]`，通信、计算和 token 另报，不混入效用；每个 Suite 提供算法隔离与闭环两种模式。

**S1 TaskAlloc（含联盟任务）**
- 地图 600 m × 600 m（风场与机巢为 D1/D2 遗产，可作为难度旋钮）；8 UAV；3 座机巢（每座同时仅容 1 架充电）；300 s。
- 32 个任务：24 个单机，8 个联盟/时间窗/前置关系任务（其中 4–6 个要求两种互补载荷在 3 s 内同步到场）。任务按泊松到达，公开，不需先搜索。
- 通信 4 KiB/s/节点；`t = 150 s` 一架 UAV 失去任务执行能力。
- 效用（采纳 Gemini 的价值加权与截止期衰减，去掉任意项）：
  `U_TA = Σ_j v_j · q_j · ψ_j · d_j / Σ_j v_j`，
  其中 `v_j ∈ {1,3,5}`，`q_j` 为完成质量，`ψ_j = max(0, 1 − Δt_sync/3 s)`（联盟任务；单机任务 ψ=1），`d_j = 1[t_done ≤ b_j]·exp(−0.01·max(0, t_done − a_j))`。分母含全部应完成任务。
- 辅助：重分配延迟、重复执行率、无效承诺率、飞行能耗、电量耗尽失能（安全事件单独记录，不隐藏进权重）。
- 基线：静态分区、最近任务贪心、周期匈牙利、CNP（D2 已有）、CBBA（标注适用假设）、CBBA-风场感知（需实现）、滚动 MILP 集中式参考。

**S2 CoopSearch-Handoff**
- 地图 800 m × 800 m；6 UAV（4 广角巡逻 + 2 长焦取证）；2 座机巢；12 目标（4 个高价值需长焦确认并持续跟踪 ≥ 60 s，8 个干扰行人）；300 s。
- 模式：exogenous 为主榜，interactive（警觉逃逸）为扩展。
- 通信 8 KiB/s/节点；90–120 s 子团队分区。
- 效用（GPT 的简化形式，保证 [0,1]）：
  `U_CS = (1/K) Σ_k 1[τ_k ≤ T]·(1 − τ_k/(2T))`，`τ_k` 为目标 k 的首次有效确认时刻。有效确认沿用 D3 证据审核（IoU ≥ 0.3，且同时检查类别、帧 ID 和时间一致性）。高价值目标的持续跟踪覆盖率 `c_j` 与交接成功作为 D3 的 AO/CE 分项并入"闭环模式"得分，权重由 pilot 固定。
- 虚警处理：预定义 report rate limit 与违规规则，不用线性扣分（Gemini 的 `−min(0.3, 0.05·N_FA)` 可产生负值）。
- 基线：独立 lawnmower、预分区 lawnmower、共享已搜索区域贪心、概率栅格 frontier、`close_track`（D3 已有）、集中式 belief 规划。

**S3 InfoShare（固定轨迹，隔离融合）**
- 400 m × 400 m（或 Gemini 的 600 m × 600 m 高密度区）；5–6 个传感节点按固定轨迹运动；4–6 个外生移动目标；180 s。
- 通信 1–4 KiB/s/节点；60–90 s 分区；120 s 一节点观测噪声升高；注入公共过程噪声与相关偏差（相关 GNSS 漂移），使独立性假设失效。
- 提供估计状态与协方差，不提供真值。
- 主分（GPT）：截断误差 `e = min(‖x̂ − x‖/20 m, 1)`（未提交有效估计取 1），`U_IS = 1 − mean(e)`。
- 校准性辅助（吸收 Gemini 的 NEES，但改为时间窗平均 ANEES）：在 10 s 窗口内计算 ANEES 并与 χ² 一致性区间比较，另报"过度自信率"。
- 基线：本地滤波、朴素信息融合（重复计入）、CI 融合、带来源去重的 gossip、集中式滤波。
- 区分度来自**共同来源与循环转发**：错误的独立性假设会使朴素融合过度自信，来源管理方法应在 ANEES 上受益。

**RobustCoord 协议**（对 S1/S2 施加）：扰动强度 `d ∈ {0, 0.25, 0.5, 0.75, 1}`，扰动包含节点静默失效、分区、机巢断电。
- 退化曲线 AUC：`S_rob = Σ_m (d_{m+1}−d_m)(Ū_{d_m}+Ū_{d_{m+1}})/2 / (d_4−d_0)`，另报 `L_deg = Ū_0 − Ū_1`。故障与通信退化分别作曲线，不混成单一指数。
- 另报故障检测延迟 `T_detect` 与任务接管恢复时间 `T_recover`。
- 注意：Gemini 的 `Rob = ½(U_C1/U_C0 + U_attr/U_C0)` 是两点比值，不是退化曲线面积，且低分策略可通过"保持低分"得到高比值，已被 GPT 指出，**不采纳**。

### 3.5 排行榜与统计协议（定案）

**赛道**：`(execution_topology, observation_profile, budget_profile)` 三元组，见 2.5。首发主榜：D-Coord（分布式、O1 或共享检测器、B1）；D-End2End（分布式、O2 原始传感器，GPU 固定配额）；C-Reference（集中式，单列，不参与 D 排名）。LLM 为 B-LLM 预算档。

**默认预算 B1**
- 实体、初始状态、传感器数量、采样率、可用地图完全相同。
- 每 Agent 2 vCPU、2 GiB RAM；CPU 时间总额不超过每模拟秒 100 CPU-ms；团队总额为 N 倍；线程并行不得逃避 CPU-time 计量。
- 不允许自带 GPU 推理（平台参考感知的开销不计入 Agent）。
- 网络字节为 Suite 硬额度（含头部、复制、转发、分片）。
- LLM token 额度为 0（B-LLM：固定模型制品，输入加输出总额 5 万/团队/episode，上下文重读按实际输入计量，禁止不计费的跨轮缓存 API）。
- 同一预算下比较的是相同上限，同时报告实际消耗；"相同实际计算量"需单独设计匹配实验。

**主分**：`S_task = 100 · Σ_s (1/|S|) · Ê[U_s]`（任务族等权）。不把 EC/EU/AO/CE 生硬套到每个 Suite；D3 原榜保持独立。

**样本规模**（首发官方配置，pilot 后修正）
- 每 Suite 12 个场景配置 × 5 个外生秘密种子 = 60 episodes，3 个 Suite 共 180 episodes/提交；干预对照（`Δ_cut`、`Δ_perm`）各加 60，但可对榜首与候选提交按需执行（对照组的平台基线 π_ind、π_central 由官方预计算缓存）。
- 提交验证阶段先跑每 Suite 2 场景 × 3 种子的冒烟集，崩溃率 > 20% 或效用低于独立基线一半则终止。
- 功效：`n ≈ ((z_{1−α/2} + z_{1−β}) σ_D / δ)²`。例：σ_D = 0.10、δ = 0.05、α = 0.05、β = 0.2，需约 32 个有效独立配对。再按 pilot 的 ICC 乘设计效应。
- L2 抽样审计榜独立发布，不把少量 L2 样本伪装成与 O1 相同的证据强度。

**推断**
- 主结果：场景等权均值及 95% CI（层次 bootstrap，1 万次）。
- 辅助：IQM、失败率、10% 分位数、性能概况（performance profiles）。
- 配对增益：同场景同种子形成差值，再 bootstrap。
- 多重比较：Holm。实际意义阈值 `ε = 0.02`（由 pilot 的 σ_D 复核）：下界 > ε 为"显著且实际更优"；区间落入 [−ε, ε] 才称等价；未检出差异不等于等价。
- 支配分层：保留 D3 的 tier 机制，但先构造"经校正的优于"有向图，合并强连通分量，标注"不确定组"。

**失败处理**：策略崩溃、超时、非法动作按预定义失败计分；基础设施故障独立认定、原样重跑；不得因某次任务失败而删除 episode。

**划分与防作弊**
- dev：公开地理块与种子，完整调试真值。
- validation：不同地理块与事件参数，公开聚合结果。
- holdout：独立地理区、隐藏事件生成族、冻结秘密种子，每月一次。
- 同一建筑、纹理资产及相邻块不跨 split；公开种子只用于开发，不参与官方分数；holdout 每半年轮换一部分。
- 运行隔离：每 Agent 独立沙箱，仅暴露私有 IPC；无出站网络，只读根文件系统，独立临时目录，禁 Docker socket、宿主 `/proc` 和共享可写挂载，seccomp，非 root；高风险提交使用 microVM；GPU 多 Agent 共享若不能保证隔离，则限制执行模式。
- 真值服务不在 Agent 网络命名空间内；不提供免费的"某动作是否有效""某任务是否完成""是否有目标"查询；内部对象 ID 不作为可观察目标身份下发；报告审核检查 frame provenance、采集时间、Agent 可见性与框坐标。
- 提交审计：保存 OCI digest、SBOM、依赖许可证、模型哈希；前列提交做静态审计、系统调用异常检查、重放和跨配置测试。
- 措辞：使用"风险控制与证据链"，不写"根除作弊"。

### 3.6 PettingZoo/BenchMARL 适配

```text
adapters/
  pettingzoo_parallel.py   # ParallelEnv: step() = 一个密封决策周期
  pettingzoo_aec.py
  torchrl_env.py
  benchmarl_task.py
  legacy_obs_v1.py
```

- `ParallelEnv.step(actions)`：验证同一密封 tick 的动作，同步提交，内核运行到下一密封决策时刻，返回各 Agent 私有 observation/reward/termination/truncation/info。不得把每个网络事件映射成一次 `step()`。
- `info` 不含 Agent 无权获得的真值；集中 critic 的全局 state 由独立训练接口返回。
- 固定机器人类型时的空间映射（采纳 Gemini 的槽位化方案并加掩码）：
  - observation `Dict`：`self_state: Box(float32, (D,))`、`detections: Box((Kmax, F))` + `detection_mask`、`inbox: Box((Mmax, P))` + `inbox_mask` + 每槽位 `age`、`rgb`（仅 O2）、`assignment_mask`；
  - action `Dict`：`velocity: Box(−vmax..vmax, (3,))`、`yaw_rate`、`gimbal`、`message_emit: Discrete(2)`、`message_vec: Box(−1..1, (D_msg,))`（适配器量化为 int8 装入 `SendRequest`）、`interaction_op: Discrete(N_nests + 1)`。
  - 截断策略、排序规则与最大项数固定。
- 动态实体授权不意味着 PettingZoo Agent ID 同步增减：首发固定决策 Agent 集合，变更 Assignment 并用 mask。
- 研究任意 bytes 协议时用原生 SDK，不强行压进固定张量空间。
- 同步/异步差异：ParallelEnv 为统一节拍加屏障，inbox 仍保留每条消息的实际时间戳；真正异步用原生 SDK 或 AEC（AEC 是轮转 API，不等于真实异步网络）；非均匀决策周期用固定最小步长加 action mask。
- 训练吞吐：L1 无渲染、无 JPEG、列式数组状态、批量感知；独立进程池优先；训练时 Trace 采样或关闭，官方评测必须完整；BenchMARL 经 TorchRL 适配张量 spec，不把训练库植入仿真核心。
- **吞吐验收以实测为准**：例如 8 实体、L1、10 Hz、32 环境，目标 ≥ 200 team-steps/s/服务器；未测量前不对外承诺 1000 FPS 或更高数字。
- 提供 `drone4d sdk pack` 把训练好的策略与适配层打包为符合 `coord.v1` 的评测容器（Gemini 的"一键导出"，采纳）。

### 风险与触发指标

| 风险 | 触发指标 | 缓解 |
|---|---|---|
| 确定性承诺失真 | L1 同制品 100 次运行出现非预期哈希差异；L2 重放分差 > 0.5 个百分点 | 排查调度与浮点来源；L2 降为容差复现；不发布跨机器位级承诺。 |

3. **一个可信的 Abstract 网络**：共享服务、令牌桶、队列、GE、LoS/NLoS、分区、字节计费，未实测的 profile 一律标 synthetic。
4. **三个小而有区分度的 Suite 加 RobustCoord 协议**，含算法隔离模式、至少三类基线、公开 dev 与独立 holdout。
5. **资源对齐、统计可审计的榜单**：绝对任务分为主榜；`Δ_ind`、`Δ_cut`、`Δ_perm`、`R_central` 为诊断；CI、Holm 校正、提交审计。

## 5. 双方方案的主要缺陷汇总（用于设计评审记录）

### 5.1 Gemini 的缺陷
- 夸大确定性（逐字节一致、任何机器一致）。
- 失败回退（超时悬停）使结果依赖墙钟。
- `η_B`（第一轮 GPT 版）与 `NCG`（Gemini 版）的公式缺陷：分子分母口径不一致，`B→0` 时可被刷分，切断通信的"脆弱策略"使增益虚高；`Rob` 为两点比值而非曲线面积。
- 金丝雀伪目标注入正式传感器会污染 benchmark。
- 随机 tile 切 40/30/30 造成地理泄露。
- 同容器多 `agent_id` 不构成隔离。
- 观测噪声防隐写"容量趋近于零"无证明。
- Suite 的预期得分、吞吐数字无实测依据；效用公式可为负。
- 路线图把论文定稿安排在 holdout 冻结的同一时段。
- 第一轮被截断，缺少路线图、风险和对设计稿的批评。

### 5.2 GPT 的缺陷
- `Decision` 同步屏障缺少对"一跳往返需两个周期"的显式说明（Gemini 的批评部分成立，见 2.3）。
- 没有 `Δ_perm` 这类更强的因果对照。
- `InfoShare` 首发固定传感器轨迹，不含主动选位，保守但削弱了"协作"表达（可通过 v1.1 扩展）。
- 只用 6 个场景 × 20 个种子，场景数量不足以支撑"泛化到场景族"的声明（它自己也指出了这一点）。
- 文献中有若干错误（见 6 节）。
- 对吞吐、协议类问题说得很多，但缺少可立即执行的 Suite 抽象和难度旋钮的具体建议（Gemini 在这方面更具体）。

### 6.5 结论

- **两个模型都发生了文献错误，且都没有主动标注出自己的错误**：Gemini 偏向"会议与期刊张冠李戴"（Zavlanos、Hollinger、Dames、Nunes、Melting Pot 2.0、PARTNR/Habitat 合并）；GPT 的错误更少，但在 Nunes 的作者名与刊物、Dames 的刊物、CoELA 第一作者、VMAS 会议处出错，并且在第二轮对对方的"审计"中还给出了新的错误。

- 对"待核实"的使用：GPT 的做法（对没把握的明确标注）更可取；Gemini 在第二轮的"文献审计"补齐了页码，其中 BenchMARL、SMACv2 部分为正确，但 CARIC 的发表信息不准确。

## 7. 主要的正确判断（摘要）

1. 平台贡献应限定为"在声明的确定性等级下，统一描述观测、通信、行动和资源预算，支持可重放、可审计的协作干预实验"，不是"首个"或"任意机器位级一致"。
2. "协作智能"的科学含义来自干预对照，而不是总分：
   - 主榜用绝对任务效用；
   - `Δ_ind`、`Δ_cut`、`Δ_perm`、`R_central` 分别回答不同问题；
   - 只有 `Δ_perm` 接近机制层因果。
3. 资源对齐是排行榜可信度的前提：算力、字节、token 的账本，加上物理分离的 Agent 进程。
4. 通信模型要有可验证的实现和诚实的标签（`synthetic-stress`），先保证队列、公平、守恒这些可测性质，再谈真实城市无线。
5. Suite 宁少勿滥：三个有区分度的 Suite + 横切的鲁棒性协议，比四个任务语义各异的 Suite 更有价值。
6. 路线图关键路径是内核契约、Abstract 网络、Suite 区分度 pilot 与分布式沙箱；NS-3、LLM 在线 API、MAPF/CoopTracking 等延后。
