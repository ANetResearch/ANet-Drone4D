**实现者先读这 12 条（每条都有源码或实测依据）：**

1. **无 GPU 服务器完全可以跑 PX4 多机，用 SIH 不用 Gazebo。** 实测每个 SIH 实例在 RTF≈0.95 时约占 **0.21–0.23 核**，RSS 约 **10 MB**，每实例 29 个线程。本机（1.7 GHz Broadwell 8 核，与其他任务共享）跑 **≤8 机可保持 RTF≥0.92**，16 机 RTF≈0.72，32 机 RTF≈0.36–0.44。归一化成本约 **0.23–0.30 核·秒/仿真秒/机**。容量估算公式：`N_rt ≈ 0.8·cores / 0.25`（独占机器，估算）。见 §3.9。
2. **不用编译。** 官方镜像 `px4io/px4-sitl:<tag>`（45 MB）已包含 `simulator_sih`、`simulator_mavlink`、`uxrce_dds_client`、`sensor_*_sim`、`battery_simulator`。机体物理参数可以用环境变量 **`PX4_PARAM_<NAME>=value`** 在启动时覆盖（`ROMFS/px4fmu_common/init.d-posix/rcS` 的 env 循环），已实测生效：`SIH_MASS` 被改为 2.064。
3. **SIH 默认 `sihsim_quadx` 不像真实机。** 默认参数是 1 kg、每桨 5 N、`SIH_KDV=1 N/(m/s)`，线性阻力过大。实测 50 m 位置阶跃最高只到 9.8 m/s（被阻力限住），8 m/s 风里要**俯仰 39°** 才能悬停。换成 x500 级参数（§3.2 表）后，vmax 11.9 m/s，8 m/s 风里俯仰 7.9°，更可信。
4. **PX4 多旋翼控制级联**（`PositionControl.cpp`）：位置 P（`MPC_XY_P=0.95`）→ 速度 PID（`MPC_XY_VEL_P/I/D_ACC=1.8/0.4/0.2`，Z 轴 `4/2/0`）→ 加速度 → `body_z=normalize(-ax,-ay,g)` 并限倾角 45° → `collective=(az·Th/g−Th)/cos` → 期望四元数 → 姿态 P（`MC_ROLL_P=4`，yaw weight 0.4）→ 速率 PID（`MC_ROLLRATE_P/I/D=0.15/0.2/0.003`）→ 控制分配（效能矩阵伪逆）→ 电机一阶滞后。公式和伪代码见 §3.3。
5. **我们的 mock L1**（`mock_px4lite.py`，约 250 行 numpy）与 SIH（x500 参数）对照几乎一致。offboard 50 m 阶跃：vmax 11.89/11.89 m/s，a98 7.97/8.00 m/s²，t90 4.85/5.0 s，超调 1.67/1.70 m。平滑 GoTo：巡航 5.25/5.16 m/s，t90 10.4/10.9 s。8 m/s 风里悬停俯仰 7.9/7.9°。**性能**：1000 架 @250 Hz 每步 3.5 ms，单核。
6. **端口规则**（`px4-rc.mavlink`）：GCS 链路本地 18570+i，远端 14550；**API/Offboard 链路本地 14580+i，远端 14540+i，但 i>9 时远端固定为 14549**（10 机以上会撞端口，实测 16 机只收到 11 个心跳）。**正确做法**是 Gateway 主动 `udpout` 到 **14580+i**，PX4 会把回包地址锁定为我们的源端口（`mavlink_receiver.cpp` L3920–3960）。SIH 真值走 19410+i，HIL 物理接口走 TCP 4560+i（PX4 是 client）。
7. **多机实例的命名规则**：`MAV_SYS_ID=i+1`、`UXRCE_DDS_KEY=i+1`，DDS namespace 是 **`uav_i`**（i≠0 时；见 rcS）。注意 `docs/en/sim_sih/index.md` 和 `multi_vehicle_simulation.md` 里写的 `px4_1` **与代码不一致**，以代码为准。
8. **所有 SIH 实例默认出生在同一点**（`SIH_LOC_LAT0/LON0/H0` 默认值 47.397742, 8.545594, 489.4）。**SIH 的地面是 `SIH_LOC_H0` 高度处的一个无限平面**（`equations_of_motion` 的 fake ground），不认识楼宇和点云。所以每个实例都要设各自的 `PX4_HOME_LAT/LON/ALT`；与世界几何的碰撞、起降点地形由 World Service 负责（§6 R3）。
9. **SIH 风只支持水平均匀常值风**（`SIH_WIND_N/E`，飞行中可改）。**参数语义是"风从北/东吹来"**，代码里 `_v_apparent_N = _v_N + _v_wind_N`。没有垂直风、阵风和空间场。要支持 E(x,y,z,t) 风场，得靠我方物理：mock L1/L2 或 HIL 桥（§3.6）。
10. **Offboard 协议**：先以 ≥2 Hz 流式发 setpoint，再切 `OFFBOARD`（main_mode 6），然后解锁；超过 `COM_OF_LOSS_T`（默认 1 s）没收到就会触发 failsafe。**offboard 下的 position setpoint 不经过平滑**，直接进入 P 环，实测倾角 44°、加速度 8 m/s²。平滑航点要用 `DO_REPOSITION`/Mission，或者我方自己生成 jerk 受限轨迹再以 pos+vel+acc 形式发送（§3.4、§3.5）。
11. **每个 SIH 进程有独立的 lockstep 时钟**。RTF<1 时，各机仿真时间会相互漂移：16 机时 min/mean RTF 为 0.69/0.71，每分钟约差 1 s。需要机间交互（编队、避碰、ANet 协同）的场景，必须由 World 统一步进（HIL 桥或 mock），或者接受"按 wall-clock 近似同步"（§6 R5）。
12. **只有 Gazebo 需要 GPU**：`gz_bridge/server.config` 固定加载 `gz-sim-sensors-system`，且 `<render_engine>ogre2`；`px4-rc.gzsim` 强制 Gazebo ≥ Harmonic（gz-sim 8）。本机无 GPU，Gazebo 只能用 llvmpipe 软件渲染，camera/gpu_lidar 基本不可用。**Gazebo 只作 V0.5+ 的 GPU 节点可选项**，不作为飞控后端的必需组件。

## 2. 源码结构与关键模块

### 2.1 SITL 启动链（从 `make` 到飞起来）

```text
make px4_sitl_sih sihsim_quadx            # 或容器：docker run px4io/px4-sitl (PX4_SIM_MODEL=sihsim_quadx)
  └─ build/px4_sitl_sih/bin/px4 -i <inst> -d <rootfs/etc>       # posix 守护进程，px4_instance=inst
      └─ ROMFS/px4fmu_common/init.d-posix/rcS
          ├─ 按 PX4_SIM_MODEL 在 airframes/ 找 "<ID>_<model>" → SYS_AUTOSTART   (10040_sihsim_quadx / 4001_gz_x500)
          ├─ param set MAV_SYS_ID = inst+1 ; UXRCE_DDS_KEY = inst+1        # 多机身份
          ├─ PX4_SIM_SPEED_FACTOR → 按倍数放宽 COM_DL_LOSS_T / COM_RC_LOSS_T / COM_OF_LOSS_T
          ├─ . airframes/<ID>_<model>          # 机架默认参数（CA_ROTOR*, SIH_*, MPC_* …）
          ├─ env PX4_PARAM_<NAME>=v → param set  # ★ 无需重编译即可覆盖任意参数
          ├─ . px4-rc.simulator
          │     ├─ sihsim  → px4-rc.sihsim : PX4_HOME_* → SIH_LOC_*；simulator_sih start；sensor_{baro,gps,mag}_sim start
          │     ├─ gz      → px4-rc.gzsim  : 检查 gz ≥ 8.0.0；起/连 gz server；/world/<w>/create 生成模型 <model>_<inst>；gz_bridge start
          │     ├─ rotorpy → px4-rc.mavlinksim + px4-rc.rotorpy（SYS_HITL=1）：simulator_mavlink start -c 4560+inst
          │     └─ 其它    → px4-rc.mavlinksim（gazebo-classic / jsbsim / xplane …）
          ├─ commander / sensors / pwm_out_sim / navigator / rc.vehicle_setup（mc_pos/att/rate_control, control_allocator…）
          ├─ uxrce_dds_client start -t udp -p 8888 [-n uav_<inst>]
          ├─ . px4-rc.mavlink                   # 4 条（SIH 时 5 条）MAVLink 链路，见 §3.8
          └─ ekf2 start ; logger
```

### 2.2 关键模块与文件

| 文件 / 类 / 函数 | 作用与本项目相关要点 |
|---|---|
| `src/modules/simulation/simulator_sih/sih.hpp/.cpp` · `class Sih` | 进程内刚体仿真。`lockstep_loop()`：频率为 `min(IMU_GYRO_RATEMAX, IMU_INTEG_RATE)`；SITL 下 `px4-rc.simulator` 设 `IMU_INTEG_RATE=250`，即 **250 Hz，每步 4000 µs**。每步调用 `px4_clock_settime(CLOCK_MONOTONIC)` 推进仿真时钟，然后 `sensor_step()`，再**等待 `actuator_outputs_sim` 更新**，最多 10 s，最后 `usleep(rt_interval)`。`sensor_step()` 依次执行 `read_motors → generate_force_and_torques → equations_of_motion → reconstruct_sensors_signals`，外加测距（50 Hz）、信标（2 Hz）、真值发布 |
| `sih.cpp::generate_force_and_torques` | 四旋翼：`T_B=(0,0,−T_MAX·Σu)`；`Mt_B=(L_ROLL·T_MAX·(−u0+u1+u2−u3), L_PITCH·T_MAX·(u0−u1+u2−u3), Q_MAX·(u0+u1−u2−u3))`；`Fa_E=−KDV·R_N2E·v_apparent`；`Ma_B=−KDW·ω`。六旋翼用 `u·|u|`（二次推力） |
| `sih.cpp::equations_of_motion` | 在 ECEF 下积分：重力（WGS84，随纬度变化）、科氏力、transport rate。速度用 forward Euler，位置用梯形积分，姿态用 `q_E ← q_E ⊗ AxisAngle(ω·dt)`，角速度 `ω̇ = I⁻¹(M − ω×Iω)`，限幅 ±6π rad/s。**假地面**：高度低于 `SIH_LOC_H0` 且合力向下时抵消合力，首次触地时一步刹停 |
| `sih.cpp::reconstruct_sensors_signals` | IMU 真值加高斯噪声：acc σ=0.1 m/s²，gyro σ=0.01 rad/s。代码里"armed 大噪声"分支被 `if (false && …)` 关闭 |
| `sih_params.yaml` | `SIH_MASS=1.0`、`SIH_IXX/IYY=0.025`、`IZZ=0.03`、`SIH_T_MAX=5 N`（单桨）、`SIH_Q_MAX=0.1 N·m`、`SIH_L_ROLL/PITCH=0.2 m`、`SIH_KDV=1.0 N/(m/s)`、`SIH_KDW=0.025`、`SIH_T_TAU=0.05 s`、`SIH_WIND_N/E=0`、`SIH_LOC_*`、`SIH_VEHICLE_TYPE`（0 quad … 5 rover） |
| `simulator_mavlink/SimulatorMavlink.cpp` | HIL 接口。PX4 以 **TCP client** 连到 `localhost:4560+i`，收 `HIL_SENSOR`（`imu.id==0` 时用 `time_usec` 设置 PX4 单调时钟，并调用 `px4_lockstep_progress`）、`HIL_GPS`、`HIL_STATE_QUATERNION`、`DISTANCE_SENSOR`、`ODOMETRY`、`RC_CHANNELS` 等；发 `HIL_ACTUATOR_CONTROLS`。**SIH 镜像里也带这个模块（已实测），设 `PX4_SIMULATOR=rotorpy` 即会等待 4560** |
| `gz_bridge/GZBridge.cpp` | 订阅 `/world/<w>/clock`（同步 PX4 时钟）、`/world/<w>/pose/info`、`…/imu_sensor/imu`、磁力计、气压、navsat、odometry、2D/1D lidar、光流。电机经 `GZMixingInterfaceESC` 输出 |
| `gz_bridge/server.config` | 世界插件：Physics、UserCommands、SceneBroadcaster、Contact、Imu、AirPressure、AirSpeed、ApplyLinkWrench、**WindEffects**、NavSat、Magnetometer、**Sensors(ogre2)**、OpticalFlow、GstCamera |
| `mc_pos_control/PositionControl/PositionControl.cpp` | `_positionControl`、`_velocityControl`（含垂直优先的推力饱和与 tracking ARW）、`_accelerationControl`、`updateHoverThrust`（切换 hover thrust 时对积分器做补偿） |
| `mc_pos_control/PositionControl/ControlMath.cpp` | `limitTilt`、`bodyzToAttitude`、`thrustToAttitude`、`constrainXY`（在限幅内优先保留位置项）、`cross_sphere_line` |

### 3.1 坐标系约定与转换（必须全系统统一）

PX4 内部统一使用 **NED 世界系 + FRD 机体系**（x 前、y 右、z 下）。四元数 `q` 表示 body→NED，按 `[w,x,y,z]` 存储。本项目的 World 用 ENU（RTK 原点），Three.js 为 Y-up 右手系。

```text
NED → ENU :  (e, n, u) = ( y_ned,  x_ned, −z_ned )
ENU → Three : (X, Y, Z) = ( e,  u, −n )            # X=东, Y=天, Z=南
NED → Three : (X, Y, Z) = ( y_ned, −z_ned, −x_ned )
姿态：R_obj = M_w · R_nb · M_bm
  M_w  = [[0,1,0],[0,0,−1],[−1,0,0]]               # NED 向量 → Three 向量
  M_bm = [[0,0,1],[−1,0,0],[0,−1,0]]               # glTF 模型系(+X 左,+Y 上,+Z 前) → FRD
  验证：R_nb=I（机头朝北）时 R_obj=diag(−1,1,−1)，即绕 Y 转 180°，模型 +Z 指向北（−Z_three）。✓
yaw_ned（0 指北、顺时针为正）↔ heading_enu = π/2 − yaw_ned
```

**多机坑**：MAVLink 的 `LOCAL_POSITION_NED` 原点是**各机自己的 EKF 原点**（首次 GPS 定位或 home），不同机的原点不同。Gateway 转换到 World ENU 时，应以 `GLOBAL_POSITION_INT` 或 SIH 真值 `HIL_STATE_QUATERNION` 的 lat/lon/alt 为准：先转 ECEF，再转 World ENU（原点取 `coordinate.json` 的 RTK origin）。另一种做法是记录每机出生点偏移后直接加上。

### 3.2 SIH 刚体动力学（mock L2 可直接移植）

**方程**（`sih.cpp`；我们在局部 ENU/NED 平面近似下移植，去掉 ECEF、科氏力和 transport rate，因为城市尺度下误差可忽略）：

```text
u_i ← u_i + dt/τ · (u_sp,i − u_i)                         # 电机一阶滞后，τ = SIH_T_TAU
T_B  = (0, 0, −T_max · Σu_i)                               # 四旋翼线性推力（六旋翼用 u|u|）
M_B  = ( L_r·T_max·(−u0+u1+u2−u3),
         L_p·T_max·( u0−u1+u2−u3),
         Q_max    ·( u0+u1−u2−u3) ) − K_dw·ω               # PX4 电机编号：0 前右 CCW，1 后左 CCW，2 前左 CW，3 后右 CW
v_air = v − w(x,t)                                          # ★ 我们用 Environment 风场 w；SIH 是 v + wind_from
F     = R·T_B − K_dv·v_air  (+ 可选二次项 −K_q·|v_air|·v_air) + m·g·ẑ_down
v̇ = F/m ;  ω̇ = I⁻¹(M − ω×Iω) ;  q ← q ⊗ exp(ω·dt/2) ; 归一化
地面：if z_ned ≥ −h_ground(x,y) and F_z > 0: 抵消 F_z；首次触地 v ← 0 → landed
```

### 3.3 PX4 多旋翼控制级联（mock L1/L2 的核心，逐级公式）

记号：NED；`Th` = hover thrust（归一化）；`g=9.80665`；推力矢量 `thr` 为归一化量（−z 为向上）。

**① 位置环**（`PositionControl::_positionControl`）

```text
v_sp = K_pos ⊙ (p_sp − p) + v_ff                          K_pos = (MPC_XY_P, MPC_XY_P, MPC_Z_P) = (0.95, 0.95, 1.0)
v_sp.xy = constrainXY(v_pos.xy, v_ff.xy, MPC_XY_VEL_MAX=12)   # 限幅时优先保留"指向目标"的分量
v_sp.z  = clamp(v_sp.z, −MPC_Z_VEL_MAX_UP=3, +MPC_Z_VEL_MAX_DN=1.5)
（任一维 setpoint 为 NaN 即不控该维；xy 必须成对出现）
```

**② 速度环 PID**（`_velocityControl`）

```text
e_v   = v_sp − v
a_sp  = Kp_v⊙e_v + I_v − Kd_v⊙v̇ + a_ff                   Kp_v=(1.8,1.8,4.0) Ki_v=(0.4,0.4,2.0) Kd_v=(0.2,0.2,0)
I_v.z 限幅 ±g
```

**③ 加速度→推力矢量**（`_accelerationControl`，默认 `MPC_ACC_DECOUPLE=1`）

```text
body_z = normalize(−a_sp.x, −a_sp.y, g)                  # 解耦：垂直加速度不参与倾角计算
body_z = limitTilt(body_z, ẑ, MPC_TILTMAX_AIR=45°)        # 超限时沿同一方位角把倾角压到上限
T_ned_z = a_sp.z · Th/g − Th
collective = min(T_ned_z / body_z.z, −MPC_THR_MIN=−0.12)
thr = body_z · collective
```

**④ 推力饱和（垂直优先 + 水平裕度）与抗积分饱和**

```text
xy_alloc = min(|thr.xy|, MPC_THR_XY_MARG=0.3)
thr.z    = max(thr.z, −sqrt(THR_MAX² − xy_alloc²))
thr.xy  *= min(1, sqrt(THR_MAX² − thr.z²) / |thr.xy|)
垂直 ARW：推力贴下限且 e_v.z≥0，或贴上限且 e_v.z≤0 时，e_v.z ← 0
水平 tracking ARW：a_prod = thr.xy·g/Th；若 |a_sp.xy| > |a_prod|，则 e_v.xy −= (2/Kp_v.xy)·(a_sp.xy − a_prod)
I_v += Ki_v ⊙ e_v · dt
```

**⑤ 推力矢量→期望姿态**（`ControlMath::bodyzToAttitude`）

```text
z_b = −thr/|thr| ;  y_C = (−sin ψ_sp, cos ψ_sp, 0) ;  x_b = normalize(y_C × z_b) ;  y_b = z_b × x_b
R_sp = [x_b y_b z_b] → q_sp ;  thrust_body_z = −|thr|
```

**⑥ 姿态环**（`AttitudeControl::update`）

```text
q_red = shortest_rotation(z(q) → z(q_sp)) ⊗ q               # 先对齐推力轴
q_sp' = q_red ⊗ Rz(MC_YAW_WEIGHT · Δψ)                     # yaw 优先级降低（0.4）
e_q  = 2 · sign(q_e.w) · q_e.xyz ,  q_e = q⁻¹ ⊗ q_sp'
ω_sp = K_att ⊙ e_q   （K_att = (4, 4, 2.8/0.4)，即 yaw 增益先除后乘，净效果不变）
ω_sp = clamp(ω_sp, ±(220, 220, 200) °/s) ；自动模式 yaw 速率另受 MPC_YAWRAUTO_MAX=60°/s 限制
```

**⑦ 角速率环**（`RateControl::update`）

```text
τ = K·[P⊙(ω_sp−ω) + I − D⊙ω̇_filt + FF⊙ω_sp]          P=(0.15,0.15,0.2) I=(0.2,0.2,0.1) D=(0.003,0.003,0) K=1
i_factor = max(0, 1 − (e/400°)²) ;  I += i_factor·I_gain·e·dt ;  |I| ≤ (0.3,0.3,0.3) ；分配器饱和方向上停止积分
```

**⑧ 控制分配**：先按转子几何算效能矩阵 `B`（6×n），再求伪逆 `u = B⁺·[τ; T]`，并做逐步去饱和。四旋翼 X 型可以直接用 §3.2 的闭式反解：

```text
u0 = T/4 − τx/(4L) + τy/(4L) + τz/(4Q)   … （符号对应 §3.2 的 M_B 公式，再 clamp 到 [0,1]）
```

**控制器运行频率**：rate 环在每个陀螺仪样本执行（SITL 250 Hz）；姿态环跟随 `vehicle_attitude`（EKF2 输出预测器，约为 IMU 速率）；位置环跟随 EKF 的 `vehicle_local_position`（约 50–100 Hz，默认按 100 Hz 采样）。

**L1 简化**（`mock_px4lite.py` 的做法，已验证）：⑦⑧ 视为理想（ω=ω_sp），⑥ 只保留"四元数 P + 速率限幅"，yaw 使用净增益 `MC_YAW_P`，推力大小加一阶滞后 τ=0.03 s。于是每架机每步只需几十个向量运算，完全可以 numpy 向量化。

### 3.4 轨迹生成（jerk 受限；GoTo / 航线平滑）

**VelocitySmoothing**（单轴，`lib/motion_planning/VelocitySmoothing.cpp`）：给定当前 `(a0, v0)`、目标速度 `v_sp` 和约束 `j_max, a_max, v_max`，求三段时长：

```text
dir = sign(v_sp − v_at_zero_acc) ;  j = dir·j_max ;  Δv = v_sp − v0
T1 = (−a0 + ½·sqrt(2a0² + 4jΔv)) / j   （取使 T1、T3 ≥ 0 的根，并按 |a0 + jT1| ≤ a_max 截断）
T3 = a0/j + T1
T2 = (−½T1²j − T1T3j − T1a0 + ½T3²j − T3a0 + Δv) / (a0 + jT1)   （≥0）
状态更新 evaluatePoly(j,a0,v0,x0,t)：a=a0+jt, v=v0+a0t+½jt², x=x0+v0t+½a0t²+⅙jt³
三轴同步：取最长 T123，其余轴按 updateDurationsGivenTotalTime(T123) 重算
```

**PositionSmoothing**（航点）：

```text
crossing = isTurning ? L1Point(pos, wp_prev, wp_target; L1 = max(acc_rad, 5 m)) : wp_target
v_xy = min(MPC_XY_CRUISE, computeXYSpeedFromWaypoints([pos, wp1, wp2]))   # 反向递推
  computeMaxSpeedInWaypoint(α, a, d) = sqrt(a·d·tan(α/2))                  # 转弯处允许的最大速度
  computeMaxSpeedFromDistance(j, a, s, v_f):  b = 4a²/j ;  c = −2a·s − v_f² ;  v = ½(−b + sqrt(b² − 4c)) ;  max(v, v_f)
v_sp = unit(crossing − pos_traj) · v_xy  → 各轴 VelocitySmoothing
time_stretch = 1 − clamp(|drone − traj| / MPC_XY_ERR_MAX(2 m), 0, 1)       # 机体落后时放慢虚拟轨迹
```

默认约束：`MPC_XY_CRUISE=5`、`MPC_ACC_HOR=3`、`MPC_JERK_AUTO=4`、`MPC_Z_V_AUTO_UP/DN=3/1.5`、`MPC_ACC_UP/DOWN_MAX=4/3`、`MPC_XY_TRAJ_P=0.5`、`NAV_ACC_RAD=10`（多旋翼实际常设 2 m）、`NAV_MC_ALT_RAD=0.8`。

**mock 用的向量化近似**（牺牲精确的三段解，换取 N 架并行，已验证 t90 与 SIH 相差 <5%）：

```python
v_des = unit(target - x_tr) * min(cruise, vmax_from_dist(j, a, dist))    # z 轴单独处理
a_tgt = clip(2.0 * (v_des - v_tr), -a_max, a_max)
a_tr += clip(a_tgt - a_tr, -j*dt, j*dt)       # jerk 限幅
v_tr += a_tr*dt ; x_tr += v_tr*dt
→ 作为 (p_sp, v_ff, a_ff) 送入 §3.3 ①②
```

PX4 custom_mode 编码：`custom_mode = main<<16 | sub<<24`。main：MANUAL 1、ALTCTL 2、POSCTL 3、AUTO 4、ACRO 5、OFFBOARD 6、STAB 7。AUTO sub：READY 1、TAKEOFF 2、LOITER 3、MISSION 4、RTL 5、LAND 6。

**Offboard 时序**（`docs/en/flight_modes/offboard.md` + 实测）：

```text
1. 以 ≥2 Hz（建议 20–50 Hz）持续发 SET_POSITION_TARGET_LOCAL_NED（MAVLink）
   或 OffboardControlMode + TrajectorySetpoint（ROS 2）
2. DO_SET_MODE(1, 6, 0) → OFFBOARD ；3. ARM
4. 若 > COM_OF_LOSS_T(1 s) 未收到 → failsafe（COM_OBL_RC_ACT：0 Position（默认）、1 Altitude、2 Stabilized、3 Return、4 Land、5 Hold、6 Terminate、7 Disarm；无人机不带遥控时建议设为 5 Hold 或 3 Return）
type_mask（POSITION_TARGET_TYPEMASK：bit0–2 pos、3–5 vel、6–8 acc、9 FORCE、10 YAW、11 YAW_RATE，置 1 表示忽略）：
  只控位置（yaw 不控）= 0x0DF8；位置 + yaw = 0x09F8；pos+vel+acc+yaw 前馈 = 0x0800（只忽略 yaw_rate）
  （本次实测用的 0x0FF8 多置了 FORCE 位，因为 acc 也被忽略，所以不影响结果；正式实现请用上面的值）
```

**实测起飞曲线**（x500 化 SIH 同样适用）：AUTO_TAKEOFF 以约 1.5 m/s 爬升，10 m 约需 8 s。Offboard 直接给目标高度时，受 `MPC_Z_VEL_MAX_UP=3` 限制，实测峰值 2.75 m/s。

**mock 状态机**（对齐 PX4 的字段）：

```text
arming_state ∈ {DISARMED=1, ARMED=2}
landed_state ∈ {ON_GROUND, TAKEOFF, IN_AIR, LANDING}              # MAV_LANDED_STATE
nav_state    ∈ VehicleStatus.NAVIGATION_STATE_*
takeoff:  disarmed → spoolup(1 s) → ready → rampup(3 s，v_up 从 −g/Kp_vz 升到 TKO_SPEED) → flight
```

### 3.6 风扰：PX4 能做到哪里，我们要补什么

| 途径 | 源码依据 | 能力 | 结论 |
|---|---|---|---|
| **SIH** `SIH_WIND_N/E` | `sih.cpp::parameters_updated` 设 `_v_wind_N=(N,E,0)`；`ecefToNed` 算 `_v_apparent_N = _v_N + _v_wind_N` | 水平均匀常值风，**"从北/东吹来"为正**；飞行中可用 `PARAM_SET` 改（实测生效）。无垂直风、无阵风、无空间变化 | V0.2 演示"风速滑块 → 真飞控抗风"足够；E(x,y,z,t) 做不到 |

**风力模型**（mock 与 HIL 物理统一使用）：


### 3.9 实测：SIH 多机在无 GPU 服务器上的开销

条件：同一容器内起 N 个 `px4 -i k`（`--network host`），CPU 取容器 cgroup 的 `cpu.stat usage_usec`，统计窗口 10 s，RTF = Δ`time_boot_ms` / Δwall。"FLY" 列为全部解锁并悬停于 10 m 时的数据。主机同时被其他任务占用，load1 列出供参考。

| N | 容器 CPU（核，idle/fly） | 每机 CPU（核） | RTF min/mean（fly） | RSS 合计 | host load1 |
|---|---|---|---|---|---|
| 1 | 0.231 / 0.227 | 0.23 | 0.95 / 0.95 | 10 MB | 10–14 |
| 4 | 0.860 / 0.869 | 0.22 | 0.96 / 0.96 | 39 MB | ~5 |
| 8 | 1.790 / 1.737 | 0.22 | 0.92 / 0.92 | 88 MB | ~6 |
| 16 | 2.764 / 2.854 | 0.18 | 0.73 / 0.74 | 158 MB | 25–38 |
| 32 | 3.696 / 3.433 | 0.11 | 0.33 / 0.36 | 316 MB | 78–98 |
| 4 @ `PX4_SIM_SPEED_FACTOR=4` | 2.418 / 1.399 | 0.35 | idle 2.76，fly 1.39 | 39 MB | — |

**解读**：
- 单位成本约 **0.23–0.30 核·秒/仿真秒/机**（1.7 GHz Broadwell）。32 机时 RTF 掉到 0.36，主因是**线程数（29/机）远超核数时的调度延迟**，lockstep 每 4 ms 要走一轮 `usleep` 加等待 actuator。这不是纯算力不够，所以 RTF 不随 CPU 线性恢复。
- 容量建议：本机实时 **≤8 机**；独占的现代 16 核 3 GHz 服务器估算可实时约 **32–48 机**（估算，需复测）。更大规模可以：a) 从源码编 `nolockstep` 变体，用 `realtime_loop`（hrt 定时器，不做 lockstep）；b) 按 "hero drones 用 PX4 + crowd drones 用 mock" 混合保真度（§4）；c) 多主机分片。
- **加速仿真可行**：4 机 ×4 倍速时实际 RTF 1.4–2.8，可用于批量任务回归和 Agent 训练数据生成。
- 运行时信息：`px4-simulator_sih --instance k status` 会打印 "Achieved speedup: 0.99X"，可做健康监控。

## 6. 风险与注意事项

| # | 风险 / 坑 | 影响 | 对策 |
|---|---|---|---|
| R1 | 从源码构建需初始化 ~30 个子模块，`Tools/setup/ubuntu.sh` 会全局装包 | 本机禁止；CI 环境复杂 | 用官方容器（45 MB，已验证）；需要改源码时用 `px4io/px4-dev-*` 容器编译 |
| R2 | **i>9 时 API 链路远端端口统一为 14549** | ≥10 机时 udpin 模式串线（实测 16 机只收到 11 个心跳） | Gateway 一律 `udpout` 到 14580+i，先发心跳让 PX4 学习地址 |
| R3 | **SIH 地面 = `SIH_LOC_H0` 平面**，所有实例默认同一出生点 | 城市点云里起降高度错误，机体可"穿楼"，多机重叠 | 每机设 `PX4_HOME_LAT/LON/ALT`（ALT 取地形高程）；碰撞由 World Service 检测并发 crash 事件；需要严格地形时走 HIL 桥 |
| R4 | SIH 默认物理不真实（1 kg、KDV=1） | 风里倾角 39°、限速 9.8 m/s | 采用 §3.2 的 x500/P600 参数，用 `PX4_PARAM_*` 注入 |
| R5 | 各 SIH 进程 **独立 lockstep 时钟**，RTF<1 时会互相漂移 | 编队、避碰、协同任务时间不一致 | 需要机间交互时用 mock 或 HIL 桥统一步进；否则 Gateway 按 wall-clock 对齐并在 UI 标注 RTF |
| R6 | 线程数（29/机）远超核数时 RTF 急剧下降（32 机仅 0.36） | 大规模 PX4 不可行 | 混合保真度；`nolockstep` 变体；多主机分片；CPU pinning（`--cpuset-cpus`） |
| R7 | 文档与代码不一致：DDS namespace 代码是 `uav_i`，文档写 `px4_i`；RotorPy 文档写成 `PX4SIMULATOR`（少下划线） | ROS 2 话题对不上；HIL 模式起不来 | 以 `rcS` 和 `px4-rc.simulator` 为准，用 `PX4_SIMULATOR=rotorpy` |
| R8 | `SIH_WIND_N/E` 是"来向"语义，且无垂直分量 | 风向符号反了会导致 UI 与物理相反 | 统一在 Environment 层定义"air velocity（去向）"，送 SIH 时取反 |
| R9 | `HIL_STATE_QUATERNION` 的 `time_usec=0` | 真值流没有时间戳 | 接收端打时间戳，或对齐 `ATTITUDE.time_boot_ms` |
| R10 | onboard 链路默认约 400 msg/s/机 | 32 机时 Python 解析成为瓶颈 | `SET_MESSAGE_INTERVAL` 关掉不用的流（§3.8）；或 GCS 链路只取需要的流 |
| R11 | Gazebo 强制 ≥ Harmonic，server.config 固定 ogre2 Sensors | 无 GPU 机器上相机/LiDAR 基本不可用 | Gazebo 只放 GPU 节点；无 GPU 时 LiDAR 用我方点云射线投射 |
| R12 | x500 SDF 没有 `<enable_wind>`，windy 世界的风效果不确定 | gz 风扰验证可能无效 | 若采用 gz，需实测并在 SDF 加 `enable_wind` |
| R13 | 解锁前 EKF 需 2–5 s 收敛（实测会先报 "Preflight Fail: no heading reference"） | 起飞命令被拒 | Gateway 重试 ARM/TAKEOFF 或等待 `SYS_STATUS` 健康位；mock 模拟 3 s 的 "initializing" 状态 |
| R14 | `SIM_BAT_DRAIN=60 s`、`MIN_PCT=50%` 的默认电池仿真与真实不符 | 电量显示失真 | 使用 SIH 时 UI 电量改由我方电池模型计算；或设 `SIM_BAT_DRAIN` 为真实续航 |
| R15 | 本次测量主机被其他任务高负载占用（load 5–98） | §3.9 数值偏保守 | 在独占节点复测后再定容量 |
| R16 | 为实测拉取了镜像 `px4io/px4-sitl:v1.18.0-rc1`（45 MB） | 占用本机 docker 镜像存储 | V0.2 会继续使用；不需要时执行 `docker rmi px4io/px4-sitl:v1.18.0-rc1` |
| R17 | MAVSDK-Python 每个 System 起一个 `mavsdk_server` | 多机时进程数、端口数暴涨 | Gateway 用 pymavlink；MAVSDK 仅用于单机脚本和示例 |

## 7. 对设计文档 01-design.md 的优化建议

1. **§26/§35 "PX4 SITL + Gazebo 为第一阶段"应改为分级后端。** 飞控动力学不需要 Gazebo。建议改成：**L1 mock（MVP）→ PX4 SIH 容器（V0.2）→ PX4 + HIL 桥（V0.4/V0.6）→ Gazebo/Isaac（仅用于 GPU 节点的传感器仿真）**。同时在 §33 后端表里把 "Simulation: Gazebo" 改为 "Simulation: PX4 SIH / HIL / (Gazebo optional)"。理由：本机无 GPU 实测 SIH 可跑 8 机实时，而 Gazebo 在无 GPU 时传感器基本不可用。
2. **§29 "每架一个 PX4 SITL" 需要补容量与编排规则**：写明端口规则（§3.8）、`MAV_SYS_ID`/DDS key/namespace、出生点、容器化方式，以及"≤8 机/8 核"的容量结论。并引入**混合保真度**：关键机用 PX4，群体机用 mock L1，UI 用 `source` 字段标识。
3. **§28 DroneState 过于粗略**，建议按 §3.12 补全：坐标系/四元数约定、仿真时钟与 wall 时钟、`nav_state`/`arming_state`/`landed_state` 枚举（直接复用 PX4）、setpoint、真值与估计分离、电机输出、风（估计/真值）、事件流、`source`。
4. **§30 控制模式要映射到 PX4 语义**（§3.5 表）。mock 也必须实现同样的模式名、状态转移和 failsafe，这样 mock → SIH → 真机时 UI 和 Agent 代码都不用改。
5. **§36 数据流 "PX4 → ROS2 → Gateway → WS" 在 MVP 阶段过重。** 建议先做 **PX4 ⇄ MAVLink ⇄ Sim Gateway ⇄ WS**，ROS 2（uXRCE-DDS + Agent + Jazzy）放到 V0.6，按需接入 EGO-Swarm/Prometheus。同时把 §33 的 "UAV API: MAVSDK" 改为 "pymavlink（Gateway）/ MAVSDK（脚本）"。
6. **§37 刷新频率要写实**：PX4 SITL 的 IMU 与 rate 环 250 Hz（`IMU_INTEG_RATE=250`），位置环跟随 EKF（约 50–100 Hz）；mock 物理 100–250 Hz；Backend 聚合 50 Hz；WS 20–30 Hz 二进制帧，客户端缓冲 100 ms 后插值；Web 60 FPS。另外补充 lockstep 与倍速（`PX4_SIM_SPEED_FACTOR`）对 Timeline 的影响：仿真时间 ≠ 墙钟。
7. **§19–20/§47 风场分级要写明各后端能力**：SIH 只有均匀水平风，且参数是来向语义；空间变化风、垂直风、阵风（建议 OU 过程）只能在 mock/HIL 物理里实现。§47 的 "Wind → Drone Force" 应定义为 `F = −K_dv·(v−w) − K_q·|v−w|·(v−w)`，并给出 P600 的 K 值标定流程。
8. **§27 P600 数字孪生要落到参数层**：一份 `p600.yaml` 同时生成 SIH 机架、mock 参数和 gz SDF；参数项包括 `SIH_*`、`CA_ROTOR*`、`MPC_THR_HOVER`、`MPC_*`、`MC_*`。标定流程：称重 → 推力台或 ULog 中的 `hover_thrust_estimate` → 阶跃响应（对照 §3.10 的表）→ 风天悬停姿态回归 K_dv。本文给出的 P600 估算值（4 kg、TWR 2、I≈0.063/0.063/0.115）只作初值。
9. **缺少"世界几何 ↔ 飞控"的约定**：SIH/PX4 只认识一个地面平面。需要新增：① 出生点地形高程 → `PX4_HOME_ALT`；② World Service 提供 `ground_height(x,y)` 和 `collision(x,y,z)`（voxel/SDF），mock 与 HIL 物理直接使用，SIH 模式下由 Gateway 做碰撞检测并产生 crash 事件；③ 地理参考统一：各机 `LOCAL_POSITION_NED` 原点不同，一律经 lat/lon/alt 转 World ENU。
10. **缺少"时钟与同步"设计**：多 PX4 实例的 lockstep 时钟彼此独立。需要机间交互的场景（编队、ANet 协同）要么用 mock，要么用 HIL 桥的"World 统一时钟、全机队 lockstep"。
11. **§45 V0.2 验收标准可量化**：Takeoff/Land/GoTo/Orbit/RTL 全部可用；8 机 RTF ≥ 0.9；GoTo 50 m 的 t90 ≈ 10–11 s；offboard 阶跃超调 < 2 m（引用 §3.10）；WS 端到端延迟 < 150 ms。
12. **§42 Repo 结构建议**：`simulation/` 下分 `mock/`（L0–L2）、`px4/`（docker/launcher/airframes/params）、`hil/`（HIL server）、`gateway/`（MAVLink ⇄ DroneState ⇄ WS），并新增 `vehicles/p600/p600.yaml` 作为唯一参数源。
13. **安全与失效**：把 PX4 的 failsafe（数据链丢失、offboard 丢失、低电量、地理围栏 `GF_*`）和故障注入（`MAV_CMD_INJECT_FAILURE`：GPS off/stuck/wrong、电机）纳入产品功能，放在 UI 的"Scenario / Fault"面板。mock 也要实现相同的事件语义。
