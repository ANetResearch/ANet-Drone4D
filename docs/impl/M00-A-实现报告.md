### 1.6 Make 目标行为

| 目标 | 行为 |
|---|---|
| `make setup` | 架构检查（非 x86-64 退出码 13）→ 缺 `.venv` 时用 python3.12 创建 → uv 版本不符时自举 → `uv pip sync requirements.lock` → `pip install -e . --no-deps` → Node 22.12 检查（退出码 8）→ `npm ci`（锁文件哈希与上次成功安装一致时跳过，`FORCE=1` 强制）→ 检查本机 Chrome 151（缺失只警告）→ `SETUP_TARGETS` → `awr doctor --quick`（CLI 可用时）；支持 `OFFLINE=1` |
| `make lint` | `ruff check python tools tests` + `oxlint --type-aware`（apps/web）+ `LINT_TARGETS`；`-k` 模式下汇总全部失败 |
| `make test` | 共享性能锁内执行 `pytest -m "not perf"`（tests/ 全量）+ `vitest run --project unit --project browser` + `TEST_TARGETS`；`PYTEST_ARGS`、`VITEST_ARGS` 透传 |
| `make ci` | `tools/ci/run.sh` 存在时由它承载；否则依次 lint → `CI_TARGETS` 与 `tsc --noEmit` → vite build（`apps/web/index.html` 存在时）→ test |
| `make build` | 共享锁内 `npm run build -w apps/web` + `BUILD_TARGETS`；入口文件缺失时明确报错 |
| `make worlds`、`perf`、`chaos` | 分别调用 `WORLDS_TARGETS`（共享锁）、`PERF_TARGETS`、`CHAOS_TARGETS`（排他锁）；未登记实现时报错并提示所属模块 |
| `make run`、`dev` | 预检 supervisor 可导入 → `RUN_PRE_TARGETS` → worlds → 前端产物过期时 build（仅 run）→ `exec python -m awr.runtime.supervisor`（AWR_PROFILE 默认 demo、dev） |

性能锁：默认 `$(git common dir)/../runs/.perf.lock`，非 git 时为 `runs/.perf.lock`；等锁 1800 s；共享锁超时退出码 11，排他锁超时退出码 14；持有方式经 `AWR_PERF_LOCK_HELD`（sh 或 ex）传给子进程，嵌套调用不重复加锁。

## 3. 与设计文档的偏差及理由

| 编号 | 偏差 | 理由 | 影响与后续 |
|---|---|---|---|
| D-01 | 根 `overrides` 写 `"three": "0.186.1"`，而非 AWR-11 §3.5、§3.6 的 `"$three"` | npm 的 `$pkg` 引用只能指向根清单的直接依赖；workspaces 根没有 three，实测 `npm error Unable to resolve reference $three` | 语义等价；升级 three 时须同时改 apps/web 与根 overrides（`test_version_drift_rules` 会检出 three 版本变化） |
| D-02 | 新增 `requirements.in`（uv、pip、setuptools），锁命令为 `uv pip compile pyproject.toml requirements.in --extra geo --extra tools --extra test --extra dev --extra fetch --generate-hashes --python .venv/bin/python` | `uv pip sync` 会卸载锁外的一切包，包括 uv 自身与 pip；`fetch` 组（py7zr）是 ADR-038 列出的可选组，AWR-11 §3.6 的锁命令漏列，而 `make fetch-data` 需要它 | 锁文件含 70 个包；AWR-11 §3.6 的命令与 BOM 需同步 |
| D-03 | test extra 增加 pytest-asyncio 1.4.0、httpx 0.28.1 | 任务书要求一次装全（后续 agent 不再装依赖）；AWR-11 §3.2 未列 | M11 §14 第 9 条"不新增 httpx"的测试口径不受影响；需登记 BOM（`tools/ci/bom.json`） |
| D-04 | 显式列出 llvmlite==0.49.0 | AWR-11 §3.5 要求 numba、llvmlite、numpy 三者同步锁定 | 无 |
| D-05 | 不安装 three-mesh-bvh 为直接依赖 | AWR-11 T14：D1 无调用方，不写入 D1 清单 | drei 10.7.9 传递安装了 three-mesh-bvh 0.8.3（依赖范围 ^0.8）；V0.8 引入 0.9.x 时与 drei 的范围冲突，需届时评估 |
| D-06 | `uv pip sync` 从 `.venv` 卸载了研究期安装的 open3d、gdown、dash、flask、ipython 等 | 这是 `make setup` 的设计语义（锁文件为唯一版本来源）；D1 任何进程禁止 import open3d（TECH-FR-004）；gdown 只用于 P2 航线文件 | 需要 open3d 时用 `geo-worker` extra（V0.2）；gdown 需要时向 M00 申请加入 fetch 组 |
| D-07 | pytest 配置在冻结片段之外增加 `strict_markers`、`markers`、`faulthandler_timeout = 300`、`asyncio_default_fixture_loop_scope` | AWR-18 §8.2 要求登记标记且未登记即报错、挂死输出线程栈；冻结字段 testpaths、addopts 未改 | pytest-asyncio 保持 strict 模式，不影响 anyio 用例 |
| D-08 | ruff 增加 `allowed-confusables`（全角括号、逗号、冒号等中文标点，以及 ×、–、—、−） | PY-RUFF-01 选择了 RUF，RUF001–RUF003 会把中文注释与文档字符串中的全角标点全部判为易混淆字符 | 规则集本身（select、ignore、per-file-ignores、isort）与 AWR-19 §7.4 一致 |
| D-09 | tsconfig 增加 `allowImportingTsExtensions` 与 `resolveJsonModule` | vitest.config.ts 以 `./vite.config.ts` 导入，消除 Vite 原生配置加载器警告；契约 JSON 需要被 TS 导入 | 只在 `noEmit` 下生效，不影响构建 |
| D-10 | Make 目标失败时进程退出码为 2，§16.2 的具体码写在错误信息中（"错误（退出码 N）"） | GNU make 对任何失败配方都以 2 退出，无法直接透传 | OPS-FR-005 的"返回退出码"由 `awr` CLI 满足；Make 层只保证信息与修复命令；如需严格透传，可由 M00 在后续提供 `tools/ci` 包装脚本 |
| D-11 | `make setup` 在 package-lock.json 哈希与上次成功安装一致时跳过 `npm ci` | `npm ci` 每次删除并重装 node_modules（约 30–70 s），无法满足 OPS-AC-003"第二次 ≤ 60 s" | `FORCE=1` 强制重装；判据为锁文件哈希，锁文件变化必然重装 |
| D-12 | 未执行 `git init`，`.pre-commit-config.yaml` 暂不能安装为钩子 | 任务书明确不使用 git | D1-MS1 第一项（AWR-03 §4.5 第 1 条、OPS-FR-007）待允许使用 git 时执行；性能锁在非 git 时落在本仓库 `runs/.perf.lock` |
| D-13 | apps/web 的 tsconfig、vite、vitest、oxlint 配置由本工作包提供 | M15 §9.3 标注为"M00 统一"，且 make lint/test 需要它们才能执行 | M15 可在此基础上提需求；index.html、components.json 与 src 由 M15 提供 |

## 4. 遗留问题与风险

1. **Node 引擎告警**：react-scan 0.5.7（仅 dev）传递依赖 react-doctor 0.9.14、oxlint-plugin-react-doctor、eslint-scope 9.1.2、eslint-visitor-keys 5.0.1，要求 Node ≥ 22.13，本机锁定 22.12.0，npm 报 EBADENGINE 警告但安装成功；只影响 react-scan 附带的 doctor 功能。如 M15 使用 react-scan 时出错，需评估 Node 升到 22.13+（需改 ADR-037 的 `.nvmrc`）。
2. **TECH-FR-008 口径**：react-doctor 还传递安装了 typescript 5.9.3，`npm ls typescript` 会出现 7.0.2 之外的版本；类型检查仍用 7.0.2 的 tsc。lint 工作包实现 `check-deps.mjs` 时应只按直接依赖或加白名单判定。
3. **TECH-FR-003 口径**：cmdk 1.1.1（AWR-11 T09 选定）传递依赖 @radix-ui/react-dialog 等 10 个包；`@radix-ui/*` 禁用规则应按直接依赖执行，否则与 T09 冲突。
4. **BOM 未建**：`tools/ci/bom.json`（TECH-FR-002）与 `tools/lint/*`、`tools/ci/run.sh` 不在本工作包范围；BOM 需登记 D-02、D-03、D-04 新增项，以及 uv、pip、setuptools。
5. **npm 源**：本机 npm registry 为 registry.npmmirror.com，package-lock.json 中 1023 个 `resolved` 地址均指向该镜像；其他主机 `npm ci` 可正常访问，但如需官方源须重新生成锁文件。
6. **体积**：node_modules 911 MB，高于 AWR-19 §7.5 第 3 条的 0.3–0.5 GB 估算（shadcn CLI、@gltf-transform/cli、react-scan、potree-core、Playwright 占比大），worktree 磁盘预算需按此修正。
7. **shadcn add 会装包**：M15 执行 `npx shadcn add` 时 CLI 默认安装组件依赖（含 lucide-react），与"后续 agent 不装依赖"及 TECH-FR-003 冲突，已在请求中说明处置方式。
