## 0. 摘要

1. **日历与太阳**（ADR-102，AWR-04 §6.5）：`calendar{start_utc, tz}`，`t_cal = start_utc + t_sim`；`env/calendar{start_utc, tz, jump = true}` 在 20 ms 网格点生效（jump 时生效时刻即为该日历时刻）；NOAA 太阳位置（Meeus 低精度式，方位改用 atan2 形式），以世界锚点经纬度与真北偏差求网格方位。
2. **照度与照度档**：AWR-04 §6.5 的分段式（日间 h ≥ 6°、低照 −6°–6°、夜间 < −6°），云量乘 `(1 − 0.7·c)`；被动 EO 的 k_light 锚点（E ≈ 50 lx 在 h ≈ −2.55°，k_light 0.5 在 h ≈ −5.37°）由测试复核。
3. **按波长消光**（ADR-101，AWR-04 §6.3 第 4 步）：550 nm 与 D1 逐位相同（σ = ln20/MOR）；850、905 nm 的气溶胶按 Kim 指数缩放，降水与波长无关；LWIR 另加 `σ_wv = (0.03 + 0.012·ρ_v)/km`，ρ_v 由湿度按 Magnus 式求得，随湿度单调。
4. **热背景与声学背景**：地表温度与发射率（4 种地表类别）、8–14 µm 等效天空温度、热交叉 `k_cross`（日出后与日落前 1 h 为 0.5）；声学背景 rural、suburban、urban 的日夜级与晨昏过渡、降水增量、24 个 1/3 倍频程带级（能量和等于总级）。
5. **下发**：SkyModel 启用（设了日历或声学背景）后 EnvKeyframe 带 `config.sun.{mode, illum_lx, band}`、`calendar`、`humidity_pct`、`surface`、`acoustic_bg`；1 Hz【仿真】复核，太阳方向变化 ≥ 0.5° 或照度档变化等即发新版本（×1 下约 766 版/仿真日），照度档变化另发 `env.changed{reason: illum_band}`；未启用时帧逐字节同 D1（D1 关键帧夹具 6 类全部不变）。D2 最坏帧 1585 B（硬上限 2048 B）。
6. **服务端接口**：EnvPerceptionView 全部方法与 `sky_sample`（M19 EnvSample 的超集）、`forecast`、`next_band_change`、`configure_session`、`session_snapshot`；`env/calendar` 命令处理与 `env/set` 的 D2 键；时钟档（sandbox100）下的 tick 长度与全量求值相位。
7. **REST**：`rest/env.py` 改用请求级上下文 `ctx_for`；新增 `sandbox_router`（SB-60 至 SB-63）；show-api 的 D1 REST 面与 OpenAPI 快照不变（共享展示的日历经 WS `call env/calendar`）。
8. **前端**：`engine/environment` 的 sky 纯函数（与 Python 逐式对拍）、EnvStore 的 `sky`（日历时刻、太阳、照度档、服务端湿度、地表与声学背景）、场景太阳方向随日历变化且夜间直射光为 0、summary 的 `sky` 字段（UX-FR-114 的数据）、测试钩子 `__env.injectSky`、`__env.sky`。

## 2. 设计要点与参数（供 M07 PRD D2 增补节并入）

### 2.1 日历

- 内部只保存 `cal0_unix_ms`（t_sim = 0 对应的日历时刻）与 `tz`；`t_cal(t) = cal0 + t`，快进时随仿真时间推进（ADR-045 规则 ①）。
- `env/calendar{start_utc, tz, jump}`：生效时刻 `t_apply = ceil(apply_tick·tick_ns / 20 ms)·20 ms`；`jump = true` 时 `cal0 = start − t_apply`，`false` 时 `cal0 = start`。形状错误 300，取值错误 110（`detail.field` 为 `start_utc` 或 `tz`，`why` 为 NOT_ISO8601、YEAR_OUT_OF_RANGE、INVALID_DATE、INVALID_OFFSET、UNKNOWN_TIME_ZONE）。
- 线上：`calendar.start_utc` 为 cal0（与 AWR-04 §6.5 的定义 `t_cal = start_utc + t_sim` 自洽），`calendar.t_cal_unix_ns` 为该条关键帧 `t_ns` 处的日历时刻（十进制字符串，心跳随 `t_ns` 更新）。
- 会话快照的 `calendar.start_utc` 取导出时刻的日历时刻（恢复后的新会话从该时刻继续）。
- `tz` 只用于界面本地时刻；太阳位置、气温日变化用经度求真太阳时。
- 剧本重置（`env/reset`、时钟回退）不改日历与声学剖面（会话配置属性）。

### 2.2 太阳位置

- NOAA Solar Calculator 的公式（Meeus 低精度式，不含 ΔT），输入 UNIX 毫秒与 WGS84 经纬度；方位用 `atan2(sin H, cos H·sin φ − tan δ·cos φ) + 180°`（与 NOAA 表格的 acos 式等价，天顶附近稳定）。
- 高度为几何高度（不含折射）：照度档、热交叉与声学过渡都按几何高度；`refraction_deg` 只供对拍与显示。
- 世界锚点取 `coordinate.json` 的 `anchor.latDeg/lonDeg`（缺省 synthcity 示意锚点 30°N、120°E），网格方位 `az_grid = az_true − trueNorth.yawOffsetDeg`（16 号文档：偏差为 world +Y 到真北的俯视逆时针角；现有七个世界均为 0）。
- 未设日历时为固定太阳（`config.sun` 的 150°/50°，即 D1 行为）。

### 2.3 照度与照度档

| 太阳高度 h | 晴空照度 |
|---|---|
| h ≥ 10° | `1.2e5·sin h` lx |
| 0° ≤ h < 10° | 由 `1.2e5·sin 10°` 线性降至 400 lx |
| −6° ≤ h < 0° | 对数插值 400 → 3 lx |
| −12° ≤ h < −6° | 对数插值 3 → 0.008 lx |
| −18° ≤ h < −12° | 对数插值 0.008 → 0.001 lx（本文设定，见 §4 第 1 条） |
| h < −18° | 0.001 lx |

另加可选月光（`SkyModel.moon_lx`，满月 0.1 lx，缺省 0，未开放配置接口），总值乘 `(1 − 0.7·c)`（c 为 `cloud.cover`）。照度档编码同 `rt/enums.json` LightBand：day 0（h ≥ 6°）、low 1、night 2（h < −6°）。

### 2.4 LWIR 热背景（本文设定的工程近似，建议登记为模拟参考值 D）

- 日均气温 `T_mean = 15 − 0.0065·h_ground + isa_dt`（与 THERMO 的 ISA 同一基准；THERMO 查询本身不加日变化，D1 物理与 rho 不变）。
- 气温 `T_air = T_mean + A·cos(2π(τ − 15 h)/24 h)`，τ 为真太阳时，`A = 4 K·(1 − 0.6·c)`；固定太阳时 `T_air = T_mean`。
- 地表 `T_b = T_air + K_sol·max(sin h, 0)·(1 − 0.7·c)·(1 − 0.5·wet) − K_night·clamp((6° − h)/12°, 0, 1)·(1 − 0.8·c)`，wet 为锚点湿润度。

| 地表类别 | ε_b | K_sol（K） | K_night（K） |
|---|---|---|---|
| urban（缺省） | 0.93 | 15 | 2.5 |
| vegetation | 0.97 | 6 | 3.5 |
| soil | 0.93 | 12 | 4.0 |
| water | 0.98 | 1 | 0.5 |

- 8–14 µm 等效天空温度 `T_sky = (1 − c)·(T_air − (40 − 20·rh) K) + c·(T_air − 0.0065·base_m)`。
- 热交叉：几何高度 h(t) ≥ −0.833° 且 h(t − 1 h) < −0.833° 或 h(t + 1 h) < −0.833° 时 `k_cross = 0.5`，其余 1；固定太阳时恒 1。
- 地表类别取世界 `env.json` 的 `surface.class`（现有世界未写，缺省 urban），可由会话配置 `surface_class` 或 `env/set{patch: {surface: {class}}}` 设置。

### 2.5 声学背景

- 日夜总级（dB(A)）：rural 40/30、suburban 50/40、urban 60/50；`L = L_night + (L_day − L_night)·clamp((h + 6°)/12°, 0, 1)`；降水 `(5 + 5·rain_k)·min(1, R_eff/0.5)` dB（R_eff ≥ 0.5 mm/h 时 +5 至 +10 dB，`rain_k = ln(1 + R)/ln 51`；0–0.5 mm/h 线性起步避免阶跃）。
- 24 个 1/3 倍频程带（50 Hz–10 kHz，与 M18 声源带表相同）；每个剖面一条 A 计权相对谱（urban 取 EN 1793-3 归一化道路交通噪声谱并外推到 50–80 Hz 与 6.3–10 kHz；rural 为风与植被为主的宽平谱；suburban 介于二者之间），按能量和归一化为 0 dB，带级 `L_b = L + rel_b`，能量和恰为 L。A 计权按 IEC 61672-1 解析式。
- 缺省剖面 rural（M18-M19 PRD §6.11 的回退口径；AWR-04 §7.3 锚点的 `L_bg = 30 dB(A)` 即乡村夜间）。

### 2.6 按波长消光

- 地面点消光 `σ_λ = σ_bg·(λ/550)^−q + σ_precip`，q 按 Kim 由 `V2 = ln50/σ_bg`（km）给出（M07 既有口径）；λ ≥ 8 µm 另加 `σ_wv = (0.03 + 0.012·ρ_v)/km`。
- 路径光学厚度：气溶胶（指数霾的 Quilez 闭式积分 + 雾层）乘 Kim 比，降水层不缩放，LWIR 水汽沿程均匀；550 nm 走 D1 `optical_depth_arr`（逐位相同）。
- `ρ_v = 216.7·rh·e_s(T_mean)/(T_mean + 273.15)`，`e_s = 6.112·exp(17.62·T/(243.12 + T))` hPa；取日均气温（不随日变化），使水汽项只随湿度变化（D2-AC-15"随湿度单调"）。rh 为 `atmosphere.rh` 标量（用户轴），线上 `humidity_pct = 100·rh`。

### 2.7 关键帧下发

- SkyModel 启用条件：设了日历（命令或会话配置）、声学剖面或地表类别；启用前关键帧不含任何 D2 字段（D1 逐字节不变）。
- 新版本时机：日历、D2 补丁操作在网格点生效；其他操作（预设、`env/set`、阵风、重置）生成的新版本一律在发出前写入该时刻的 D2 字段；1 Hz【仿真】复核相对上次下发：太阳方向变化 ≥ 0.5°、照度档或太阳模式变化、照度对数变化 ≥ 0.1、热交叉或发射率变化、地表温度 ≥ 0.5 K、背景级 ≥ 0.5 dB 或剖面变化、湿度 ≥ 1% 时以 `touch` 发新版本（只改 `config.sun` 与 D2 字段，过渡与锋面不变）。
- 照度档变化另发 `env.changed{version, by: "calendar", reason: "illum_band", band}`；日历操作 `reason: "calendar"`，D2 补丁 `reason: "d2"`。
- 数值规整：方位与高度 0.001°、照度 4 位有效数字、温度与背景级 0.01，便于跨平台逐字节比较。
- 版本量：synthcity 10 月 5 日 ×1 一个仿真日 766 版（约 0.5 版/分钟），照度档事件 4 次。

### 2.9 时钟档（ADR-090）

- `tick_ns_of(ctx)`：`ctx.dt_tick` → `ctx.clock.tick_ns` → 4 ms；服务的 `tick_ns` 每次 `ensure_service` 刷新。
- 全量求值相位：`k = tick·tick_ns // 20 ms`，`k % 10 ∈ {1, 7}`。d1_250（tick = 5k）下与原 `tick % 50 ∈ {5, 35}` 逐 tick 相同；sandbox100（tick = 2k）下为同一组仿真时刻，10 Hz。env stage 的 `(every, phase)` 由 M08 的按档调度表给出（d1_250 5/0、sandbox100 2/0），注册代码未改。
- `DT_ENV_S = 0.02` 与 20 ms 锚点网格在两档相同。

### 2.11 前端

- `SkyEval.update(wire, tRender, cover, geo)`：关键帧不带 D2 字段时只在换帧时设置一次（无逐帧开销，D1 的零分配用例不变）；clock 模式且已知世界锚点时在 tRender 处按 NOAA 求太阳（`source = noaa`），否则用关键帧方位高度（`source = keyframe`）；照度与照度档用与服务端同一函数。

## 4. 偏差与裁决

1. **照度 −18°–−12° 段**：AWR-04 §6.5 写"更低（−12° 以下）为 0.001 lx"，在 −12° 处会由 0.008 跳到 0.001 lx；实现以对数插值衔接（−18° 处到 0.001 lx），保证连续单调；对感知无影响（该段 k_light 恒 0）。已报文档总编。
2. **被动 EO 的 k_light 锚点**：AWR-04 §6.5 的"h ≈ −5.4° 时降到 0.5"对应彩色曲线（E_min 0.5 lx）；按 `auto` 模式取彩色与黑白两曲线较大值时，0.5 出现在 h ≈ −7.8°。测试按彩色曲线复核；判据归 M19。
3. **日历线上语义**：17 §17.6.9 未定义 `start_utc` 在 jump 后的含义与 `t_cal_unix_ns` 的参考时刻，实现取"start_utc = t_sim 为 0 的日历时刻、t_cal_unix_ns 为该帧 t_ns 处"（§2.1），与 AWR-04 §6.5 的定义自洽，已报文档总编。
4. **热背景与声学参考谱**：基线只规定"由 M07 按地表类别与日历给出""谱形取对应环境的参考谱"，参数为本文设定（§2.4、§2.5）。
5. **Kim 指数的能见度口径**：沿用 M07 既有 `V2 = ln50/σ_bg`；WP-01 桩以 MOR 代入，二者在 MOR 1–6 km 的近红外略有差别，已请 M19 用 M07 函数生成可行窗口黄金表（`d2-WP-09-to-M19.md`）。
6. **路径**：`apps/web/src/stores/env.ts` 与 `apps/web/src/viewport/layers/environment.tsx` 在 AWR-03 §4.3 归 M07，但 AWR-04 §14.2 的 WP-09 行未列，本工作包未改动；`sky` summary 在运行期已写入 store，类型声明与世界锚点接线的两处一行改动写入请求（`d2-WP-09-to-文档总编.md`、`d2-WP-09-to-M15.md`）。未接世界锚点时前端太阳取关键帧值（每 ≥ 0.5° 一版）。Playwright 用例 `perf/m07/env-sky.spec.ts` 按 AWR-03 §4.3 M16 行"各模块在 perf/m<nn>/ 下提交自己的 spec"新增并在 `perf/m07/cases.mjs` 登记，已请文档总编确认 D2 下模块子目录的归属。
