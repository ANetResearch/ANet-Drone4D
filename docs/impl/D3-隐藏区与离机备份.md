## 1. 隐藏制品的范围（K07 修订）

test 事件的下列制品只存于 `hidden/<eid>/event/v<N>/`，保持事件编译目录的相对路径：

- 磁带与真值：`tape.bin`、`tape.json`、`truth.mcap`、`observability.npz`，以及编译器写出的 `truth/r<k>/event_truth.json`、`truth/r<k>/event_graph.json`；
- 路线、锚点与编译报告：`plan.json`（含演员路线）、`anchors.json`（目标搜索类含实际抽样位置）、`compile_report.json`；
- 事件源：`event.yaml`、`event.json`、`anchors.overlay.json`。

事件编译目录 `events/<eid>/v<N>/` 对 test 事件只允许留存 `brief.json`（对研究者开放的简报）与发布、停用标记 `published.json`、`deprecated.json`。其余文件，包括子目录中的文件，一律视为隐藏制品：

- `misplaced` 递归列出这些文件；
- `seal_event` 按相对路径把它们移入 hidden，并删除移空的子目录。

事件先以 dev 发布、之后才登记为 test 时，同样按此处理。

Run 真值存于 `hidden/<eid>/truth/run_<id>.{mcap,frames.idx}`，规则不变。

## 2. 属主与权限

| 对象 | 属主 | 权限 | 说明 |
|---|---|---|---|
| `hidden/` 及其下全部目录 | `10002:10002` | 0700 | Evaluator 服务用户（数值 uid/gid 10002，容器内用户名 `d3-eval`；宿主不建登录账号） |
| `hidden/` 下全部文件 | `10002:10002` | 0600 | 不允许符号链接与其他文件类型（`perms` 报告，`--fix` 不处理链接） |
| `bench/splits.json` | 管理员 | 0600 | 划分登记，变更写审计 `split_change` |
| `audit/access-<UTC 日期>.jsonl` | 写审计的进程 | 0600 | Evaluator 以 10002 运行时须可追加写；部署 B21 时按运行用户确定属主 |

- uid 10001 是内部工作区（lab）的服务用户，bench-api、lab-web 与 subworker 以它运行。Evaluator 与 lab 分用不同 uid：lab 容器即使误挂载隐藏区，也无权读取。lab 容器不挂载隐藏区。
- 读取 test 制品一律经 `HiddenStore`，并写 `truth_read` 审计：
  - 正式评测作业以 `--user 10002:10002` 运行，挂载隐藏区；
  - bench-api 中评测员读取 test 事件详情（BN-22）与制品（BN-27）时，从隐藏区组装；
  - 外部主体返回 691。
- 核对与整理（以 root 运行；`--fix` 写审计 `hidden_perms`）：

  ```bash
  python -m awr.bench.split --data-root /data/d3 misplaced                    # 编译目录与数据集中残留的 test 制品，须为空
  python -m awr.bench.split --data-root /data/d3 perms --uid 10002 --gid 10002          # 只核对
  python -m awr.bench.split --data-root /data/d3 perms --uid 10002 --gid 10002 --fix    # 整理模式与属主
  ```

## 3. 离机加密备份方案（未执行外传）

test 事件的源文件目前只有隐藏区这一份，`configs/events.d3/` 中只有 dev 事件的源。隐藏区一旦损坏，test 集无法按同一承诺值重建：`split.yaml` 的哈希是 v1 承诺。因此需要离机备份，要求如下。

| 项 | 方案 |
|---|---|
| 备份内容 | `hidden/`（含 test 事件源、磁带、真值与 Run 真值）、`bench/splits.json`、`configs/bench.d3/split.yaml` 的对应版本，以及一份清单 `MANIFEST.sha256`（逐文件 sha256 与字节数） |
| 打包 | 在 dmax 上以 root 执行 `tar --numeric-owner --sort=name --mtime=@0 -C <数据根> -cf - hidden bench/splits.json \| zstd -19`，保留数值属主，不跟随符号链接 |
| 加密 | 使用 `age`（X25519）加密到两个收件人公钥：用户持有一个，离线管理员持有一个。私钥不放在 dmax 与任何部署主机上。dmax 只保存公钥文件 `recipients.txt`，它不是密钥，可以入库 |
| 存放 | 由用户指定的私有存储，例如私有对象存储桶或离线介质。不得进入 git、ModelScope、emax 或任何公开渠道；文件名不含事件 id 与内容摘要 |
| 频率 | 每次 test 集变更（`test_split_version` 升级、新增或重编 test 事件）后立即备份一次，平时每周一次；保留最近 3 份与每个 `test_split_version` 的最后一份 |
| 完整性 | 加密前生成 `MANIFEST.sha256`；上传后回读密文，比对其 sha256，结果写入备份记录（UTC 时间、份数、字节数、密文 sha256；不记录内容） |
| 恢复演练 | 每季度一次，在 dmax 临时目录（0700）中执行：解密，按 `MANIFEST.sha256` 逐文件校验，再运行 `misplaced` 与 `perms` 核对。演练记录写入阶段报告，临时目录随即删除 |
| 审计 | 打包与恢复都写入审计日志（`hidden_backup`、`hidden_restore`），只记录份数与摘要，不记录文件内容与路径以外的信息 |

执行前需用户确认三项：存放位置、两个收件人公钥、执行人。确认之前不外传任何数据。
