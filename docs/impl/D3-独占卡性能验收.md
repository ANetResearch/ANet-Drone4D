## 3. D3-AC-34 Realistic 档锁步的性能条款

### 3.1 测量

- 工具：`tools/bench/d3/gz_lockstep.py run --repeats 3 --m25-runs 1`（P03 交付）：3 架 x500（`p600_bench` 质量与惯量映射）由 BenchEnv 驱动 360 s，物理档为每 Run 新起的 gz `physics` 兄弟容器（`d3-gz:dev`，`--cpus 2 --memory 2g`，不挂 GPU，无网络），资源由宿主 cgroup v2 每 1 s 采样。
- 口径：ADR-195 决策 (6) 规定 gz `physics` 实例的 RTF 与资源在 CPU 池测量，前置条件为 `d3.slice` 内无其他 D3 批作业。`physics` 类运行（L1，无 M25 负载）不使用 GPU，其 RTF 与启动时长与 GPU 独占级别无关；`m25` 类运行（L2 + M25 会话）使用 GPU 2，只用于"有无 M25 负载时物理轨迹逐位一致"等非性能条款。两组 `physics` 运行期间 dmax 上除常驻服务容器（registry、lab 等）外无其他 D3 批作业容器，`/data/anet-drone4d-d3/d3dev` 下除本任务外无目录变动，宿主 loadavg 5.9–11.8（64 线程）。
- 两组运行：
  - 第 1 组（`out/gz`，18:56–19:25）：guard 持主机排他锁，窗口前 600 s 外部进程只驻留（B 级候选），窗口内外部推理服务恢复计算（536 个活动采样），guard 判 invalid。`physics` × 3 不受影响；`m25` × 1 的 GPU 部分为共享卡。
  - 第 2 组（`out/gzcpu`，19:27–19:38）：只跑 `physics` × 3，宿主容器不挂 GPU，工具在容器内持主机排他锁，按 ADR-195 (6) 的 CPU 池口径复测。
- 工具输出的 `gpu_label` 两组均为 `shared`（第 1 组按 GPU 2 快照，第 2 组未指定卡），性能条款因此标为 `*_shared_not_counted`；按 ADR-195 (6)，本文以 CPU 池前置条件判定 `physics` 运行的计入资格。

- GPU 时间（ADR-213 决策 (3)，GPU·s/仿真 s，标准轨 x1）：渲染与效果链 0.037、热成像 0.029、nvJPEG 0.144、Warp LiDAR 0.751，合计 0.960；读回单列 0.017。nvJPEG 与 LiDAR 两项为墙钟上界（编码区间与 `scan_batch` 调用的墙钟，含 CPU 侧压缩与回传），不是 GPU 计时，合计因此高于 §4.7 最坏档准入预算 0.85；以 CUDA 事件计时替换上界列为后续事项（§8 第 1 项）。
- 容量单位 C（ADR-213 决策 (4)，独占 A40、crop 世界、完整效果链、全输出，Worker 渲染进程组，最坏档持续帧率，3 次中位）：`rgb720-gs` 234.1、`rgb1080-rs` 157.2、`therm512` 518.2 帧/s（K03 单进程为 61.1、53.5、114.3）。

## 7. 复现

dmax 驱动脚本 `/data/anet-drone4d-d3/d3dev/s21/run_s21.sh`（宿主机 root 运行），阶段如下：

| 阶段 | 内容 |
|---|---|
| `mon` | 宿主机全程 pmon 与计算进程采样 |

| `cam` | guard 包装四组 `camera_throughput.py run --repeats 3 --load-max 32`：`therm512` sustained 600 s；`rgb1080-rs` online `--runs 1,3 --online-sim-s 360`（完整标准轨）；`rgb720-gs` online `--runs 1`；`rgb720-gs,rgb1080-rs` × `clear,worst` sustained 600 s |

| `write-retry`、`lidar-retry` | 在 `DEADLINE` 前反复等待空闲卡并执行对应阶段，直到 guard 不判 invalid |

K04 起，D3-AC-34 的 CPU 池性能条款以仓库脚本 `tools/deploy/dmax/run_gz_perf.sh <输出名> [startup] [gzcpu]` 复现（本机仓库根目录执行）：同步代码快照到 dmax `$D/perf/<输出名>/src`，依次执行 `startup`（`gz_lockstep.py startup --n ${N:-40}`）与 `gzcpu`（`--kinds physics --repeats 3`），两者同一输出目录，汇总并入冷启动样本；容器名前缀 `d3-gzperf-`，结束后删除。
