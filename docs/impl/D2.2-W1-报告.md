## 0. 结论

1. **缺陷已在本机复现并确认根因**：共享展示的实体全部属于 S7 的运行世界 synthcity（每条实时连接的 `serverInfo.world.id = synthcity`），但前端只有机群图层和机群面板用到了这一信息；目标物、感知体与场视图采样、任务与机巢、传感器缓存、机群行、任务线、时间轴标记、环境关键帧、告警与事件日志等数据层在切换世界时既不清空也不按世界过滤，图层每帧按这些模型绘制，于是 synthcity 的目标物盒与感知体轮廓、声学场壳与采样点、图例、运行号和时间轴标记被原样画在深圳、苏州、纽约等城市中。`?sel=` 深链接在切换世界时也不校验世界。
2. **修复在数据层完成**：新增“世界作用域”（`stores/worldScope.ts`）。每份世界绑定的客户端状态都属于（实时数据源，世界）这一对：只有数据源模拟的世界等于视图打开的世界时才摄入（`worldLive()` 闸门，在 store 与引擎模型的每条消息、每帧入口检查），这一对变化时统一重置（`onWorldReset`）。节能断开、观看排队、沙盒停泊仍保留同一世界的最后已知状态（设计 §15.7.7 不变）。
3. **验证**：新增单元用例 13 个、Playwright 用例 2 个（公开演示构建与测试构建，S7 实景栈，WebGL2 规范最小上限模拟下 WebGL 错误、three 警告与页面错误均为 0），全部通过；全量 Vitest unit（1393）、相关 browser 用例、`make lint`、`make test-contracts`（pytest 434、vitest 281）、`tsc` 通过；回归 `perf/m15/tasks-d2.spec.ts`（6）、`perf/d2/integration-live.spec.ts` 底图切换（沙盒在七个世界间切换）、`perf/d2/demo-live.spec.ts`（2）通过。

## 2. 根因

### 2.1 共享展示的实体属于哪个世界，前端是否知道

共享展示（show-api 加 sim-core）只运行一个世界：公开 profile 的 `run.world = synthcity`。其全部实体（机队、识别物、感知体、任务、机巢、视锥所依附的机体与传感器）都属于 synthcity。服务端已经标识世界：每条 WS 连接的 `serverInfo.world.id`、REST `GET /api/worlds` 的 `in_use`。前端在 `connView.sessionWorldId` 中保存了它，但只有三处使用：`viewport/layers/drones.tsx`（世界不一致时退订仿真频道、隐藏机群图层，即 M06-FR-030 静态浏览）、`ui/panels/drones/DronesPanel.tsx` 与 `ui/panels/world/WorldPanel.tsx`（“此世界当前没有仿真运行”提示）。其余数据层不知道“当前实时流的世界”和“当前打开的世界”是否一致。

## 3. 修复设计

### 3.1 世界作用域（`apps/web/src/stores/worldScope.ts`）

| 字段 | 含义 | 来源 |
|---|---|---|
| `world` | 视图显示的世界：视口打开的世界（`stores/world`），视口打开之前和没有视口时（UI-only 测试构建）取界面的世界（路由世界或沙盒会话世界） | `app/shell/worldScope.ts` |
| `source` | 实时数据源：`shared`、`local`、`sandbox:<sid>`；静态浏览与不可用的沙盒为 `null`。与链路是否打开无关：节能、观看排队、沙盒停泊不改变它 | 同上，由运行期界面推出 |
| `streamWorld` | 当前数据源连接的 `serverInfo.world.id`；节能断开时保留，数据源变化时清空 | `ui/shell/RtContext.tsx` |
| `live` | 数据源、世界、流世界都已知且流世界等于视图世界：允许摄入 | 推导 |
| `foreign` | 没有数据源，或数据源模拟的是另一世界：仿真频道不订阅（静态浏览） | 推导 |
| `epoch` | 每次重置加 1；异步 REST 应答以此判断是否过期 | 推导 |

重置时机：视图世界变化、数据源变化（共享、静态、沙盒之间，含同一世界从共享展示进入沙盒）、已知的流世界变为另一世界（沙盒切底图）。不重置：同一数据源的链路关闭与重连（节能、观看排队、断线重连、沙盒停泊与恢复）、首次收到 `serverInfo`、启动时的首次绑定。外壳尚未绑定时（只测单个 store 的单元测试）闸门打开，与修复前行为一致。

### 3.3 界面与 URL

1. **`sel` 深链接按世界绑定**（`ui/shell/urlSync.ts` `requestSelection`，由 `App.tsx` 在每次世界变化时调用）：作用域对该世界 live 且名册到达后才选中，名册中没有的 id 丢弃并提示数量（原有 `url.selMissing`）；该世界是静态浏览或数据源模拟另一世界时，深链接作废并从 URL 中删除 `sel`；视口仍显示上一世界时等待，之后的世界变化替换它。原先首次加载时的一次性名册校验并入此处。
2. **场视图图例**：作用域 `foreign` 时不显示（图例读的是实时数据源世界的场，静态浏览没有）。工具栏的视图选择是偏好，保留。
3. **面包屑运行号**：作用域 `foreign` 时显示“无运行”，不再把另一世界的运行号挂在当前世界之后。
4. 未改的界面：静态浏览时页头时钟仍显示共享展示的仿真时间（STALE）与“已断开”徽标，时间轴为共享展示运行的时间轴（标记已清空），见第 6 节第 3 条。

### 3.4 新增测试钩子（只在测试构建）

`window.__vp.isolation()`：作用域、各图层当前绘制数、姿态数、视锥数、名册大小、识别物行数与感知体数、场视图剖面与感知体与锚点、任务线统计与任务 store 计数、标签数、GoTo 标记、相机模式与焦点。`window.__vp.governorHold(on)`：让 PerfGovernor 回到全部 0 级并保持（`PerfGovernor.hold`，生产构建不暴露），否则 SwiftShader 下点云预算长期在下限，调速器会关掉被测的视锥等图层。

## 6. 偏差与遗留

1. **端口偏移**：`net.port_offset` 的取值范围是 0 至 31，实际端口偏移为其 10 倍。本任务按“偏移 300”使用 `AWR_PORT_OFFSET=30`（预览端口 4530 至 4533）；`sbstack.py` 的 show-api、sandbox-api 与总线端口由其自选空闲端口，不与他人冲突。启动的栈与预览进程在每次运行结束时已全部停止。
2. **V1 机型没有视锥（既有缺陷，未在本任务修改）**：S7 名册中 AWR-V1 的 `model` 为 `awr-v1`，而传感器规格表 `engine/sensors/specs.gen.ts` 的键为 `awr_v1`，`SensorCache.specsFor` 按原样查表，因此 V1 机体在视口中没有传感器视图、视锥、FPV 与传感器视图（P600 的 `model = p600` 正常）。机体外形模块已有 `modelKey` 归一化，传感器缓存缺少同样的归一化。建议由 M13 在 `specsFor` 中按 `modelKey` 规则查表并补单元用例。本任务的回归用例因此选用 P600（即用户示例中的 `p600-03`）。
3. **静态浏览的运行层显示未改**：静态城市的页头仍显示共享展示的仿真时钟（STALE）与“已断开”徽标，时间轴仍是共享展示运行的时间轴（标记已清空，不再有实体）。它们属于运行层而非世界绑定实体，且是 WP-12 的既有静态浏览设计；下一任务为各城市接入展示内容后，城市页面将有自己的数据源与时钟，此问题随之消失。
4. **本地构建的在途消息**：在 `local` 界面切到其他城市时，机群图层退订仿真频道与作用域重置在同一次提交中完成，但退订生效前（不超过 250 ms 加往返时延）在途的名册或机群帧仍可能写入 `RtClient` 的名册与快照；所有 store 与引擎模型都经闸门，不会摄入，面板以闸门后的 store 为准。演示构建的静态浏览没有链路，不存在此情况。
5. **调速器与视锥**：SwiftShader 下点云预算长期处于下限，PerfGovernor 会逐级关掉视锥等图层。演示构建没有测试钩子，用例在调速器已到第 2 级时记录注释并依赖测试构建用例的数据层断言；本次运行中演示构建的视锥在 synthcity 已绘制，未触发该分支。
6. 并行任务 L1 修改了 `landing.*` 文案，曾使 `tests/m15/demo.test.ts` 一度失败；最后一次全量 unit 已通过，与本任务无关。
7. 用户原话后半句“在其他的地图中也加入模拟的无人机监测任务和对应的目标物”不在本任务范围，接口说明见第 7 节。

## 7. 下一任务接口说明：各城市共享展示的接入

本节给出城市演示任务接入共享展示内容时必须遵守的接口；隔离由世界作用域保证，接入方只需正确声明世界与数据源。

### 7.1 世界标识（必须）

1. 每个展示数据源的每条连接都必须在 `serverInfo.world.id` 中给出它模拟的世界 id（七个世界之一），并在 `serverInfo.run.id` 中给出运行号；录制回放时为录制中原样保存的 `serverInfo`。前端只在 `streamWorld === 视图世界` 时摄入，任何不一致的数据都不会显示，不需要接入方额外过滤。
2. 剧本的 `world_id`（`awr.sandbox.snapshot.v1`）必须等于该城市 id，坐标为该城市世界包的 ENU；识别物、机巢、任务几何不得复用 synthcity 的坐标。
3. 一个数据源只服务一个世界；同一世界有多个数据源（例如共享展示与访客沙盒）时，它们是不同的 `source`，切换时客户端状态按数据源重置，实体 id 相同也不会混用。

### 7.2 数据来源（建议）

emax 为 4 核且与 ANet 生产服务共用，不宜为六城各常驻一个 sim-core。建议两种方式按城市选择，接口相同：

| 方式 | 内容 | 服务端成本 | 适用 |
|---|---|---|---|
| A 录制回放（推荐） | 在开发机以 `AWR_RT_CAPTURE=<dir>`（`python/awr/api/rt/awrrt.py`）对每个城市剧本运行一次共享展示并采集一条观看者连接，得到 `.awrrt`；部署为静态文件，例如 `/worlds/<id>/show/show.awrrt`（与世界包同目录，经部署包上传，不入 git）；浏览器内由 `RtClient` 的 in-process 回放（`FakeSource` 的 fixture 模式，`loop=1` 循环，`perf/m15/tasks-d2.spec.ts` 已使用同一路径）播放 | 0（nginx 静态文件） | 六城的只读展示 |
| B 实时运行 | 独立的 show-api 与 sim-core 运行该城市剧本，经单独的实时路径提供 | 每城约 1 个 sim-core | 需要实时交互或高保真的城市（不建议在 emax 上常驻） |

录制时需要订阅齐全：`fleet/roster`、`swarm/state`、`env/state`、`event`、`swarm/target/state`、`target/*/detail`、`nest/*/status`、`task/*/status`、`relay/*/stats`、`field/*` 与 `field/volumes`（场视图需要时）、选中机的 `uav/<id>/state`、`uav/<id>/perception`、`uav/<id>/sensor/<name>/pose`；回放不响应客户端的新订阅，按兴趣生成的主题（读数卡 `target/<id>/quant`、随选择变化的机体主题）只对录制时订阅过的对象可用，界面应以“录制内容”的只读语义呈现。循环回放的接缝处 TIME 纪元变化，已有的纪元处理会清空轨迹与插值。

### 7.3 展示清单（契约增补，只增不改）

建议在 `GET /api/worlds` 的列表项增加可选字段 `show`（不改已有字段，缺省表示该世界只有静态浏览），由部署配置生成：

```json
{ "id": "shenzhen", "show": { "kind": "replay", "url": "/worlds/shenzhen/show/show.awrrt", "scenario_id": "d22-shenzhen-watch", "run_id": "r20261014-000000-0001", "loop": true } }
{ "id": "synthcity", "show": { "kind": "live", "rt_path": "/api/rt", "scenario_id": "s7-synthcity-relay" } }
```

同步 `packages/contracts` 的 REST schema 与生成物并通过 `make test-contracts`；前端在 `demoWorlds` 读取世界列表时一并取得 `show`。公开站 `nginx` 对 `/worlds/<id>/show/` 只需静态文件规则。

### 7.4 前端按世界切换内容（接入点）

1. **运行期界面**（`app/shell/surface.ts` `resolveSurface`）：演示构建中 `/world/:id` 的世界若有 `show`，界面为 `shared`，`rtPath` 取该世界的数据源（`live` 为 `rt_path`，`replay` 为回放 URL）；没有 `show` 的世界仍为 `static`。现在的规则“路由世界等于共享展示世界才为 shared”改为“路由世界有展示数据源才为 shared”。
2. **数据源键**：`app/shell/worldScope.ts` `sourceKeyOf` 与 `ui/shell/RtContext.tsx` `endpointKeyOf` 都要把世界纳入键，例如 `show:<world>`，使两个有展示的城市之间切换时重连并重置；目前两者对共享展示都只用 `shared`。
3. **连接**：`RtContext.connectFor` 对 `replay` 数据源以回放 URL 初始化客户端（`resolveRtUrl` 增加不依赖 `?source=fake` 测试开关的回放 URL 形式，例如 `replay:/worlds/<id>/show/show.awrrt?loop=1`）；`live` 数据源与现在相同。观看者席位、节能与排队只适用于 `live`。
4. **世界作用域**：无需改动。视图世界变化或数据源变化即重置，`serverInfo` 到达后对该城市 live，各 store 与图层按本报告第 3 节的闸门自动只显示该城市的实体。
5. **`setShowWorld`**：现在只记录一个共享展示世界；改为由展示清单决定每个世界是否有展示后，可以保留它作为 `live` 展示世界的来源。
6. **界面文案**：静态浏览提示与“此世界当前没有仿真运行”只在没有 `show` 的世界出现；回放展示可在状态条注明“录制展示”（新增 i18n 键按任务前缀增加，中英文同步）。
