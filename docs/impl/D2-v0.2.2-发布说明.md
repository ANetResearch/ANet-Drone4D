## 1. GitHub release notes

### v0.2.2

Patch release of V0.2 (Interactive Sandbox). It contains the copy review of the release surface and the fixes released in v0.2.1. Server requirements are unchanged: Linux x86_64 with 4 CPU cores and no GPU.

#### Added

- The README states the runtime prerequisites of each capability and a requirements table: the Interactive Sandbox (V0.2) needs no server GPU; sensor generation in the Event Lab (V0.3, in development) requires an NVIDIA GPU with driver 535 or later.

#### Changed

- README and README.zh-CN follow one structure: capabilities with delivery and runtime prerequisites, requirements, quick start, documentation, license and attribution, and citation. Performance and scale figures state their hardware and measurement method.
- The product name is written as ANet Drone4D in the README, CITATION.cff, the about dialog and the landing page; the repository identifier remains in URLs only.
- Interface strings name the 3D view "三维场景视图" (Scene View): the "在三维场景视图中打开" button on the jobs page and the narrow-window hint.
- The English title of the public demo uses sentence case ("ANet Drone4D public demo").
- The landing page states that the Event Lab's sensor generation requires a server GPU.
- CITATION.cff and the BibTeX entries carry version 0.2.2.

#### Fixed

Released in v0.2.1:

- The Python SDK's queue long polls use their own read timeout (#14).
- Session usage reports nests and active tasks (#7).
- The application chunk is retried on a failed load, with a reload offered when it still fails (#9).
- The add-vehicle dialog disables nests that are full or incompatible (#8).
- HOLD and signal-delay states are judged by each vehicle's own sample interval, which removes false STALE reports (#6).

#### Known limitations

- The known issues listed in the v0.2.0 release notes still apply; see docs/impl/D2-验收报告-第2轮.md.
- The banner image (`docs/media/drone4d-banner.jpg`) still shows the repository identifier `ANet-Drone4D` as artwork.
