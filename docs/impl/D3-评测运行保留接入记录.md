## 1 代码改动

### 1.1 逐帧摘要（`retention.frames_digest`）

- **LiDAR 规范化**：`lidar_frame.v2` 帧头的 `frame_id` 为 `<run_id>/<uav>/<sensor>/<seq>`，同一帧流的两次重复存档字节不同。摘要对 LiDAR 载荷以 `recorder.lidar.canonical_lidar_frame` 去掉 `frame_id` 的运行前缀后求哈希（`<uav>/<sensor>/<seq>`），点数组与其他帧头字段原样参与。录制契约 `lidar_frame.v2` 与 Agent 收到的帧不变（Agent 收到的帧本来就不含 run_id）。摘要版本保持 `drone4d.bench.frames_digest.v1`：这是对 v1 文档约定"不含 run_id，同一帧流的两个 Run 摘要逐字节相同"的实现修正，不改变语义。
- **单遍读取**：新增 `FrameStore.scan_frames`，按 `(chunk_offset, msg_offset)` 顺序遍历索引，每个块只解压一次；`Frame.sha256` 改为缓存属性。此前按通道分页读取，同一块被重复解压约 5 次。
- **摘要缓存**：`cached_frames_digest(run_dir, digest_dir)` 以运行目录路径与 `raw.mcap`、`frames.idx` 的大小与修改时刻为戳缓存摘要，干跑与执行共用，执行时不再重读 `raw.mcap`；`finalize_board(..., jobs=N)` 以进程池并发预计算摘要。

### 1.2 精简与去重（`retention.compact_ranked`、`finalize_ranked_eval`）

- 去重 Run 只省去 `frames.digest` 与 `preview/`，**保留 `truth_min`**（`truth/{contacts.jsonl, fleet.npz, l1.jsonl|l2.jsonl, run_seed.json}`），使每个 Run 都能离线复评（K16 的重评按 Run 读取运行真值）。M27-FR-171 原文"去重 Run 只登记 `dup_of`"与此不同，见 doc_notes。
- 运行真值在隐藏区（B21 的 `seal-truth` 布局 `hidden/<事件>/truth/runs/<run_id>/`）时，精简同时删除隐藏区中非最小集文件（`run_<id>.mcap`），`truth_min.json` 以 `store: hidden` 登记，只记字节不记 sha256。
- 保留文件补充 `termination.json` 与 `evaluation.<后缀>.json`（重评版本的评测结果）。
- `finalize_ranked_eval` 可重入：已抽样的组沿用原抽样，已精简的组不再重新抽样，被引用（pinned）的 Run 不进入抽样；逐 Run 登记阶段（`sampled`、`compacted`、`planned`、`pinned`、`missing`、`error`）与精简前后字节；删除失败记入 `errors`，不中断其余 Run。干跑不写入运行目录与审计。
- 运行目录不在数据根下（`mbl_e2e` 的 `<out>/runs/<key>`）时，登记到 `<数据根>/bench/retention_runs.txt`，`retention_gc` 一并扫描，30 天到期精简对这些 Run 同样生效。
- 新增 `finalize_board(root, board_dir, ...)`：按榜单行解析运行目录（行内 `run_dir`、数据集布局、`runs_roots`、`mbl_round` 输出目录、遗留提交 `<submission_id>-r<seed>`），以"提交（或基线条目）× 测试事件"分组调用 `finalize_ranked_eval`。基线条目在不同分轨下同名（B21 的 `baseline/track_share` 同时在 std3-l1 与 std3-l2），分组键为 `<榜单版本>:<分轨>:<条目>`。`exclude` 所列 run_id 不处理，登记为 `excluded`。命令行：`python -m awr.bench.retention --data-root R finalize --board V [--runs-root D] [--entry E] [--skip-run RUN_ID] [--dry-run] [--digest-dir D] [--jobs N] [--out F]`，存在未解析行或删除错误时退出码为 1。
- 精简前后字节（`bytes_before`、`bytes_after`）计入隐藏区运行真值。
- 运行收尾：`clean_run_sockets(run_dir)` 删除运行目录下的 Unix 套接字（gz 控制套接字 `phys/sock/ctl.sock`）并删除空的 `sock` 目录。

### 1.4 提交运行清单、租约与孤立提交恢复（`subworker`）

- 提交运行写出 `run_manifest.json`（`timing`、`attempt`、`restart_count`、`seed_commit`、`experiment_id = board-<榜单版本>`、`split = test`），排名运行没有 `seed_commit` 时不写；遗留榜单经 board 配置 `evalstore` 取 `k_eval` 计算 HMAC 种子承诺。
- 私有结果重采样随机源改为 `aggregate.rng_scope(cfg)`（K16 遗留 2）。
- 租约：处理提交时对 `submissions/<sid>/worker.lock` 加非阻塞文件锁，心跳线程每 60 s 写 `lease.json`（`drone4d.bench.subworker_lease.v1`，有效期 600 s）。
- 孤立提交：状态为 EVALUATING、租约过期（无租约时以 `_meta.updated_unix_ns + 600 s` 计）、文件锁可得、榜单未冻结。`process_one` 处理新提交前先恢复孤立提交：已计费且有输出的运行复用评测结果或由 `termination.json` 重建墙钟超限行；已计费但无输出的运行判 FAILED（320，`orphan_unresolved`）；其余运行删除后重跑；恢复记录写入 `_meta.recovered[]`。语义与 `board_v1_formal.resume_submission` 一致。SCORING 状态的孤立提交只记录日志（§5 第 3 项）。

### 3.1 干跑发现的两处缺陷

首次干跑（05:25–07:22 UTC，摘要计算 1 h 57 min）发现两处缺陷，修正后以缓存的摘要重新干跑（每次约 10 s）：

1. **基线条目跨分轨合组**：分组键为 `<榜单版本>:<条目>`，L1 与 L2 的 `baseline/track_share` 落入同一组。L2 Run 与同组的 L1 首次运行比对摘要，120 对 L2 重复全部判为不同；抽样也按两个分轨合并，只抽 56 个。分组键改为带分轨后，抽样 80 个（每"条目 × 事件"1 个），可去重的重复 382 对。
2. **精简前字节未计隐藏区真值**：`bytes_after` 出现负值（例如 -1.6 MB），原因是释放字节含隐藏区 `run_<id>.mcap`，精简前字节不含。精简前后字节改为计入隐藏区运行真值。
