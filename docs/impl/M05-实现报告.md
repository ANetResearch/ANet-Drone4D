## 4. 与 PRD 的偏差及理由

| 偏差 | 理由与影响 |
|---|---|
| 退化档判定带 1% 容差：`min(hi, 0.6·池容量) ≤ lo·1.01` | ADR-010 第 2 轮池容量使 iGPU 钳制值 3,000,729 仅比 high 档 lo（3M）大 729 点，严格按 `lo ≥ 0.6·容量` 则 high 档不退化，与 §6.8.4 的意图（iGPU 5、6 档、dGPU 6 档退化）不符；M05-AC-011 的"手动 ultra 时 B 恒为 2.88M"按旧池写成，现为 0.6·5,001,216 = 3,000,729.6 |
| 18 §4.3 第 2 层两格阈值按原型包络判定（igpu B 反向 10 次/分钟、超 1.5T 5.5%；dgpu144 11 次/分钟、4.5%） | 原型 `ctrl.mjs` 自身的记录结果（g02 `out/ctrlsim_*.json`，本测试逐项复现）已超出表值；产品控制器在无积压、未触下限时与原型逐帧相同。已请求 M16/18 以 ADR 更新 |
| M05-AC-002"τ 受限时 limitedBy ≠ budget"按 ≤ 5% 帧判定（3M 为 0） | 纽约 750k 在原型与产品中均有 70/1801 帧为 budget，属数据性质 |
| 根节点以"相交"入堆（子节点总是重新裁剪） | 保证与原型在 g02 夹具（节点自身紧包围盒而非子树盒）上逐帧一致；对子树盒数据只少一次继承优化 |
| 首屏阶段每帧以深度上限 L 重取首帧目标集 | 相机在打开过程中移动（内容版本重开、飞行中切换）时，一次性目标集可能永远凑不齐而卡在 first_screen；静止相机下与"一次选择"等价 |
| 设备丢失恢复期把"选中且已缓存"的节点记为已绘制（迟滞），并在 0.95 覆盖或 2 s 后恢复派发 | 防止重传期间迟滞失效导致选择漂移到需下载的节点；PRD 的"覆盖率恢复到 0.95 或满 2 s"据此落实 |
| DTM 纹理为 R32F + 顶点着色器 4 次 textureLoad 双线性（PRD 写 R16F + LinearFilter） | 顶点阶段的硬件过滤需要显式 LOD，手写双线性与 CPU `dtm.sample` 逐位同式；精度优于 R16F，内存对六城最多 2.2 MB |
| 拾取 id 用 RGB 24 位（PRD 写 RGBA8 4 字节） | 不透明节点材质强制 alpha = 1；拾取子表点数 ≤ B ≤ 12M < 2^24 |
| 分页层级在打开时一次展开（子 chunk 取自整体 GET 的 hierarchy.bin），而非按需 Range | FR-001 规定 hierarchy.bin 整体 GET，文件已在内存；六城为单 chunk，此路径只用合成夹具 |
| 夹具放在 `apps/web/tests/pointcloud/fixtures/`（PRD 写 `apps/web/tests/fixtures/pointcloud/`） | 后者属 M00 目录（路径所有权）；已告知 M00 |
| 点云图层所有档位都在 CH_CLOUD（PRD 表中 Tier S 为 CH_MAIN） | 遵从 M06 注册表约定（Tier S 单 pass 渲染 MAIN \| CLOUD） |
| 画质采样只记录位姿，覆盖掩码留 null | 掩码需要 M06 在该帧以同一 DrawTable 渲染覆盖 RT，已请求 |
| Tier A quad 点径（FR-050）未实现 | M06 尚无 Tier A 后端；取点函数已抽出（`fetchNode.ts` 接受 vid 参数）便于 quad 接入 |
| 引擎直接从 `lib/tokens/*.gen.ts` 取默认 token，同时接受 `options.tokens` 注入 | 与 SK-F 一致；lint 允许 engine 读 lib |
