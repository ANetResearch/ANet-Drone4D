## 0. 摘要

1. **作业注册表**（FR-201，ADR-113 第 ② 条）：`register_plan_kind(kind, fn, *, owner, budget_ms, validate_input, priority_default)` 替换 worker 的 if/elif 分派；D1 的 11 种作业由新模块 `kinds_builtin` 登记（处理函数不变）；插件清单 `AWR_PLAN_PLUGINS`（缺省 `awr.sim.planning.kinds_builtin,awr.tasking.plan_kinds`）在 sim-core、D1 plan-pool worker、共享规划服务与其 worker 中按同一清单导入；未登记类别 300（UNKNOWN_KIND），同名重复登记在导入时抛 `PlanKindError`。
2. **规划服务端核心** `PlanServer`（FR-203、FR-204）：W 个（缺省 1，可配 2）可杀 worker 进程（独立解释器、socketpair 通信）；按会话轮转的公平队列、会话内按优先级与提交序；每会话在途与排队 ≤ 8（111）；同键取代；作业墙钟超过 `3 × 预算` 即 SIGKILL 并立即重建（本机 1.0–2.5 s，含 numba 核装载）；10 min 内 3 次超时冻结 5 min（586，冻结时排队作业一并回复）；崩溃首次重排、第二次 214；> 1 MB 结果外置到 `<shm_root>/<sid>/plan/`；世界装载阶段不计入作业预算；多世界 LRU ≤ 4，会话结束后解除不再使用的世界的映射；每个作业后释放 A* 整栅格工作数组。
3. **remote 模式**（FR-202）：`PlanPoolClient(mode="remote", bus=…)` 经本会话总线 query `ctl/plan/submit` 提交（`PlanRequest.to_wire()`，query 超时 = 预算 × 3 + 5 s，不重试），回复在总线回调线程只入队、由客户端解码线程解码（外置文件校验路径与 sha256 后读取并删除），仍只在 `drain(tick)` 生效并写输入日志；被取代或取消的在途作业发 `ctl/plan/cancel`；在途 query ≤ 4，其余本地按优先级排队。线上编码 `jobs.packb`（msgpack + numpy 扩展），往返后数组逐字节相同，`result_sha256` 与 inline 模式一致。
4. **输入配额**（FR-212）：`validate_input` 在 sim-core 提交前（全部模式）与服务端入队前执行；通用实现 `quota_check`（`PLAN_QUOTA` = AWR-04 §11.5 的九项），585 回复列出全部超限项与上限；D1 类别校验 `keepouts ≤ 64`。
5. **Grid25 来自派生缓存**（FR-205）：worker 优先取 M04 `world.grid25(alt, copy_on_write=True)`（WP-14 同期交付）；世界未提供时，D1 plan-pool 与本机开发在进程内构建，公开模式回复 123 derived_cache_missing；栅格按（世界, 高度）缓存并随世界淘汰。
6. **scenarios REST**（FR-213）：全部路由改为 `Depends(ctx_for)`（WP-03 已交付 `deps.ctx_for`），不再读 `request.app.state.awr`；sandbox-api 不挂载（`sandbox_main.DENY_MODULES` 含 scenarios，用例断言）。共享展示（S7）仍为 process 模式 plan-pool，经同一注册表分派插件类别（用例断言 worker 导入插件）。

## 2. 设计要点

### 2.1 注册表与插件

- 注册表是进程内字典，锁保护；`PlanKindSpec` 冻结数据类，同一函数以相同参数再次登记视为幂等（模块经两条路径导入），否则 `PlanKindError`。
- `load_plan_plugins` 每个模块每进程只尝试一次：模块不存在记 `missing`（缺省清单含尚未交付的 `awr.tasking.plan_kinds`），导入抛错记 `error` 并记录日志（`strict` 时重新抛出）；`kinds_builtin` 恒在清单首位。sim-core 在构造 PlanPoolClient 时导入，取得预算与校验函数；D1 plan-pool worker 在 `init_worker` 中导入（S7 的 `tasking.*` 作业据此在共享展示的规划进程执行）。
- 内置类别的处理函数保持 D1 代码，`plan_ms` 统计口径不变（`job_t0()` 取 `worker_main` 入口时刻）。未登记类别的 detail 由 D1 的 `UNKNOWN_KIND:<kind>` 改为 `UNKNOWN_KIND`（类别名放在 stats），这是对拍中唯一不同的一项，用例单独断言。

### 2.2 PlanServer

| 方面 | 做法 |
|---|---|
| worker 进程 | `subprocess.Popen([python, "-c", ...], pass_fds=[socketpair])`，父子以 `multiprocessing.connection.Connection` 通信；不经 multiprocessing spawn，因此不重新导入宿主的 `__main__`（sandbox-pool 的事件循环与总线不进入 worker 匿名页），宿主也不需要 `__main__` 守护。PYTHONPATH 补上 `python/`，配置经环境变量 `AWR_PLAN_WORKER_CFG` |
| worker 初始化 | PDEATHSIG 与父进程复核、`OMP_NUM_THREADS = 1`、`nice +10`、`awr.runtime.cgroup.join(cgroup_leaf)`、多世界 LRU、导入插件、装载 numba 核（TOPP-lite、2.5D A*、M04 几何核），之后回报 `ready`；就绪超过 60 s 判失败重建；启动期间退出按指数退避（≤ 5 s），曾就绪的 worker 被杀或崩溃后立即重建 |
| 线程 | 一个调度线程独占 worker 管道（`connection.wait` + 自管道唤醒）；`submit`、`cancel`、`drop_session`、`stats` 任意线程可调（一把可重入锁）；回复回调在锁外执行。总线 queryable 回调只做 `inbox.put`（PY-CB-01），解码、准入、移出总线 5 s 清扫在调度线程 |
| 调度 | 轮转指针按会话首次提交顺序，跳过空队列与已冻结会话；会话内 `(优先级, 提交序)` 小顶堆；崩溃重排保留原键（排到本会话队首） |
| 计时 | 派发时进入"装载"阶段（worker 打开或命中作业世界，上限 30 s，超时回复 123 WORLD_LOAD_TIMEOUT，不计入会话超时次数）；worker 回报 `begin` 后进入"执行"阶段，`3 × 预算` 起算；有效预算 = min(作业给出值, 登记值 × 3)，未登记类别在准入时已拒绝 |
| 期限 | wire 提交按客户端 query 超时记回复期限；排队超过期限的作业不再执行（125 QUEUE_EXPIRED；无可用 worker 时 213） |
| 结果 | worker 内完成 `PlanResult.to_bytes()`，宿主不解码；> 1 MB 写 `<shm_root>/<sid>/plan/<安全化 job_id>-<sha1 前 8 位>.msgpack`（0600，先写 tmp 再改名），回复 `result_path` 与 `result_bytes_sha256`；`drop_session` 删除残留文件 |
| 内存 | 每个作业后 `release_scratch()` 释放 `astar25._PLANNERS`（sanfrancisco 整栅格工作数组约 50 MB 被触及的匿名页），作业之间只保留解释器、numba 核与世界映射 |

### 2.3 remote 客户端

- 提交：本地优先级堆 + 在途 query 上限（缺省 4），因此正常客户端不会触发服务端每会话 8 个的上限；校验不通过的作业不发送，下一次 `drain` 以 585 结束（与其他模式一致）。
- 回复：总线回调线程只把 `(job_id, 回复, 错误, 用时)` 放入解码队列；解码线程把回复转为 `PlanResult`（外置文件：路径必须位于 `result_dir` 之下，读后即删，sha256 不符报错），再入 inbox；`drain(tick)` 生效、写输入日志，与 process 模式相同。
- 错误：0.5 s 内以无回复结束视为没有服务方（213），否则为超时（125 PLAN_TIMEOUT，同时发 cancel 释放服务端名额）；本地另有"query 超时 + 2 s 仍无回调"的兜底。
