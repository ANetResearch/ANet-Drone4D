## 3. 与 PRD 的偏差及理由

| 编号 | 偏差 | 理由与影响 |
|---|---|---|
| D-01 | fake_gw 自带最小协议实现（Starlette + uvicorn），未复用网关的 SyntheticSource 与协议栈 | 网关工作包尚未交付；线上行为按 17 §6.8（发送时装帧、尾帧保证、编码一次、credit）实现并由契约 schema 与 golden 校验。网关交付后可切换复用（已写入 M11-R-to-M11） |
| D-02 | fake_gw 的 advertise 中逐机 channel 的 `layout` 为 null，只有 `swarm/uav/state` 等全局 raw channel 附 `{schemaName, hash, size}` | N = 1000 时逐机附完整布局会使 advertise 达数 MB；schema 允许 null，客户端以 `serverInfo.layouts` 哈希与生成的访问器解码 |
| D-03 | supervisor 额外注入 `AWR_ZENOH_CONFIG`、`AWR_PROC`、`AWR_PLUGINS`、`AWR_CONFIG`、`AWR_WORLD`、`AWR_SCENARIO`、`AWR_PROFILE`、`AWR_BIND`、`AWR_ACCESS_MODE`、`AWR_PORT_OFFSET`、`AWR_RUNS_DIR`；zenoh 子进程配置渲染为 `/dev/shm/awr/<run>/zenoh.json5` | 19 §6.3 只列出部分注入变量，17 §9.3 写明"supervisor 注入 namespace 与端点"但未给机制；秘密仍只经文件传递 |
| D-04 | 第 6 次异常退出时立即进入 FAILED，不再等待第 6 个退避周期 | 19 §4.2 表写作"退避到期且为窗口内第 6 次"；计数口径不变（首次启动与 sys/restart 不计），只是 FAILED 提前约 8 s 呈现，测试时长也因此可控 |
| D-05 | exec 前检查 `python -m` 的模块与包 `__main__`、uvicorn 的 app 模块；缺失时直接 FAILED 且不进入重启循环 | D1 期间 sim-core、api 等入口尚未交付（包只有骨架），避免 `make run` 反复崩溃刷日志；ci profile 下仍以退出码 20 让测试判定 |
| D-06 | EventSubscriber 发现缺口后先等 20 ms（或下一次 pump）再补拉；`_replay` 无回复时等到 1 s 超时再报告缺口（§6.4.12 伪代码为收到错误立即放弃） | 同一步按 category 分开发布的消息会交错到达，立即补拉产生大量无效补拉（60 s 压测中 4,140 次瞬时缺口只需 122 次补拉）；无回复等待 1 s 与 M11-AC-004"`_replay` 无回复 1 s 后放弃"的文字一致；`truncated` 仍立即报告 |

## 5. 遗留问题

1. D1-AC-08 完整口径（3 个浏览器客户端 + flight60 下 api ≤ 0.35 核）依赖网关与 M16 harness；`bench_state.py --clients` 目前以退出码 14 结束。
2. D1-ext：`sys/run` 会话世界切换未实现（D1-core 回复拒绝 213）；checkpoint 恢复链路的生产者侧（5 s 内再次崩溃标记 poison、3 代中毒重开剧本）需 M08 接线，存储侧接口已具备。
3. `awr status --ws`、`awr sys loglevel`、`awr trace` 需要 api 端点，待网关交付后接入；`awr token` 不登记席位。
4. api 的 faulthandler 看门狗（`dump_traceback_later(2.5)` 每 0.5 s 重布置）、`hb.api` 10 Hz 任务与事件循环延迟采样属网关进程实现（已在 M11-R-to-M11 说明用法）。
5. seqlock 只在 x86-64 验证；ARM runner 的 10⁵ 次撕裂检测（K-01）无环境。
6. 带时间阈值的功能用例（kill -9 ≤ 100 ms、子进程 ≤ 1 s 退出）在宿主机严重过载时可能抖动；非验收阈值的上界已留余量。perf 标记用例目前直接由 pytest 执行，待 M16 harness 统一调度。
7. 契约与文档不一致项（sys_procs 枚举、事件 `batch_id`、基准 IPC 字段、`make test-fixtures`、19 §6.3 注入变量清单）已写入请求文件，待 M00 处置。
