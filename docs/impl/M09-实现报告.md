## 2. 装配与接口约定（给集成与其他模块）

1. **导入即登记**：sim-core 组合根按 `plugins: [awr.sim.safety]` 导入即完成全部登记；`AWR_SAFETY_AUTOINSTALL=0` 可关闭（诊断用）。
   tests/safety 的 conftest 在收集阶段调用 `uninstall()`，保证同一 pytest 进程中 M08、M11 的 SimCore 用例不被 M09 改变（已验证
   `tests/sim/test_skeleton.py` 与 M09 用例同进程通过）。进程内需要 M09 时调用 `ensure_installed()`。
2. **FSM 与 M08 运动的关系**：M08 CommandEngine 直接执行命令运动；M09 FSM 按运动模式的变化推断名义推进（SYSTEM）与操作员转移
   （OPERATOR），安全类命令与 resume 另经 `apply_operator` 显式登记（先于推断）。AUTO 安全动作经 SupervisorQueue 在下一 tick 执行，
   并以 `sup_expect` 标记，fsm 据此区分。流程：arm/takeoff → PREFLIGHT/CHECKING（1.0 s，与 M08 1 s 怠速重叠）→ READY →
   TAKING_OFF/SPOOLUP|CLIMB（与 M08 起飞阶段同步）→ 到达 → FLYING/HOVER；land → LANDING/GOTO|DESCEND|TOUCHDOWN →
   触地 → LANDED/SETTLING → 2 s → DISARMED；rtl → RTL/CLIMB → CRUISE → DESCEND → FINAL（M08 refgen 读 RTL 子模式）。
3. **链路**：操作员接管的机体按 hold_rtl 以席位 ping 年龄判定；客户端必须按 2 Hz 发 `ping`（浏览器 ClockSync 已满足）。不 ping 的
   测试客户端在接管 3 s 后 HOLD/LINK_LOSS（见 §6 第 1 条与 M09-to-M11 请求）。
4. **safety 行**：`state/sim-core/safety`，兴趣集（`ctx.interest`，agent_no）10 Hz【仿真】变化行 + 1 Hz【墙钟】全量；经
   `ctx.events.bus` 发布（请求 M08 提供正式发布入口）。

| FSM 通过"运动模式变化推断"得到 SYSTEM/OPERATOR 转移，而非由 CommandEngine 为每条命令调用 `apply_operator` | M08 只对安全类命令与 resume 调用钩子，导航命令直接执行运动；推断以 `mode_t` 变化 + Supervisor 期望模式区分来源，结果与 PRD 语义一致（`test_uav_state_event.py` 逐变化核对） |
| 预检窗口（1.0 s）与 M08 起飞怠速（1 s）重叠，takeoff 自 DISARMED 时 SPOOLUP 子模式通常直接跳到 CLIMB | M08 的 takeoff 立即开始怠速且不暂停运动；FSM 在窗口内显示 PREFLIGHT，到期经 READY 进入 TAKING_OFF 并与 M08 阶段对齐；预检失败时下发 DISARM 并以 103 结束调用 |
| 航向误差只在 FLYING/HOVER 与 HOLD 下评估 | M08 PATH/ORBIT 的航向设定点按航迹切线跳变（未限速），在转弯处评估会误报（NFR-007 零误报） |
| 倾角误差、状态缺失外的控制劣化参考速度取 ENU 参考点差分 | M09 不读 NED 的速度指令数组（AWR-03 §5.3 第 3 条） |
| FleetGuard：低优先级方已不在 FLYING（例如已悬停让行）而冲突仍在时，高优先级方同样让行 | D1 无避让机动（三层互避 V0.6）；只让一方时高优先级方会撞上悬停的一方（M08 jerk 限幅刹停距离约 6 m），"最小距离 ≥ 3 m"无法保证 |
| 双方 K1 = 2（无人可让）时发 `SAF.SEP.AVOIDING`/`VIOLATION`（detail `NO_YIELD:<mate>`），不是独立 critical 代码 | 契约目录无对应代码；已请求 M00 可选登记 `SAF.SEP.NO_YIELD` |
| `uav.state` 与 `safety.*` 分属 EventPublisher 的 `sim`、`safety` 两个 category，每轮各一次 put | category 映射属 M11；每 category 每轮至多一次仍满足 ADR-018 的合批 |
| safety 行：可选字段取缺省值时省略、数值以 float32 编码；`geofence_margin_m` 无世界时为 99999 | 带宽（NFR-009）；schema 仍通过；前端按缺省解释 |
| state_drop 以 M09 内部状态年龄叠加驱动判据，不冻结控制器的状态估计 | M08 尚无 `est_freeze`（§14 第 10 条），已请求 |
| 流式指令 watchdog 容差实测 ±30 ms（AC 为 ±20 ms） | 250 ms 墙钟由 M08 ingest 计时（每 tick 4 ms 检查），测试台以 5 tick 一步推进，外加 1 tick Supervisor 延迟 |
| RTL 子阶段 FINAL 判据用"高于 home 10.5 m"而非 AGL < 10 m | 与 M08 refgen 的 DESCEND 目标（home 上方 10 m）一致，避免阶段抖动；fsm_min 同口径 |
| `checkpoint.py` 未单列，checkpoint 扩展段在 `service.py` | 内容少，与钩子同处；M08 尚未调用 |
| 故障注入 REST（R16/R62）只实现 sim 侧查询路由 `safety/fault` | api 路由属 M11（已请求） |
| 前端 store 单元测试放在 `tests/safety/web`（M09 路径）并自带 Vitest 配置 | apps/web/tests 不属 M09；`make test` 经 `TEST_TARGETS` 运行，已请求 M00 决定是否并入 unit 项目 |
