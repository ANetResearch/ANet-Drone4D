## 1 结论摘要

- 本轮复测 16 条：通过 2 条（11b、14），不通过 14 条（03b、04、07、08、09a、16、17、19、23、25、26、27、28、29），没有未测项。
  沿用的 22 条（01、02、03a、05、06、09b、10、11a、12、13、15、18、20、21、22、24、30、31、32、33、34、35）都是通过。
  合计 38 条（03、09、11 各分 a、b）：通过 24 条，不通过 14 条（第 2 轮通过 22、不通过 16；第 1 轮通过 13、不通过 23、未测 2）。
  - 含 P0 的 25 条：通过 16 条；不通过 9 条（03b、04、07、08、09a、19、25、26、27），这 9 条的 P0 子项都不通过。
  - 只含 P1 的 13 条：通过 8 条（05、09b、11b、18、21、22、30、31），不通过 5 条（16、17、23、28、29）。
  - D1 退出条件（G4：P0 全部通过）不满足。
- 与第 2 轮相比，多数不通过项只剩一个子项，且离阈值近了一大截：
  1. **整景与大机群的帧节奏**：整景 > 50 ms 由 10.57% 降到 4.59%，n200 由 14.05% / 1.08% 降到 6.51% / 0.46%，p50、p95、p99、> 100 ms 全部进入暂定阈值；
     不通过的只有"最大帧间隔"（整景 317 ms、n200 467 ms、soak 结束后的整景 450 ms）和由它连带的"整景进入目标带"（2.95 s）。这些 300–570 ms 的尖峰在
     `chrome=0`（只有画布）下同样出现，属 WebGL 侧（web-engine，4.2）。
  2. **sim-core N = 1000**：RTF 1.000、CPU 0.563 核、单步最大 7.2 ms、追帧饱和 0 都已满足（第 2 轮 0.758、0.755、41.1 ms、674），只剩单步 p99 4.96 ms
     （阈值 3 ms）；3 个 SwiftShader 客户端并发时 tick 数据年龄 p99 16.5–16.7 ms、单步 p99 10.6 ms（D1-AC-08、28，sim，4.1）。
  3. **恢复、渲染后端、回放内存**：11b 通过（第 2 轮恢复 5.33 s），14 通过（Tier A 功能矩阵已实现），soak 的 RSS 增长 api +0.55%、sim-core +0.05%
     （第 2 轮 api +46.3%），堆增长 16.5%、重连 0、GPU 池高水位不上升；29 只因帧节奏的最大间隔（与 03b 同源）不通过。
  4. **风暴、选中、跟随**：全机 RTL 期间帧间隔 p50 67 ms（第 2 轮 133 ms），Toast、渲染行、FIFO 满足；t_sim 到像素 p95 200 ms（第 2 轮钳在 300 ms），
     命令到可见、关注集切换、×10 HOLD、选中机通道频率四个新子项通过。
- 本轮新发现：
  1. **LoAF 探针不能识别主循环**（web-engine，4.2a）：Chrome 151 对 rAF 回调报告的 `invokerType` 是 `user-callback`（`invoker` 为 `FrameRequestCallback`），
     而 `engine/perf/loaf.ts` 只在 `invokerType === 'frame-request-callback'` 时按时间匹配主循环，因此主循环回调从不被排除，主循环本身超过 50 ms 的帧都计为
     "我方 > 50 ms"。诊断运行中，全机 RTL 探针计 2 次、按源位置排除主循环（`ui-*.js@516414`，函数 `Lx` 即 `engine/loop` 的帧回调）后为 0 次。D1-AC-27
     的我方 LoAF 计数、整景用例的 `ours_over50`（2，第 2 轮 0）都受此影响。
  2. **主循环内的强制同步布局**：整景与 warmup 诊断各有一帧主循环回调 58–66 ms，其中强制样式与布局 47.5–51 ms（4.2a）。
  3. **S1 整景的 PerfGovernor 降到点云下限**：ADR-067 的不可见子步骤串联使 S1 两架机的整景在揭开后 5–20 s 内降到第 7 步、B 1.0–1.2 万（第 2 轮整景 B 2.03 万）。
     不违反 18 §2.3 的顺序，但整景画面点数降了约一半（4.2）。
  4. 交付状态 numba 缓存（清空后只经 `make numba-warm`）在全部性能用例运行前后文件集合相同（运行期新增签名 0）；本轮全部运行（含 `chaos` 的 kill -9）没有新增孤儿
     plan-pool 进程（4.1b）。
- 暂定阈值：03b 与 09a 的 p50、p95、p99、> 50 ms、> 100 ms 可以按暂定值冻结，最大间隔维持 250 ms 不放宽；09b 维持第 2 轮的冻结建议；26 的 t_sim 到像素
  维持 150 ms，并建议以 ADR 明确统计窗口起点；credit_skips ≤ 1% 暂不冻结；固定层合计 ≤ 10 ms 可冻结、单层预算按实测重分；soak 的 RSS ≤ 10% 可冻结（第 5 节）。

### 4.2a web-engine：LoAF 探针不能识别主循环，主循环内有强制布局（D1-AC-27、06）

- 诊断方法（`.cache/acc3/diag/loafdiag.mjs`，不判定）：真实后端与生产构建，页面初始化脚本另挂一个 `long-animation-frame` 观察器，记录每个 ≥ 50 ms 条目的全部脚本
  （invoker、invokerType、sourceURL、sourceCharPosition、sourceFunctionName、forcedStyleAndLayoutDuration），与产品探针 `__perf.loaf` 并列；整景、warmup 操作、全机 RTL
  各 1 次。结果在 `diag/loaf-{full,warmup,rtl}.json`。
- 发现：
  1. Chrome 151 对 rAF 回调的条目报告 `invokerType = "user-callback"`、`invoker = "FrameRequestCallback"`；`engine/perf/loaf.ts` 的 `isLoopCallback` 要求
     `invokerType === 'frame-request-callback'`，该值在 Chrome 151 中不会出现，因此**主循环回调从不被排除**。生产构建中主循环帧回调位于 `ui-CuK7zbIZ.js@516414`
     （函数 `Lx`，即 `engine/loop` 的 `requestAnimationFrame` 回调，`Ix` 为 16 项的 `cbStarts`），属"我方 chunk"，于是主循环本身超过 50 ms 的帧都会计入
     `oursOver50`。FX2-R3-web-ui 2.3 第 7 条把计数偏高归因于 16 帧时间环，实际首先是 invokerType 判别失效（时间环问题可能同时存在）。
  2. 全机 RTL：探针 2 次；两条被计入的条目都含主循环回调（19.1、31.1 ms），排除主循环后我方脚本 40.2、20.3 ms，均不超过 50 ms，**按 18 §6.3 的口径为 0 次**。
     其余我方脚本为按键处理（`DOMWindow.onkeydown`，19 + 15.8 ms）与空闲回调（`IdleRequestCallback`，Toast 帧后投递，20.3 ms，强制布局 12.4 ms）。
  3. 整景：探针 2 次；被计入的一条为主循环回调 58.3 ms，其中**强制样式与布局 47.5 ms**；warmup：主循环回调 66.4 ms，强制布局 51 ms。即主循环的某个阶段在 DOM
     失效后读取布局（同步回流），一次约 50 ms。这不属"主循环之外的我方脚本"，但它是一帧 100–210 ms 长帧的主体，也是整景用例 `ours_over50`（2，第 2 轮 0）的来源。
  4. warmup："切换天气"经命令面板时按键处理 57–60 ms（强制布局 21–23 ms），第一、二遍都在，按 18 §6.3 计为我方 > 50 ms 的 LoAF（不属本条阈值，D1-AC-25 只看帧间隔）。
- 影响与建议：D1-AC-27 的判定值（RTL 5、link_drop 3）来自探针，本报告按其判定为不通过；探针修正（invokerType 按 `user-callback` + `FrameRequestCallback` 判别，或按
  首次匹配后记下的 `sourceURL` + `sourceCharPosition` 识别主循环，FX2-R3-web-ui 第 7 节第 2 条）属 web-engine（M06 `engine/perf/loaf.ts`），修正后需复测 D1-AC-27 与
  D1-AC-06。主循环内 47–51 ms 的强制布局需按 trace 定位读取布局的阶段（标签层、HUD、unobscured rect 同步等，web-engine 与 web-ui 协同）。
