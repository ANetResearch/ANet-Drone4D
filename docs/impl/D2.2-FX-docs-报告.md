### 1.2（次要）quickstart 引用的 FastAPI Duplicate Operation ID 告警端点名与真实输出不符

**核实**：原复核给出的证据（两次独立 `make setup` 均只出现 `_head`）**部分不成立**——不是"应当把 `_get` 改成 `_head`"，而是**两种
后缀在不同进程中都会出现，取决于 Python 的哈希随机化种子**，原文档与原复核的"_get"/"_head"都只是单次观察，不能作为稳定结论。

**证据**（本任务独立验证，优先级高于只跑两次 `make setup` 的经验观察）：

1. 代码证据：路由定义在 `python/awr/api/rest/runs.py:194`：
   `@router.api_route("/api/runs/{run}/segments/{name}", methods=["GET", "HEAD"])`，同时服务 `GET`、`HEAD` 两个方法。
2. 项目自己的契约生成脚本 `tools/contracts/gen_openapi.py` 第 38-40 行已经写明这一机制："FastAPI suffixes the operation id of a
   multi-method route (GET + HEAD) with `list(route.methods)[0]`, the first element of a set: it changes with PYTHONHASHSEED." 并为此对
   已提交的 OpenAPI 快照做了规范化（`_stable_operation_ids`），说明项目内部早已知晓这一非确定性,只是从未同步到用户文档。
3. 本任务用项目 `.venv`（FastAPI 0.141.1）实际构建 `create_app(...).openapi()`，对 `PYTHONHASHSEED=0..12` 共 13 个种子逐一复现：
   `_get` 出现 6 次（种子 0,1,2,8,10,11），`_head` 出现 7 次（种子 3,4,5,6,7,9,12）,证明两种后缀都会真实出现,大致各半,并非稳定为
   `_head`。

**修复**：不把文档改成断言另一个同样会过期的具体值,而是如实说明"后缀取决于解释器哈希种子,两次运行可能不同",同时给出两种可能的完整
字符串,并说明这只影响告警文字、不影响已提交的 OpenAPI 快照（已被该脚本规范化）。

**改动文件**：`docs-site/en/intro/quickstart.md`、`docs-site/zh_CN/intro/quickstart.md`（"输出中的告警"一节的最后一句）。
