## 0. 任务范围说明（与用户另一条反馈的关系）

本次工作是在既定工作流任务 D2.2-R-landing（首页对抗式复核）下执行的，端口偏移、输出格式（结构化 findings）与硬性约束（"只报告有证据的问题，不修改代码"）均由该任务规定。复核过程中，用户在会话里另外提出一个不同子系统的问题："切换城市时，最初在 synthcity 中布置的目标物、视野、感知范围被带到其他地图"，并要求修复、并为其他地图加入模拟任务与目标物。

核实后这件事与本任务的对象（`apps/web/src/app/demo/` 静态落地页）无关：落地页本身明确不加载 three、引擎与实时客户端（`Landing.tsx` 文件头注释与 `vite.config.ts` 的 `LANDING_MODULES`/`APIDOCS_MODULES` 分块约束），没有城市切换、无人机监测任务或目标物布置的界面——这些都在主应用的仿真运行时里（`apps/web/src/stores/targets.ts`、`perception.ts`、`mission.ts`、`apps/web/src/app/shell/worldScope.ts`、`apps/web/src/viewport/layers/*`）。本任务的工具与产出格式（Playwright 复核 + 结构化 findings，明确禁止修改代码）也不支持去实现一次跨多个 UrbanScene3D 城市的新增任务/目标物内容这类功能性工作。

已花时间做了只读排查，定位给后续任务：
- 代码里已经有专门为"世界切换残留"设计的机制（标注 D2.2-W1，ADR-111）：`apps/web/src/stores/worldScope.ts` 的 `onWorldReset` 注册表 + `apps/web/src/stores/targets.ts`/`perception.ts`/`mission.ts` 的 `resetTargetsWorld`/`resetPerceptionWorld`/`resetMissionStore`，在世界或实时源切换时清空目标物、感知帧/视野、任务路径等。这说明问题更可能是这套机制里的一个具体缺口（例如视口渲染层 `viewport/layers/targets.tsx`/`field.tsx`/`mission.tsx` 没有正确响应 store 清空、或 `app/shell/worldScope.ts` 的 `sync()` 在沙盒切换世界时没有及时拿到新 `worldId`），而不是完全没有清空逻辑。
- `perception.ts` 里 `fieldView`/`volumesMode`/`physicalRef` 被注释明确标为"视图偏好，世界切换后保留"（第 25–27 行），如果用户感知到的"视野"是指这几项，那是设计如此，需要和用户确认是否要改为切换世界时也重置。
- 建议另开一个有代码写入权限、且覆盖主应用视口（而非仅静态落地页）的任务，用上述文件作为起点，用沙盒会话实际切换城市复现后定位。"其他地图加入模拟无人机监测任务和目标物"需要产品侧先定哪些城市、哪些目标物/任务模板，工作量superior于本次复核范围。

## 1. 复核结论摘要

共发现 6 项有证据支持的问题，其中 3 项较重（major）：首屏滚动揭示动画会让真实内容（含实景截图）在部分滚动节奏下保持不可见；"开启我的沙盒"流程的场景模板名称/说明在英文界面下仍强制显示中文；落地页 JS 入口分块里约 92% 的字节来自完整的中英文 i18n 词典（而落地页只用到其中几十个键）。其余 3 项较轻。同时确认了若干正向结果（见第 3 节），包括：全部测试视口无横向溢出、触控目标均 ≥44px、对比度远超 WCAG AA、alt 文本齐全、键盘焦点顺序符合视觉/DOM 顺序、no-emoji lint 干净、reduced-motion 下内容正常直接可见。

## 2. 问题清单（按严重性）

### 2.1 [major] 滚动揭示动画可能让正文内容（含实景截图）保持不可见

- 证据：`apps/web/src/app/demo/Landing.tsx` 的 `useReveal()` 用 IntersectionObserver 给 `.landing-reveal` 元素设置 `data-in`，`landing.css` 第 31–32 行：未设置 `data-in` 的元素 `opacity: 0`。脚本化复核（往返滚动全页 + 读取 `data-in` 计数）：
  - 页面刚加载、尚未滚动：`33` 个 `.landing-reveal` 元素里只有 `1` 个已揭示；对该状态直接做 Playwright `fullPage` 截图，得到的整页截图里，Hero 之后只剩一个小节标题，其余全部空白，直到页脚。
  - 用步长 400px/60ms 的节奏连续滚到底、停留 1200ms（不来回滚动）：仍有 `4/33` 个元素未揭示（1 个小节标题 + 3 张实景截图的 `<figure>`）。
  - 用更慢的节奏滚到底再滚回顶：`33/33` 全部揭示。
- 结论：揭示机制依赖 IntersectionObserver 在恰好的时机触发，截图/快照类工具（含本任务要求的 Playwright 截图本身）和较快的下滑动作都可能让内容停留在 `opacity:0`，没有超时兜底（比如"离开视口外一定距离强制揭示"）。核心受影响内容正是"实景画面"小节的产品截图——这正是本任务要核对的"动图/实景画面是否保留"的证据区。
- 建议：给 reveal 逻辑加一个保底（例如首次布局后若干毫秒未触发就强制 `data-in`，或扩大 `rootMargin`/改用 `threshold` 数组），不要让真实内容的可见性完全依赖一次性的 IntersectionObserver 回调。

### 2.2 [major]"开启我的沙盒"场景模板在英文界面下仍是中文

- 证据：`apps/web/src/ui/sandbox/StartSheet.tsx` 第 39–47 行：
  ```
  /** template label: the server's Chinese name, else the i18n name of the known ids */
  export function templateLabel(t, tpl) {
    return tpl.name_zh ? sanitizeText(tpl.name_zh, 40) : t(`sandbox.template.${tpl.template_id}`)
  }
  ```
  `templateLabel`/`TemplateLines` 无条件优先使用服务端返回的 `name_zh`/`summary_zh`/`first_feedback_zh`字段，不判断当前界面语言；即使退回 i18n key，`en.json` 里 `sandbox.template.*`、`sandbox.limitedBy.*`、`sandbox.endReason.*`（除 user 外）、`sandbox.band.*` 全部是空字符串（已用脚本枚举确认），按 `app/i18n/index.ts` 的回退规则会再退回中文。
- 影响：落地页第二主操作"开启我的沙盒"直接可达这个 Sheet（`app/demo/SandboxLaunchSheet.tsx`），英文访客选择 English 后，场景模板名称、一句话说明、首次反馈提示、沙盒结束原因等仍是中文，与周围的英文界面文字混排。
- 建议：服务端目标补充 `name_en`/`summary_en`/`first_feedback_en`（或由前端按 locale 选字段），并补全 `en.json` 里对应的空字符串键。

### 2.3 [major] 落地页 JS 入口分块里约 92% 字节是完整中英文 i18n 词典

- 证据：`VITE_AWR_DEMO=public vite build` 产出 `dist/assets/landing-NbyPXjfE.js`（478,187 B，gzip 150.66 KB），是落地页首屏唯一 `modulepreload` 的大分块。`vite.config.ts` 的 `LANDING_MODULES` 正则把 `app/i18n/**` 整体并入 landing 分块；`app/i18n/index.ts` 在模块顶层无条件 `import zhCN from './zh-CN.json'` 与 `import en from './en.json'`（分别 118,286 B 与 92,664 B 原始 JSON，另有 `reasons.zh-CN.gen.json` 20,564 B）。对 `landing-NbyPXjfE.js` 做字符串统计，文件里能直接匹配出约 441,932 字符的类 JSON 键值内容——而落地页实际只用 `landing.*`/`sandbox.*` 前缀下数十个键（全词典约 2583 个键）。
- 影响：与模块内部注释自述的"落地页要轻、不能加载 zustand"的目标相悖；访客为了看一个落地页，要多下载约 230 KB 原始（两种语言全量未使用的应用文案）。
- 建议：落地页专用一个只含 `landing.*` 前缀（及按需 `sandbox.*`）键的小词典，或做按需/当前语言单文件的拆分，避免整份 `zh-CN.json`/`en.json`/`reasons.zh-CN.gen.json` 进入首屏分块。

### 2.4 [minor] 全站强制深色，没有随系统浅色偏好或手动切换的路径

- 证据：`apps/web/index.html` 第 2 行硬编码 `<html lang="zh-CN" class="dark" ...>`，`<meta name="color-scheme" content="dark">`；`src/styles/theme.css` 第 152 行 `html:not(.dark) { color-scheme: light; }` 因此成为死代码；`LandingHeader.tsx` 没有主题切换控件。Playwright 分别用 `colorScheme: 'dark'` 与 `colorScheme: 'light'` 打开页面，两套整页截图在设计上完全一致（深色），因为 CSS 的 `.dark` 变体策略只认 class，不认 `prefers-color-scheme`。
- 影响：本任务要求核对"深浅色"，核对结果是浅色路径不存在。按企业级工业风的产品定位，纯深色可能是有意的设计决定，但未见文档明确声明；建议确认这是否为既定设计（若是，建议在设计基线里写明，避免后续被当作缺陷反复提出）。

### 2.5 [minor] Showcase 画廊偶发出现空白占位（懒加载时序问题，非每次复现）

- 证据：两次独立的整页截图复现了同一现象——图片说明文字正常显示，但对应 `<figure>` 内是空白深色块，没有图片：iPhone 15 竖屏（"跟随视角"一图）与桌面浅色模式复核（"四维环境场"一图，像素级 diff 定位到 y≈2673–4883 区间）。但用网络请求追踪脚本定向复现同一张图（iPhone 15、同样的滚动节奏）时该图正常加载完成（`complete: true`）。
- 结论：间歇性，疑似与 `loading="lazy"` 原生懒加载和程序化快速滚动的时序有关，不是每次加载都会发生；没有加载骨架屏或 `onerror` 兜底，一旦某次没按时加载完成就永久停留在空白块。
- 建议：给 `<img loading="lazy">` 加一个占位骨架或加载失败提示，并在弱网/快速划动场景下再验证一次。

### 2.6 [minor] iPad Pro 11 横屏（1194 CSS px）顶部导航已收进汉堡菜单，损失较多可用宽度下的导航入口

- 证据：`Landing.tsx` 文件头注释与实测一致——断点为 1280 CSS px，iPad Pro 11 横屏视口宽 1194px（小于 1280），头部只剩 Logo + 汉堡按钮，核心能力/实景画面/技术与路线/开源与引用四个锚点导航、语言切换、GitHub 链接、主 CTA 按钮全部收起（见 `crops/ipad-header.png`）。
- 这是文档化的既定行为（非缺陷），但 1194px 已经接近笔记本尺寸且多数情况下有鼠标/触控板，值得产品侧确认 1280px 这个阈值是否过于保守。

## 3. 确认无问题（正向结果）

- 横向溢出：iPhone 15、Pixel 8、iPad Pro 11 横竖屏共 6 个视口脚本化核验 `document.documentElement.scrollWidth === clientWidth`，全部无溢出。
- 触控目标：同 6 个视口对全部 `button`/`a[href]` 做尺寸核验，未发现小于 44px 的目标。
- 对比度：`text-muted-foreground` 在深色背景下 8.55:1，`h1` 17.73:1，均远超 WCAG AA 的 4.5:1（小字）/3:1（大字）门槛。
- alt 文本：页面全部 11 个 `<img>` 均有 `alt`（含 Hero banner、S0 动图、六张实景截图），装饰性头像图为空 `alt=""` 属合理用法。
- 键盘焦点顺序：Tab 依次走查前 20+ 个可聚焦元素，按文档绝对坐标核验（排除粘性头部的视口相对坐标干扰后）顺序与视觉/DOM 顺序一致，包括"开源与引用"小节的两列网格（先左列链接列表、后右列引用卡片，符合该断点下的从左到右阅读顺序）。
- no-emoji lint：对 `app/demo/*.tsx`、`app/demo/*.ts`、两份 i18n JSON 跑 `tools/lint/no-emoji.mjs`，`ok`。
- 动图留存：`demo-flight.webp`（S0 剧本 10s 2 倍速回放）网络请求正常完成，`naturalWidth` 非零。
- reduced-motion：`useReveal()` 在 `matchMedia('(prefers-reduced-motion: reduce)').matches` 时直接返回、不设置 `data-landing-reveal`，CSS 选择器因此不生效，内容无动画直接可见（见 `crops/reduced-motion-top.png`），没有"内容因为减少动态而永久不可见"的风险。
- GPU 最小上限：`voxelField.ts`（落地页唯一的 WebGL2 渲染代码）未使用任何 Uniform Buffer Object（无 `bindBufferBase`/`uniformBlockBinding`），不落入 `perf/m06/gpu-limits.spec.ts` 所防的 UBO 绑定点耗尽类问题；该 spec 本身的范围是 M06 主视口/引擎（含 three.js），落地页按设计不加载该部分，不适用。
- 容量信息不可用时的降级：本机复核环境没有后端（`/api/sandbox/v1/capacity` 502），页面优雅显示"容量信息暂不可用"纯文本，没有出现破损布局（该 502 为复核环境限制，非落地页缺陷）。
- 文案逐句检查（中英 `landing.*`/`sandbox.*` 前缀约 150 组键值）：未发现口语化、夸张或明显语法问题；"research"/"dev"/"available" 三态状态标注与 docs/05、docs/research/d3 交叉核对未发现把研究或开发中项标为已交付的情况；`agents`（智能体协作）卡片虽标"已交付"，但正文明确注明"V0.1 以进程内 Mock ANet 运行，公开站未启用"，披露充分，未计为问题。

## 4. 复核环境与局限

- 本机无 GPU、无后端服务，`vite preview` 静态产物复核，`/api/*` 全部 502；容量轮询、沙盒实际创建流程未做端到端验证。
