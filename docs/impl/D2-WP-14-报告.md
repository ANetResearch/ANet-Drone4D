## 0. 摘要

1. **Grid25 并入派生缓存**（ADR-113 第 5 条）：`DERIVE_VERSION` 升为 `m04-derive@2`，派生集新增 `grid25.f64`（Hf，阻塞格 +inf）、`grid25_base.f64`（阻塞前的 Hf）、`grid25_floor.f32`（格心 DTM）与 `grid25_blocked.u8`，manifest 新增 `grid25` 段；`DsmWorldQuery.grid25(alt_min_agl_m=None, *, copy_on_write=False) -> Grid25View`。缺省高度直接返回缓存的只读 memmap（文件页），非缺省高度由地板与阻塞掩码合成（不再查询 DTM、不再做多边形判定）。本机七个世界的缓存已按新键重建（`make geo-warm`）。
2. **`los_batch` numba 化**（D2-MS2 必做项）：新模块 `kernels.py`，命中即停、无中间数组，与 D1 numpy 实现（保留为 `los_batch_np`）逐位一致；惰性导入 numba，`DsmWorldQuery` 构造时只在进程已导入 numba（sim-core、plan-pool）时同步预热，核未就绪时走 numpy 路径，因此任何进程都不会在查询路径上编译；`AWR_KERNEL=numpy` 关闭核。
3. **可用性探测**（AWR-04 §4.4.7）：`cache_status`、`cache_status_all` 只读 `world.json`、校验坐标绑定与条目 manifest（`deep` 时逐数组 sha256），给出 `available`、`reason`（`derived_cache_missing`、`world_invalid`）、`detail`（`missing`、`stale`、`corrupt`）与条目、Grid25 字节数（`ws(w)` 初值）；`python -m awr.world.geometry.cli check`（退出码 4）与 `make geo-check` 供 install.sh 使用；`open_world_query(allow_derive=None)` 取 `AWR_GEO_ALLOW_DERIVE`，缓存根取 `AWR_GEO_CACHE_DIR`。
4. **`world_query.py` 的 `ctx_for`**（AWR-04 §14.3）：上下文经 `Depends(ctx_for)` 解析（M11 已交付 `awr.api.deps.ctx_for`，交付前退回 `app_ctx`），世界取 `binding.world_id`（沙盒）或 `settings.world_id`（共享展示），总线取 `ctx.bus`；路由文件不再读 `request.app.state`。show-api 的 OpenAPI 中该路由不变。
5. **`tools/bench/geo/run.py`**：七个世界的派生缓存与 Grid25 字节数、热打开、Grid25 匿名页与文件页增量、进程内构建对照、`los_batch` numba 与 numpy 每条射线 p50 与 p99 及逐位对拍；输出 `awr.bench.geo.v1` 与 `world_costs_hint`（供 M16 成本表）。

## 2. 设计要点

### 2.1 Grid25 的缓存内容与逐位相同

- 定义与 M10 `sim/planning/grid25.py::Grid25.from_world` 完全相同：`top` 取 Height_map 最大值金字塔第 1 层（4 m），地板为 `ground_dtm` 在格心的 float32 值，`Hf = max(float64(top), float64(floor) + alt)`，阻塞判定与外扩逐行照搬 `block_zones`。地板改用可分离实现 `Grid.centres_bilinear`（下标、权重与运算顺序与逐点 `bilinear` 相同），七个世界与逐点参考实现逐位相同，旧金山地板从 0.41 s 降到 0.18 s。
- 存 float64 而不是 float32：`float64(floor) + 20` 一般不能用 float32 表示，存 float32 会改变 A* 的代价与 D1 golden；`a` 直接作为 numba A* 的输入（只读 C 连续 float64）。
- 条目字节数（MiB，含 Grid25）：synthcity 9.2（1.8）、shenzhen 23.5（4.6）、suzhou 19.3（3.8）、newyork 59.0（11.6）、chicago 213.3（42.0）、shanghai 305.4（60.2）、sanfrancisco 347.5（68.5），与 AWR-04 §4.4.2 的 `ws(w)` 初值（25、30、30、65、220、310、350）一致或略小。
- 非缺省高度不再进入缓存（`GeoParams` 只有一档），由 `grid25_floor` 与 `grid25_blocked` 合成，旧金山约 0.1 s，但为匿名页（52 MiB）；是否在沙盒中允许任意高度由 M10 决定（`d2-WP-14-to-M10.md` 第 5 条）。

### 2.2 numba 核的一致性与装载策略

- 一致性：`L = sqrt((dx·dx + dy·dy) + dz·dz)` 与 numpy `linalg.norm(axis=1)` 的求和顺序经实测完全一致（10⁶ 量级随机向量 0 例不同，另一种结合顺序有 2.4 × 10⁵ 例不同）；`s_j = e + (1 − 2e)·j / (n − 1)` 与 `q_j = A + (B − A)·s_j` 保持 numpy 的运算顺序；格判定改为浮点比较 `0 ≤ fx < W`（与 numpy 的 floor 后整数比较等价，并避免大数取整溢出）；`fastmath = False`。
- 装载：只在 `los_batch` 首次需要或显式 `warm_kernels()` 时导入 `kernels.py`；`DsmWorldQuery` 构造时若 `numba` 已在 `sys.modules`（sim-core 的 `_load_world` 处于 `start()` 内、ready 之前）即同步预热：已有其他核的进程中读缓存约 7 ms，冷缓存首次编译约 1.6 s（每机每版本一次）。核未就绪时 `los_batch` 走 numpy 路径，结果相同。核只有一个签名（包装层统一为 C 连续 float64 与只读 float32 DSM 视图），满足"预热签名覆盖运行期签名"（D1 验收第 1 轮 4.1）。
- 成本（smoke 量级，合成小世界，不作为验收数据）：1 m 步长约 4 µs/条（numpy 约 78 µs），2 m 步长约 2 µs/条（numpy 约 30 µs，与 AWR-04 §4.2 的 31–35 µs 吻合）。

### 2.3 部署开关与探测

- `allow_derive` 的缺省值改为 `None`（取 `AWR_GEO_ALLOW_DERIVE`，未设置为允许），显式参数优先；`warm` 总是允许派生。沙盒与公开部署由池给 sim-core 与共享规划 worker 设 `AWR_GEO_ALLOW_DERIVE=0`，无需改动调用方。
- 探测与 `open_world_query` 共用 `read_world_header`（读 `world.json`、检查三个几何图层就绪、校验 `coordinate.json` 的 sha256），键计算相同；`stale` 表示该世界只有其他键的条目（版本、参数或世界内容变化）。

### 2.4 `ctx_for` 与沙盒路由

- 处理函数 `handle_query(world_id, request, ctx)` 与 D1 逻辑相同，上下文来自依赖。M11 在本工作包进行期间交付了 `awr.api.deps.ctx_for`（show-api 返回 `app.state.awr`，sandbox-api 按 sid 返回 SessionContext 并给出 404 `305`、410 `506`、503 `211`），本路由已直接使用。
- 沙盒前端"点选放置（`ray_hit`）"需要会话内的几何探针，但 SB-00 至 SB-68 中没有该路由；`build_sandbox_router()` 已就绪，为避免 sandbox-api 的 OpenAPI 与冻结快照不一致，未以 `sandbox_router` 名称导出，已向 M17 提议登记 SB-69。
