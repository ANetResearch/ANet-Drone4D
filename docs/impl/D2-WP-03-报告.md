## 0. 摘要

1. **运行时库**（`awr.runtime`）：`RunBinding`（run 寻址与密钥位置，`from_env` / `from_msg` / `to_msg`）；`sbauth`（持久化密钥文件、全站 `K_sbauth`、沙盒 token 编解码、`K_pool` 与池控制面签名）；`cgroup`（加入叶子组、建删叶子组、写限值、读 cpu.stat、memory.stat、PSI；无委派时返回 False 只告警一次；可用临时目录模拟）；`procutil`（从 supervisor 抽取的进程原语，supervisor 改为调用、行为不变，另加带日志文件与 cgroup 包装的拉起、starttime、environ、pidfd）；`child` 的 `AWR_DETACHED` 与 `AWR_LOG_FILE`；`config` 的 `sandbox:` 段（M17 §6.7 全部键，未知键退出码 2）、`layer: sandbox`、`${sandbox.port_effective}`、`AWR_SANDBOX_*` 环境变量与 `sandbox_from_env()`。
2. **api 改造**（show-api 行为不变）：请求级上下文 `deps.ctx_for`（show-api 恒为唯一上下文；sandbox-api 按路径 sid），`app_ctx` 保留为别名；`ApiSettings.binding()` 与 `for_binding()`；Gateway 按 `RunBinding` 实例化；`discover_routers(attr, deny)`；限流与 WS 每地址上限改按地址前缀（IPv4 /32、IPv6 /64）；show-api 显式拒绝带 `scope` 的 token。
3. **sandbox-api**（`awr/api/sandbox_main.py` + `rt/hub.py`）：GatewayHub 维护池会话镜像（`sys/session/list` 每 2 s 对账、1 Hz 摘要与池事件即时对账），每个 READY 会话一个 SessionContext（自己的总线会话 + 按绑定实例化的 D1 Gateway + per-run `K_entry`）；60 Hz 驱动只对有连接的上下文做全量 tick，无连接的 10 Hz 轻量 tick（不读环、不编码）；沙盒 token 鉴权、sid 作用域、席位固定给会话 principal、沙盒内禁用服务、`sim/speed` 经池授予、按 sid 的沙盒限流类别；1 Hz `sandbox/session` 与活动上报；4410、1012 `world_switch`；池不可达时已附着上下文继续服务，重启经 list 重建、token 跨重启有效。
4. **D2 topic 与兴趣**：识别物 roster（`kind = target`，按 kind 编号）、`swarm/target/state`（TargetLite32 行原样）、10 条按实体拆分的数据产品流、全集实体的增删 advertise、兴趣下推 `streams{}`（含尚无 channel 的挂起订阅、激光雷达每会话 1 路切换）、serverInfo 的 D2 能力、`clock.tick_hz`、`clock.rate_cap` 与 `sandbox` 块。
5. **配置**：`configs/runtime.yaml` 新增 `sandbox:` 段、`sandbox-pool` 与 `sandbox-api` 进程条目（`AWR_CGROUP=sandbox/ctl`）、public profile v2（七个世界、S7、show-api WS 24、sandbox-api 18641、`quota_profile: public`）与本机 `sandbox` profile。
6. **前端 net**：`net/endpoint.ts`（按会话角色的 `apiBase()`、`rtUrl()`、可配置 API 基址）；`net/api.ts` 沙盒会话路径带沙盒 token、401 经端点换发；RtClient 的 `updateToken`、`onWorldSwitch`、`onSandboxGone`、默认 token 刷新器随端点；RtHost 处理 4410（终止）与 1012 `world_switch`（立即重连）；roster 把识别物与无人机分开。

## 2. 设计要点

1. **一份 Gateway 代码，两种驱动**。沙盒上下文复用 D1 Gateway 全部逻辑（BATCH、credit、EventIngest、DetailDemux、席位、RPC），只增加：绑定、`drive = hub`、`seat_pinned`、`policy`。D1 show-api 的行为差异只有两处可观察的只增字段：serverInfo `clock.tick_hz` 与（数据出现后的）D2 能力。
2. **池契约的最小面**。sandbox-api 只依赖 `list`、`get`、`rate`、`activity` 四个 op、1 Hz 摘要与池事件；会话记录与绑定的形状、签名口径、活动上报的形状在 `d2-WP-03-to-M17.md` 写明，并由 `tests/rt/fakepool.py` 固化。沙盒 token 由池签发（M17-FR-050），sandbox-api 只验签。
3. **鉴权顺序按 17**（先 token 后会话），不向无 token 的请求泄露会话是否存在；SB-11 快照导出在路由器依赖内放宽（过期 ≤ 600 s、会话已结束）。
4. **无连接的上下文**仍以 10 Hz 推进收件箱与 GCS 心跳：REST-only 的 SDK 客户端的命令结果、超时与 sim-core 的链路判据不受影响，同时满足"不读环、不编码"。固定席位在 sim-core 报告的持有者不符时重登记，至多每 2 s 一次，不会与拒绝回复形成循环。
5. **按需流的鸡生蛋问题**：精确订阅在 channel 出现之前就进入兴趣下推（订阅表记录订阅时刻），首帧到达后 channel 增量 advertise、挂起订阅加入。
