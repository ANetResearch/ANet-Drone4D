# 验收概要

V0.2-demo（D2 与 D2.1）按 55 项验收：设计文档 docs/04 §13 与 §15.14 中的 D2-AC-01 至 D2-AC-55，其中 P0（阻塞发布）50 项、P1 5 项。
本页概括第 2 轮验收的结果；逐项结果、证据与诊断见 GitHub 上的完整报告。

## 结果

第 1 轮（2026-10-11 至 10-12）测量全部 55 项。修复工作包 D2-FX-R2 完成后，第 2 轮（2026-10-12 11:59 至 10-13 13:45 UTC，
西雅图时间 10-12 04:59 至 10-13 06:45，构建 0.2.0）复测第 1 轮未通过与未测的 18 项，其余项以全量功能回归覆盖：

| 项目 | 通过 | 不通过 | 未测 |
|---|---|---|---|
| P0（50 项） | **41** | 9 | 0 |
| P1（5 项） | **3** | 0 | 2 |
| **合计（55 项）** | **44** | **9** | **2** |

D2 的退出标准（P0 全部通过，P1 通过率不低于 80%）尚未满足，0.2.0 以已知问题的形式发布。

## 修复得到确认的项目

- **24 h 浸泡（D2-AC-39）**：S7 接力与 24 个观看端连续运行 24.5 h，无非预期重启、无内存溢出，sim-core 内存增长 0.48 MB/h，日切按时触发。
- **首帧时间**：较 D1 缩短 64%（第 1 轮为增长 34%）。
- **会话成本**：单个沙盒会话的仿真成本由 0.46 核降至 0.22 核；容量变体中不再出现"回收、恢复、再饥饿"的循环，创建不再排队。
- **任务**：风下固定翼、区域巡查与巡边并行的缺陷消除，三个种子下撞机 0 次、进入配置体 0 次；全机返航的最大单步由 13.85 ms 降至 7.99 ms。
- **T5 首次捕获**：46.5 至 56.5 s。
- **驻留恢复**：暂停时钟后，恢复前后的任务与接力状态逐字段一致。
- **容量接口微缓存**：每秒到达后端不超过 1 次。

## 未通过项与根因

| 根因 | 涉及项目 | 现象 |
|---|---|---|
| 公开站沙盒容量 | D2-AC-02 沙盒创建、04 并发容量、07 倍速治理、08 sandbox100、55 资源 | 4 个满载会话时沙盒 CPU 组持续用满 1.36 核上限，单会话实时因子最低约 0.58，满载下新建会话就绪约 8.8 s（阈值 6 s）。公开站因此把并发沙盒上限设为 2，其余访客排队 |
| 白天接力间隙 | D2-AC-19 接力 24 h、20 接力 7×24 h、35 应用场景一端到端 | 随机游走的识别物短暂脱离在岗机视线，24 h 批处理出现若干短时监视间隙；T5 在合成演示城市上的换电节律造成 `battery` 间隙 |
| 软件渲染帧节奏 | D2-AC-30 可视化性能 | 无硬件 GPU 时，合成演示城市默认视角的帧时间中位数为 50 ms（阈值为 Tier S 的 33.4 ms） |

未测的两项为 D2-AC-27（公开站 72 h 与 7 天观测）与 D2-AC-46（节能节省的公开站实测），都只差公开站部分，在部署后测量；后者的本机子项全部通过。

## 测试口径

与 D1 相同的一台 8 核虚拟机（Xeon E5-2603 v4，1.7 GHz，62 GiB 内存，无 GPU），浏览器为 Chrome for Testing 151 加 SwiftShader 软件渲染。
性能、容量与带时延阈值的项目在排他锁下运行，开跑前 1 分钟负载不超过 4，取 3 次中位数。公开站的资源以 cgroup 模拟：`CPUQuota=250%`、
`MemoryHigh=1.8G`、`MemoryMax=2G`、4 个核。

收尾的全量 `pytest -m "not perf"` 为 4,331 项通过、97 项跳过、2 项失败；两项失败均与测试隔离或钉核环境有关，单独运行时通过或与第 1 轮相同。
